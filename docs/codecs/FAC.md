# FAC — Flora Audio Codec (битстрим FAC1)

**Status:** Draft  
**Version:** 0.1 (bitstream v0, не заморожен)  
**Date:** 2026-07-13  
**Depends on:** [`CODECS.md`](./CODECS.md), [`CODECS-AUDIO.md`](./CODECS-AUDIO.md)  
**Reference implementation:** `Codecs/audio/` (Rust, crates `fac-core`, `fac-cli`)

---

## Overview

FAC — собственный аудио-кодек экосистемы Flora. Цель программы — кодек, превосходящий по эффективности используемые сегодня AAC/Opus в целевых сценариях Flora: голосовые сообщения (E2E, клиентское кодирование) и музыка (серверный транскод).

Документ нормативен для битстрима v0: независимая реализация, следуя этому тексту, обязана декодировать поток эталонной реализации. До заморозки (v1) битстрим может меняться без обратной совместимости.

FAC **не изменяет** действующую политику `CODECS-AUDIO` v1 (AAC-контуры остаются в проде). Ввод FAC в контуры — отдельное решение после бенчмарков (см. Roadmap).

## Strategy (честная оценка)

| Этап | Что | Против кого | Ожидание |
| --- | --- | --- | --- |
| v0 (этот документ) | Классическое MDCT-ядро, рабочий сквозной кодек | — | Фундамент: формат, метрики, инфраструктура. Хуже Opus |
| v0.x | PVQ, психоакустика, транзиенты, range coder | AAC-LC | Сопоставимо на музыке средних/высоких битрейтов |
| v1 | Заморозка битстрима классического профиля | Opus/CELT | Паритет в узких сценариях |
| FAC-NC | Нейропрофиль: RVQ-кодовые книги + генеративный декодер | Opus, xHE-AAC, EVS | Превосходство на 3–24 kbps (голос, затем музыка) — именно здесь классика проигрывает нейрокодекам в разы |

Классическое ядро не выбрасывается после появления FAC-NC: оно остаётся (a) fallback-профилем для слабых устройств, (b) транспортом высоких битрейтов, (c) детерминированной базой для PLC.

## Architecture Position

```
Codecs/audio  (отдельный cargo-workspace, чистый Rust, no unsafe, no C deps)
  ├─ fac-core   — кодек: DSP + битстрим (готов к wasm32 / FFI / серверу)
  └─ fac-cli    — encode/decode/roundtrip/gen поверх WAV (инструмент разработки)

Потребители (будущая интеграция, направление зависимостей →):
  Apps/Web (wasm)        → fac-core   # голосовые E2E: сжатие ДО шифрования, как требует CODECS.md
  Apps/Mobile (FFI)      → fac-core
  Backend/flora-music    → fac-core   # серверный транскод музыки
```

Границы: `fac-core` не знает о модулях Flora, БД и HTTP; модули знают о нём только как о библиотеке. Для E2E-контура сервер продолжает видеть только шифроблоб — меняется лишь кодек внутри `voiceBlock` (будущий `contentType: audio/fac`).

## Codec overview (v0)

- Вход: PCM f32, 1–2 канала, 44.1/48 кГц (внутренняя сетка полос рассчитана на 48 кГц; на 44.1 края полос смещаются ~8% — допустимо для v0).
- Трансформа: MDCT, hop `N = 960` сэмплов (20 мс @ 48 кГц), окно `2N = 1920`, 50% overlap-add, задержка кодек-цепочки `N`.
- Спектр делится на 21 полосу (шкала Барка), кодируются полосы до бина 800 (20 кГц @ 48 кГц); бины 800–959 не кодируются (нули).
- Каждая полоса — **gain-shape**: лог-энергия (gain) + нормированная форма (shape).
- Аллокация битов по полосам **не передаётся**: декодер выводит её из уже декодированных энергий тем же целочисленным алгоритмом, что и энкодер.
- Rate-контроль: глобальный индекс шага квантования `λ` (1 байт), подбирается энкодером под бюджет кадра.
- Стерео: фиксированное M/S.
- Полностью нулевая форма полосы → детерминированный noise-fill на декодере.
- PLC: повтор последнего спектра с затуханием.

### Нормативные формулы

Окно (Vorbis power-complementary), `n ∈ [0, 2N)`:

```
w[n] = sin( (π/2) · sin²( π·(n + 0.5) / (2N) ) )
```

MDCT (вход `x[0..2N)` — windowed, выход `X[0..N)`) и iMDCT:

```
X[k] = Σ_{n=0}^{2N-1} w[n]·x[n]·cos( (π/N)·(n + 0.5 + N/2)·(k + 0.5) )
y[n] = (2/N)·w[n]·Σ_{k=0}^{N-1} X[k]·cos( (π/N)·(n + 0.5 + N/2)·(k + 0.5) )
```

Реконструкция — overlap-add соседних кадров с шагом `N` (свойство Принсена–Брэдли выполняется окном выше).

M/S (обратимо, энергосохраняюще): `M = (L+R)/√2`, `S = (L−R)/√2`; обратно `L = (M+S)/√2`, `R = (M−S)/√2`. Плоскости кодирования: моно → `[X]`, стерео → `[M, S]`.

### Полосы (нормативная таблица, бины MDCT при N=960)

```
edges[22] = 0, 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128,
            160, 192, 224, 272, 320, 384, 480, 624, 800
```

Полоса `b` покрывает бины `[edges[b], edges[b+1])`, `b ∈ [0, 21)`.

### Энергии (gain)

Для плоскости `p`, полосы `b`: `E = Σ X[i]² + 1e-10`, `q[p][b] = round(4·log2(E))` (шаг 0.25 log2 ≈ 0.75 дБ, i32). Кодирование: дельта к предыдущей полосе той же плоскости (первая полоса — дельта к 0), zigzag + Rice(k=4). Декодированный gain: `ĝ = 2^(q/8)` (корень из энергии).

### Аллокация (общая целочисленная функция энкодера и декодера)

```
qmax   = max по всем плоскостям/полосам q[p][b]
w[p][b] = clamp(q[p][b] − qmax + 128, 0, 128) + 8        # i32
β_e8[p][b] = clamp( S_e8 · w[p][b] / Σ_{p',b'} (w·width), 0, 64 )   # i64-арифметика, деление целочисленное
```

где `width[b] = edges[b+1] − edges[b]`, `S_e8 = 8 · shape_budget_bits` (бюджет формы кадра в 1/8 бита), `β_e8` — целевые биты на коэффициент в 1/8 бита (кап 8 бит/коэфф).

Бюджет кадра `budget = round(bitrate · N / sample_rate)` передаётся в заголовке кадра (u16le) — аллокация декодера обязана совпасть с энкодером бит-в-бит независимо от фактической длины пакета и транспорта. Бюджет формы = `budget − 32 (заголовок) − фактические биты энергий` (насыщение в 0).

**Правило пропуска:** полоса с `β_e8 == 0` не кодируется вовсе (0 бит) — декодер применяет к ней noise-fill. Это удерживает низкие битрейты: кадр не тратит ни бита на полосы вне бюджета.

### Форма (shape)

Нормировка: `s[i] = X[i]/g`, где `g = sqrt(E)` — истинный gain. Квантование равномерное: `y[i] = round(s[i]/step[b])`, кодирование zigzag + Rice с `k[b] = max(0, β_e8[p][b]/16 − 1)` *(целочисленно: `if β_e8 ≥ 16 { β_e8/8 − 1 } else { 0 }`)*.

Шаг — **точная** степень двойки с табличной мантиссой (без libm, бит-в-бит на всех платформах):

```
m = λ_idx − 32 − β_e8[p][b]                # i32
step = MANT[m mod 8] · 2^(m div 8)          # div/mod — с округлением к −∞
MANT[j] = 2^(j/8), j ∈ [0,8):  1.0, 1.0905077, 1.1892071, 1.2968396,
                               1.4142135, 1.5422108, 1.6817929, 1.8340080   # f32
```

`λ_idx ∈ [0, 63]` (1 байт в кадре): энкодер выбирает минимальный `λ_idx` (самый тонкий шаг), при котором фактические биты формы ≤ бюджета; если даже 63 не помещается — 63.

Декодер: `ŝ[i] = y[i]·step[b]`, `norm = sqrt(Σ ŝ²)`. Если `norm > 0`: `X̂[i] = ŝ[i]·(ĝ/norm)` (энергия полосы восстанавливается точно в пределах шага квантования энергии). Если вся полоса нулевая — noise-fill:

```
seed = (frame_index·2654435761 ⊕ p·40503 ⊕ b·9973) | 1   # u32, wrapping
далее xorshift32 (x ^= x<<13; x ^= x>>17; x ^= x<<5) на каждый бин:
n[i] = (x / 2³¹) − 1.0  ∈ [−1, 1),  затем нормировка n к единичной норме и X̂ = n·ĝ
```

`frame_index` — порядковый номер кадра с начала потока (включая PLC-кадры), с нуля, u32 wrapping.

### Коды Райса и битовый порядок

MSB-first. `zigzag(v) = (v << 1) ^ (v >> 31)` (i32 → u32). Rice(k): `q = val >> k` единичных битов, затем `0`, затем `k` младших битов `val`. Эскейп: если `q ≥ 24` — пишутся ровно 24 единичных бита (без нуля), затем `val` как 32 бита raw.

### Кадр (packet)

```
byte 0:   flags — bit0..2 = 0 (резерв v0), bit3 = ms_stereo (1 для 2 каналов), bit4..7 = 0
byte 1:   λ_idx (0..63)
byte 2-3: budget u16le — бюджет кадра в битах (см. Аллокация)
далее: энергии всех плоскостей (плоскость за плоскостью, полосы по порядку),
затем формы всех плоскостей (тот же порядок, полосы с β_e8 = 0 пропускаются),
затем выравнивание нулями до байта
```

Декодер обязан возвращать ошибку (не панику) на любой некорректный вход.

### PLC (потеря пакета)

`decode_lost()`: последний декодированный спектр каждой плоскости умножается на 0.7 и синтезируется как обычный кадр. Состояние overlap-add продолжает жить — щелчков на границе нет.

## Контейнер FACS (файловый, для инструментов; транспорт Flora — свой)

```
магия "FACS" (4B) | version u8 = 1 | channels u8 | sample_rate u32le |
frame_n u16le = 960 | num_samples u64le (на канал, без задержки)
затем пакеты: len u16le | payload[len] ... до EOF
```

Декодер файла отбрасывает первые `N` сэмплов (задержка) и обрезает хвост до `num_samples`. В FSCP/HTTP пакеты передаются собственным транспортом — контейнер не обязателен.

## Метрики и бенчмарки

- v0: SNR (время), лог-спектральная дистанция по полосам, фактический kbps — считает `fac-cli roundtrip`.
- v0.x: ViSQOL (объективное перцептивное качество) + слепые ABX; сравнение с Opus/AAC на корпусе (речь: чистая/шумная; музыка: разные жанры; edge: аплодисменты, клавесин, кастаньеты).
- Тест-векторы FAC добавляются в `docs/test-vectors/` **только генерацией** из эталонной реализации (правило репозитория).

## Module boundaries

- Кодек — только `Codecs/audio` (`fac-core`). Модули/приложения используют его как библиотеку; обратных зависимостей нет.
- Транскод-пайплайны остаются в своих владельцах (`Flora.Music`, `Apps/Web`) — FAC не двигает границы `CODECS.md`.
- E2E-инвариант сохраняется: голосовые кодируются на клиенте до шифрования.

## Roadmap

1. **v0.1** — быстрая MDCT (FFT-путь), транзиент-детектор + короткие окна (8×120), ресемплер.
2. **v0.2** — PVQ вместо скалярного квантования, range coder вместо Rice, психоакустическая модель маскирования, per-band M/S, VBR.
3. **v1** — заморозка битстрима, фиксированная точность декодера (бит-в-бит кросс-платформенно), fuzzing-кампания, тест-векторы, WASM/FFI-обвязка.
4. **FAC-NC** — нейропрофиль: RVQ-энкодер/декодер (обучение — PyTorch, вне этого workspace; инференс — Rust `candle`/`tract`, int8), голос 3–8 kbps, музыка 12–24 kbps. Гейт на ввод в прод: слепые тесты против Opus на целевых битрейтах.
5. **Интеграция** — `voiceBlock.contentType = audio/fac` (FSCP, клиентское кодирование), ladder Flora.Music; обновление `CODECS-AUDIO.md` отдельным PR.
