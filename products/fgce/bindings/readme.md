# Клиенты FGCE для разных языков

Клиент (binding) — тонкий слой над C ABI `crates/fgce-wasm`. Он загружает модуль,
кодирует запросы и декодирует ответы. В клиентах **нет политики рендеринга**:
никакой геометрии страниц, шейпинга текста, обработки ввода или презентации.

Языконезависимый контракт:

- [`../docs/wasm-abi.md`](../docs/wasm-abi.md) — C ABI v2 и бинарный wire-формат;
- `ABI_VERSION` в [`../crates/fgce-wasm/src/lib.rs`](../crates/fgce-wasm/src/lib.rs);
- [`../tests/abi-vectors`](../tests/abi-vectors) — байты запросов и ответов, которые
  обязан воспроизводить каждый клиент.

## Правила

1. Один каталог на среду выполнения: `bindings/<lang>/`. Новый клиент добавляется
   только тогда, когда он реально нужен хосту.
2. Клиент проверяет `fgce_abi_version()` до первого запроса и соблюдает правила
   памяти: буферы запросов берутся из `fgce_alloc`/`fgce_free`, а представление
   (view) ответа действительно только до следующего `fgce_submit`.
3. Клиент обязан проходить `tests/abi-vectors`: те же байты запросов и те же
   декодированные ответы, что и у любого другого клиента.
4. Версионирование клиента идёт по ABI, а не по ядру. Версию ядра сообщает `Info`.
5. Хост-адаптеры (сцены, растеризация текста, layout, таймеры) живут в
   репозитории хоста. Для Web это `apps/Web/lib/fgce` в репозитории Flora, а не
   здесь.

## Когда клиент не нужен

- **Rust-хосты** зависят от `crates/fgce` напрямую; `Engine::submit` — тот же
  контракт без wasm. Пример — `tests/conformance`.
- **Хосты на C/C++/C#/Go** могут собрать `crates/fgce-wasm` как нативный `cdylib`
  (`crate-type = ["cdylib", "rlib"]`) и вызывать те же C-экспорты; им всё равно
  нужен небольшой кодек — это и есть клиент.
