## Overview

FRC-A — собственный аудио-кодек экосистемы Flora. Цель программы — кодек, превосходящий по эффективности используемые сегодня AAC/Opus в целевых сценариях Flora: голосовые сообщения (E2E, клиентское кодирование) и музыка (серверный транскод).

Документ нормативен для битстрима v0: независимая реализация, следуя этому тексту, обязана декодировать поток эталонной реализации. До заморозки (v1) битстрим может меняться без обратной совместимости.

FRC-A **не изменяет** действующую политику `CODECS-AUDIO` v1 (AAC-контуры остаются в проде). Ввод FRC-A в контуры — отдельное решение после бенчмарков (см. Roadmap).

## Codec overview (v0)

- Вход: PCM f32, 1–2 канала, 44.1/48 кГц (внутренняя сетка полос рассчитана на 48 кГц; на 44.1 края полос смещаются ~8% — допустимо для v0).
- Трансформа: MDCT, hop `N = 960` сэмплов (20 мс @ 48 кГц), низкоперекрывающееся окно (склейка `L = 120`, CELT-подход), overlap-add с шагом `N`, задержка кодек-цепочки `N`.
- **Транзиентный режим** (флаг в кадре): вместо одной длинной MDCT — 8 коротких MDCT `N/8 = 120` с интерливингом коэффициентов; устраняет pre-echo на атаках. Благодаря общей длине склейки `L` длинные и короткие кадры стыкуются без переходных окон и без лукахеда.
- Спектр делится на 21 полосу (шкала Барка), кодируются полосы до бина 800 (20 кГц @ 48 кГц); бины 800–959 не кодируются (нули).
- Каждая полоса — **gain-shape**: лог-энергия (gain) + нормированная форма (shape).
- Форма — **PVQ** (пирамидное векторное квантование): K импульсов со знаками, кодовое слово — равномерный символ range coder'а; широкие полосы делятся рекурсивно с передачей угла θ.
- Аллокация битов по полосам **не передаётся**: декодер выводит её из уже декодированных энергий (и сигналируемого трима) тем же целочисленным алгоритмом, что и энкодер. Аллокация перцептивная: плотность энергии взвешивается экспонентой α = 3/4 (маскирование внутри полосы растёт медленнее её энергии), сигналируемый трим наклоняет распределение НЧ↔ВЧ.
- Rate-контроль формы **точный и открытый**: стоимость кодовой книги PVQ известна до записи, неизрасходованный остаток полосы переносится в следующую (carry); итеративный подбор шага квантования не нужен.
- Стерео: фиксированное M/S.
- Полностью нулевая форма полосы → детерминированный noise-fill на декодере (кроме транзиентных кадров).
- PLC: повтор последнего спектра с затуханием в режиме последнего кадра.

### Нормативные формулы

Окно с носителем `n + l` по центру формальной длины `2n` (`l` — длина склейки, `s = (n − l)/2`, `rise(i) = sin((π/2)·sin²(π·(i+0.5)/(2l)))`):

```
w[m] = 0        для m ∈ [0, s) ∪ [2n−s, 2n)
w[s+i]      = rise(i),      i ∈ [0, l)
w[m] = 1        для m ∈ [s+l, 2n−s−l)
w[2n−s−l+i] = rise(l−1−i),  i ∈ [0, l)
```

Оно power-complementary (`w[m]² + w[m+n]² = 1`) и симметрично — условия Принсена–Брэдли выполняются. При `l = n` вырождается в классическое окно Vorbis.

- **Длинный кадр:** одна MDCT `n = N = 960`, `l = L = 120` над `[prev | cur]` (2N сэмплов).
- **Транзиентный кадр:** 8 коротких MDCT `n = N/8 = 120`, `l = 120` (полное перекрытие). Короткий блок `j ∈ [0, 8)` берёт сэмплы `[S₀ + 120·j, S₀ + 120·j + 240)` того же буфера `[prev | cur]`, где `S₀ = (N − L)/2 = 420`. Блоки точно тайлят носитель длинного окна; спад любого кадра встречает подъём той же формы `rise`, поэтому режимы свободно чередуются.

MDCT (вход `x[0..2n)` — windowed, выход `X[0..n)`) и iMDCT:

```
X[k] = Σ_{m=0}^{2n-1} w[m]·x[m]·cos( (π/n)·(m + 0.5 + n/2)·(k + 0.5) )
y[m] = (2/n)·w[m]·Σ_{k=0}^{n-1} X[k]·cos( (π/n)·(m + 0.5 + n/2)·(k + 0.5) )
```

Реконструкция — overlap-add кадров с шагом `N`; в транзиентном кадре 8 коротких синтезов суммируются в свои позиции формального 2N-окна, дальше тот же overlap-add.

**Интерливинг** (транзиентный кадр): коэффициент `f` короткого блока `j` хранится в спектре кадра по индексу `X[f·8 + j]`. Все края полос кратны 8, поэтому полоса `b` в интерливинг-домене покрывает те же индексы `[edges[b], edges[b+1])` — энергии, аллокация и форма не зависят от режима кадра.

Решение о транзиенте принимает энкодер; нормативен только флаг в битстриме. Эталонный детектор (не нормативен): скачок энергии первой разности сигнала в суб-блоке `N/8` более чем в 8 раз относительно максимума двух предыдущих суб-блоков (анализ текущего hop'а + хвоста предыдущего, все каналы). Эталонный энкодер не включает транзиентный режим при бюджете кадра < 512 бит: без noise-fill почти нулевая аллокация дала бы провалы звука.

M/S (обратимо, энергосохраняюще): `M = (L+R)/√2`, `S = (L−R)/√2`; обратно `L = (M+S)/√2`, `R = (M−S)/√2`. Плоскости кодирования: моно → `[X]`, стерео → `[M, S]`.

### Полосы (нормативная таблица, бины MDCT при N=960)

```
edges[22] = 0, 8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128,
            160, 192, 224, 272, 320, 384, 480, 624, 800
```

Полоса `b` покрывает бины `[edges[b], edges[b+1])`, `b ∈ [0, 21)`.

### Энергии (gain)

Для плоскости `p`, полосы `b`: `E = Σ X[i]² + 1e-10`.

**Coarse** (управляет аллокацией): `q[p][b] = round(4·log2(E))` (шаг 0.25 log2 ≈ 0.75 дБ, i32). Кодирование: дельта к предыдущей полосе той же плоскости (первая полоса — дельта к 0), zigzag, бинаризация `k = 4` в контексте энергий (см. Энтропийное кодирование). Декодер ограничивает восстановленный `q` диапазоном `[−1024, 1024]` (защита от враждебного битстрима; честный энкодер этих значений не достигает). Coarse-gain: `ĝ = 2^(q/8)` (корень из энергии; используется для noise-fill полос).

**Fine** (только для кодируемых полос, β > 0): `u = clamp(⌊16·log2(E) − 4·q⌋ + 2, 0, 3)` — 2 бита, позиция внутри coarse-ячейки с точностью 1/16 log2 энергии. Fine-gain для масштабирования формы:

```
ĝ_fine = 2^( (8·q + 2·u − 3) / 64 )
```

Fine-биты пишутся в начале данных формы своей полосы (см. Кадр). Ошибка gain ≤ 1/64 log2 (≈ 0.05 дБ).

### Аллокация (общая целочисленная функция энкодера и декодера)

Перцептивный water-filling: плотность энергии взвешивается экспонентой **α = 3/4** (чистый MMSE — α = 1 — перекармливает громкие полосы: маскирование внутри полосы растёт медленнее её энергии), плюс сигналируемый в кадре наклон НЧ↔ВЧ (**trim**, 3 сырых бита в начале RC-потока, нейтраль 4). Целочисленно:

```
density_e8(q, b) = (3·(q − LOG2W_X4[b])) >> 2                 # α = 3/4, floor-сдвиг
tilt_e8(trim, b) = ((trim − 4)·(2·b + 1 − 21)) >> 2           # ±5 e8 на краях спектра

β_e8[p][b] = 0, если q[p][b] ≤ −132 (полоса на epsilon-полу — цифровая тишина)
иначе:
β_e8[p][b] = clamp( C + density_e8(q[p][b], b) + tilt_e8(trim, b), 0, 64 )
             если β_e8 < 8 → β_e8 = 0

LOG2W_X4[b] = round(4·log2(width[b])) — нормативная таблица:
              12,12,12,12,12,12,12,12,16,16,16,16,20,20,20,22,22,24,26,29,30

C — наибольшее целое из [−3000, 3000], при котором
    Σ_{p,b} β_e8[p][b] · width[b]  ≤  S_e8       (бинарный поиск, монотонно)
```

Floor-сдвиги (`>>`)  нормативны и детерминированы для отрицательных значений. `trim > 4` сдвигает биты к ВЧ, `trim < 4` — к НЧ (≈ 0.6 бит/коэфф дифференциала НЧ↔ВЧ на единицу трима). Выбор трима — решение энкодера (нормативен только символ); эталонный энкодер v0.7 всегда сигналит нейтраль 4 — замеры полигона показали, что эвристика по спектральному балансу без оценки тональности вредит многотоновому контенту (редкий ВЧ-тон уходит в noise-fill). Адаптация трима — v0.8.

Правило `β_e8 < 8 → 0` (не кодировать полосы дешевле 1 бит/коэфф) обязательно: PVQ выбирает книгу максимальной мощности, укладывающуюся в аллокацию полосы, поэтому фактическая стоимость формы никогда не превышает Σ β·width/8; правило дополнительно гарантирует K ≥ 1 — кодируемая полоса не бывает пустой (`8·W ≥ ⌈8·log2(2W)⌉` для всех W ≥ 2). Превышение бюджета кадром возможно только когда `24 + 40 + биты энергий > budget` (ультранизкие битрейты — параметрический режим).

где `width[b] = edges[b+1] − edges[b]`, `S_e8 = 8 · shape_budget_bits` (бюджет формы кадра в 1/8 бита), `β_e8` — целевые биты на коэффициент в 1/8 бита (кап 8 бит/коэфф).

Бюджет кадра передаётся в заголовке кадра (u16le) — аллокация декодера обязана совпасть с энкодером бит-в-бит независимо от фактической длины пакета и транспорта. Декодер не делает предположений о величине бюджета: энкодер вправе варьировать его по кадрам (VBR). Учёт ведётся в 1/64 бита: бюджет формы (x64) = `64·budget − 64·(24 + 40 + 3) − стоимость coarse-энергий` (24 — заголовок, 40 — финализация range coder'а, 3 — трим; стоимость энергий — по нормативной функции стоимости битов, декодер накапливает её по фактически прочитанным символам). Бюджет аллокации `S = ⌊бюджет формы / 64⌋ − 2·planes·21` бит (резерв fine-битов). Всё с насыщением в 0.

**Carry.** Кодируемая полоса получает `avail = β_e8·width + carry` восьмых бита, где `carry` — неизрасходованный остаток предыдущей кодируемой полосы (ступенчатость мощностей книг PVQ); в начале кадра `carry = 0`, после полосы `carry = avail − spent`. Обе стороны вычисляют остаток одинаково — состояние выводится только из уже декодированных данных.

**VBR референсного энкодера** (ненормативно — поведение энкодера; декодер всегда читает фактический бюджет из заголовка). Базовый бюджет `base = round(bitrate · N / sample_rate)`; три механизма поверх него:

1. *Транзиентный заём:* транзиентный кадр получает `base + base/4` (долг растёт на `base/4`), нетранзиентный гасит долг по `min(долг, base/8)`; при долге выше `2·base` заём не выдаётся.
2. *Ужатие лёгких кадров:* потребность кадра `demand` — water-filling до окна 66 дБ (88 единиц q) от пиковой плотности энергии кадра (`q − LOG2W_X4`, **не** взвешенной α — MMSE-водопад как верхняя оценка расхода; только полосы громче epsilon-пола; β-кап и правило `β ≥ 8` как в аллокации) плюс фактическая стоимость энергий и накладные (заголовок, RC, трим, резерв fine). Если `demand < budget`, нетранзиентный кадр ужимается до `max(demand, base/2)` — сэкономленные биты копятся в пуле сбережений. Окно расширено с 60 дБ при переходе на α-аллокацию: α кормит тихие полосы щедрее MMSE, и прежнее окно недооценивало транзиентно-плотный контент.
3. *Буст тяжёлых кадров:* если `demand > budget`, кадр докупает `min(demand − budget, base/2)` бит из пула (не больше накопленного).

Пул — точный баланс «цель − факт» по фактическим размерам пакетов, с капом `4·base` (ограничивает всплеск после тишины). Средний битрейт не превышает целевой; перерасход возможен только на величину ограниченного транзиентного овердрафта (≤ `2.25·base` на поток, как в 0.4).

**Правило пропуска:** полоса с `β_e8 == 0` не кодируется вовсе (0 бит) — декодер применяет к ней noise-fill. Это удерживает низкие битрейты: кадр не тратит ни бита на полосы вне бюджета.

### Форма (shape): PVQ

Форма подвектора — целочисленный вектор `y` с `Σ|y[i]| = K` (K импульсов со знаками). Мощность кодовой книги `V(N, K)` — число таких векторов размерности N:

```
V(N,0) = 1;  V(0,K>0) = 0;
V(N,K) = V(N−1,K) + V(N,K−1) + V(N−1,K−1)      # u64 с насыщением; насыщение ⇒ книга отвергается
```

**Стоимость книги** из `M` слов — `cost_e8(M)`: наименьшее `c` (1/8 бита), при котором `M ≤ pow2_floor_e8(c)`, где

```
pow2_floor_e8(c) = (MANT_Q60[c mod 8] << (c div 8)) >> 60     # насыщение в u64::MAX при c div 8 ≥ 64
MANT_Q60[8] = 1152921504606846976, 1257269815929830108, 1371062456318104877,
              1495154210581915421, 1630477228166597776, 1778048025250290523,
              1938975120585633118, 2114467362444183333        # floor(2^(j/8)·2^60), нормативные целые
```

**Кодирование подвектора** размерности `N` с бюджетом `b` (1/8 бита), рекурсивно:

- **Деление** (`N ≥ 8` и `b > 512`): передаётся угол `θ` — равномерный символ `itheta ∈ [0, qn]`, `qn = 2^min(2 + b/(8·N), 7)`; списывается `cost_e8(qn+1)`, остаток `b_rem`. Гейны половин (Q15) и смещение дележа бит:

```
is = itheta·(16384/qn)
is = 0     → imid = 32767, iside = 0,     delta = −16384
is = 16384 → imid = 0,     iside = 32767, delta = +16384
иначе:       imid = bitexact_cos(is), iside = bitexact_cos(16384 − is),
             delta = ((N−1)·2⁷ · bitexact_log2tan(iside, imid)) >> 15
```

  `bitexact_cos` (Q14 → Q15) и `bitexact_log2tan` (`≈ 2¹¹·log2(isin/icos)`) — нормативные целочисленные полиномы (классические из CELT):

```
bitexact_cos(x):  x2 = (4096 + x·x) >> 13
                  1 + (32767 − x2) + FRAC(x2, −7651 + FRAC(x2, 8277 + FRAC(−626, x2)))
bitexact_log2tan(isin, icos):  нормализовать оба до 15 бит (сдвиг на 15 − bitlen),
                  (bitlen(isin) − bitlen(icos))·2¹¹
                  + FRAC(isin, FRAC(isin, −2597) + 7932) − FRAC(icos, FRAC(icos, −2597) + 7932)
где FRAC(a,b) = (a·b) >> 15  (целочисленно, i32)
```

  Дележ: `b_rem = b − cost_e8(qn+1)`, `b_left = clamp((b_rem − delta)/2, 0, b_rem)`, правая половина дополнительно получает остаток левой: `b_right = b_rem − b_left + (b_left − spent_left)`. Левая половина кодируется первой; после декодирования обеих половины умножаются на `imid/32768` и `iside/32768`. Выбор `itheta` — решение энкодера (нормативен только символ); эталонный энкодер берёт `round(qn·atan2(‖right‖, ‖left‖)/(π/2))` — угол фактического распределения энергии.

- **Лист** (иначе): `K` — наибольшее `≤ 4096`, при котором `V(N,K) ≤ pow2_floor_e8(b)` (несатурированное). `K = 0` → подвектор нулевой, 0 бит. Иначе кодовое слово — равномерный символ `∈ [0, V(N,K))`; списывается `cost_e8(V(N,K))`. Порядковый номер (CWRS): позиции слева направо, значения каждой позиции в порядке `0, +1, −1, +2, −2, …`; вклад позиции со значением `v` при `k` оставшихся импульсах и `r` оставшихся позициях — суммарная мощность книг всех значений раньше `v`:

```
offset(0) = 0
offset(±j) = V(r, k) + Σ_{i=1..j−1} 2·V(r, k−i)  (+ V(r, k−j) для знака −)
```

  где `r` — число позиций правее текущей, `k` — импульсы, не израсходованные до текущей позиции включительно. Декодер нормирует `y` к единичной L2-норме (`f64`-суммы точны: |y| ≤ 4096, N ≤ 176 — бит-в-бит на всех платформах).

Спад мощности книг ступенчатый, поэтому неизрасходованный остаток каждого уровня переносится дальше (внутри деления — правой половине; после полосы — следующей кодируемой полосе, см. Аллокация/Carry).

**Гейны.** Степени двойки вида `2^(m/64)` (целое `m`) вычисляются единой таблицей — **точно**, без libm, бит-в-бит на всех платформах:

```
R = 2^(1/64) = 1.0108892860517005                        # нормативная f64-константа
MANT64[j] = (R^j как f64, последовательным умножением) → f32,  j ∈ [0, 64)
pow2_e64(m) = MANT64[m mod 64] · 2^(m div 64)            # div/mod — к −∞; порядок клампится в ±126
```

Через `pow2_e64` считаются coarse-gain (`m = 8q`) и fine-gain (`m = 8q + 2u − 3`).

Декодер полосы: `norm = sqrt(Σ ŝ²)` по всей полосе после theta-цепочки. Если `norm > 0`: `X̂[i] = ŝ[i]·(ĝ_fine/norm)` (энергия полосы восстанавливается точно в пределах fine-шага). Если вся полоса нулевая (возможно только при вырожденном битстриме) — как некодируемая: noise-fill по coarse-gain `ĝ` **только в длинных кадрах**; в транзиентных кадрах полоса остаётся нулевой (шум без временнóй огибающей размазался бы на все 8 блоков и вернул pre-echo). Noise-fill:

```
seed = (frame_index·2654435761 ⊕ p·40503 ⊕ b·9973 ⊕ block·131071) | 1   # u32, wrapping;
       # noise-fill полосы: block = 0; anti-collapse: block = номер короткого блока
далее xorshift32 (x ^= x<<13; x ^= x>>17; x ^= x<<5) на каждый бин:
n[i] = (x / 2³¹) − 1.0  ∈ [−1, 1),  затем нормировка n к единичной норме и X̂ = n·ĝ
```

`frame_index` — порядковый номер кадра с начала потока (включая PLC-кадры), с нуля, u32 wrapping.

### Anti-collapse (транзиентные кадры)

Квантование и зануление полос в транзиентном кадре схлопывает тихие короткие блоки в цифровой ноль — на перкуссии поверх фактуры это слышно как «дыры» (выпадение послезвучия/фона вокруг атаки). Лечение по образцу CELT: декодер помнит coarse-энергии **двух предыдущих кадров** и заполняет схлопнувшиеся блоки шумом на уровне *прошлой* энергии. Прошлое не может подсветить атаку назад во времени, поэтому pre-echo не возникает.

**Память энергий.** Декодер хранит `q_hist1` (предыдущий кадр) и `q_hist2` (перед ним) на каждую пару (плоскость, полоса). Инициализация `−1024` («нет истории» — ниже любой честной энергии). После успешного декодирования кадра: `q_hist2 ← q_hist1`, `q_hist1 ← q` текущего кадра. На PLC-кадр обе истории затухают: `q_hist −= 4` (≈ −3 дБ, синхронно амплитудному затуханию PLC 0.7), с полом `−1024`. Усечённый/невалидный пакет память не меняет.

**Алгоритм** (после декодирования всех форм, только если `flags.bit1 = 1`). Для каждой (плоскости, полосы):

```
qmin = min(q, q_hist1, q_hist2);  если qmin ≤ −132 (тишина) — пропустить
короткий блок j ∈ [0, 8) схлопнулся ⇔ все коэффициенты полосы с i mod 8 = j равны 0
гейн блока: r = 2^((8·qmin − 96)/64)            # энергия qmin, делённая на 8 блоков: /√8
для кодируемых полос (β_e8 > 0) r дополнительно ограничен шумовым полом PVQ:
    r = min(r, ĝ_fine · 2^(−(β_e8 + 12)/8))      # β/8 бит/коэфф ≈ 6·β/8 дБ SNR; 12/8 = log2 √8
в каждый схлопнувшийся блок — шум xorshift32 с seed(frame_index, p, b, block = j),
нормированный к норме r по позициям блока
```

Seed обобщает формулу noise-fill термом блока: `seed = (frame_index·2654435761 ⊕ p·40503 ⊕ b·9973 ⊕ j·131071) | 1`; noise-fill длинных кадров использует `j = 0` — контексты не пересекаются, так как в транзиентных кадрах noise-fill полос выключен.

После инъекций **кодируемая** полоса перенормируется целиком к своему `ĝ_fine` (энергия полосы сохраняется); **некодируемая** полоса не перенормируется — блоки остаются на уровне шумового пола истории, и энергия атаки не размазывается на тихие блоки.

**Энкодер** (ненормативно) ставит `bit1`, когда в кадре есть «слышимо схлопнувшийся» блок: кодируемая полоса, где какой-то блок ушёл в ноль при `min(q, hist) > −132`, либо незакодированная полоса с живой энергией сейчас и в истории.

### Энтропийное кодирование: бинарный range coder

Всё после 4-байтового заголовка кадра кодируется бинарным range coder'ом LZMA-типа: 32-битный `range` (старт `2³²−1`), перенос через `low: u64`, байтовая ренормализация при `range < 2²⁴`, вероятности «бит = 0» с точностью 12 бит (масштаб 4096):

```
bound = (range >> 12)·prob0
бит 0: range = bound;    бит 1: low += bound; range −= bound
shift_low (при ренормализации): вытолкнуть старший байт low с распространением
переноса через кэш и цепочку 0xFF (классическая схема LZMA)
```

Поток RC: байты кода **без ведущего байта** — первый байт классической LZMA-схемы всегда 0 (пока не вытолкнут ни один байт, сохраняется инвариант `low + range ≤ 2³²` и перенос в начальный кэш невозможен), поэтому он не передаётся; финализация выталкивает 5 байтов (40 бит накладных). Декодер читает 4 байта инициализации `code` и зеркалит арифметику; чтение за концом буфера — признак усечённого пакета (ошибка), недостающие байты читаются как 0.

**Адаптивные контексты.** Вероятность после каждого бита сдвигается к наблюдённому значению на 1/32 (`p0 += (4096−p0)>>5` при 0, `p0 −= p0>>5` при 1). Контексты живут в пределах кадра и сбрасываются на его границе (потеря пакета не рассинхронизирует стороны). Нормативное стартовое значение `prob0` контекста энергий — 2867. Сырые биты (fine, остатки бинаризации, эскейпы) кодируются с фиксированным `prob0 = 2048` (ровно 1 бит).

**Равномерные символы** (θ и кодовые слова PVQ): значение `x ∈ [0, m)` кодируется цепочкой двоичных делений интервала `[lo, hi)` (старт `[0, m)`) до единичной длины:

```
mid = lo + (hi − lo)/2
p0  = clamp( round(4096·(mid − lo)/(hi − lo)), 1, 4095 )   # вероятность «x < mid»
бит = (x ≥ mid);  интервал сужается к выбранной половине
```

Стоимость телескопируется к `log2 m` бит для любого `m` (не только степеней двойки); учётная стоимость символа — `cost_e8(m)` (см. Форма).

**Бинаризация значения** `u` (zigzag, `zigzag(v) = (v << 1) ^ (v >> 31)`; только дельты энергий): частное `qt = u >> k` — унарно в адаптивном контексте (`qt` битов «1», затем «0»), после чего `k` младших битов `u` сырыми битами MSB-first. Эскейп: после 24 битов «1» (без стоп-бита) `u` целиком пишется как 32 сырых бита.

**Нормативный учёт стоимости** (rate-контроль): стоимость бита с частотой `f` (та сторона `prob0`/`4096−prob0`, что наблюдена) равна `768 − log2_x64(f)` в 1/64 бита, где `log2_x64(f) = ⌊64·log2(f)⌋`, вычисленный целочисленным методом последовательных возведений в квадрат (усечение только занижает `log2`, поэтому оценка — верхняя граница; реализация — `qmath::log2_x64`). Энкодер и декодер обязаны эволюционировать контексты в учёте так же, как при записи/чтении.

### Кадр (packet)

```
byte 0:   flags — bit0 = transient, bit1 = anti_collapse (только при bit0 = 1,
          иначе пакет невалиден), bit2 = 0 (резерв v0),
          bit3 = ms_stereo (1 для 2 каналов), bit4..7 = 0
byte 1-2: budget u16le — бюджет кадра в битах (см. Аллокация)
далее — поток range coder'а (без ведущего байта):
  trim: 3 сырых бита (MSB-first) — наклон аллокации, см. Аллокация,
  coarse-энергии всех плоскостей (плоскость за плоскостью, полосы по порядку),
  затем формы всех плоскостей (тот же порядок, полосы с β_e8 = 0 пропускаются):
    на кодируемую полосу — [fine u: 2 сырых бита][PVQ-рекурсия полосы, см. Форма],
  финализация range coder'а (5 байтов)
```

Декодер обязан возвращать ошибку (не панику) на любой некорректный вход; усечение обнаруживается флагом переполнения RC до изменения состояния декодера.

### PLC (потеря пакета)

`decode_lost()`: последний декодированный спектр каждой плоскости умножается на 0.7 и синтезируется как обычный кадр **в режиме последнего кадра** (длинный/транзиентный). Состояние overlap-add продолжает жить — щелчков на границе нет. Память энергий anti-collapse затухает на −4 единицы q за PLC-кадр (см. Anti-collapse).

As-built (v0): ASCII-магия **`FRAS`** (4 B). Резерв семейства FRC под нативный

```
магия "FRAS" (4B) | version u8 = 1 | channels u8 | sample_rate u32le |
frame_n u16le = 960 | num_samples u64le (на канал, без задержки)
затем пакеты: len u16le | payload[len] ... до EOF
```

Декодер файла отбрасывает первые `N` сэмплов (задержка) и обрезает хвост до `num_samples`. В FSCP/HTTP пакеты передаются собственным транспортом — контейнер не обязателен.

## Метрики и бенчмарки

- **Полигон качества `frc-a-polygon`** (с v0.7, основной инструмент): детерминированный синтетический корпус 17 кейсов (речь m/f/44.1, кастаньеты, аплодисменты, клавесин, глокеншпиль, пэд, EDM, легаси-микс, свип, мультитон, белый/розовый шум, широкое стерео, panned-клики, почти-тишина, стресс-плотность) × сетка битрейтов. Метрики: waveform-SNR, seg-SNR (10 мс), band-LSD по полосам кодека, NMR (средний и худший кадр; упрощённое маскирование — растекание 15/27 дБ/полосу, смещение 18 дБ, ATH −90 дБ от пика), pre-echo (RMS ошибки в окне 13 мс перед атакой относительно RMS атаки), стерео ILD-ошибка и side-дрейф, фактический kbps, enc/dec ×RT, доля транзиентных кадров. CLI: `run` (таблица + JSON-снимок + сравнение с baseline, ненулевой код выхода при регрессиях), `compare`, `list`, экспорт WAV для прослушивания. Quality-gates — интеграционные тесты с порогами на курируемом подмножестве.
- **Арена конкурентов** (v0.7.x, в составе `frc-a-polygon`): тот же корпус и те же метрики против Opus / AAC / MP3 / Vorbis через `ffmpeg`/`ffprobe` CLI (`run --vs opus,aac,mp3,vorbis|all`, доступность — `probe`). Честность сравнения: сырой f32 PCM в обе стороны; битрейт конкурента — сумма **пакетов** кодека по `ffprobe` (контейнерный оверхед не считается — как payload FRC-A); задержка кодека компенсируется кросс-корреляцией (грубо по энергетическим огибающим, точно по волне); Opus — кадр 20 мс и constrained VBR (дисциплина битрейта, сопоставимая с VBR FRC-A); прочие — дефолты ffmpeg с явной целью `-b:a`. Сводка арены: победы/поражения по NMR/segSNR/LSD, разбивка по битрейтам, топ кейсов-разрывов, флаг систематического отклонения фактического битрейта. ffmpeg — опциональная зависимость машины разработчика: без него полигон и CI-гейты работают в режиме только-FRC-A. Снимки JSON (schema v2) несут поле `codec`; снимки v1 читаются как `frc-a`.
- **Позиция v0.7 по арене** (замер 2026-07, объективные метрики полигона): seg-SNR и band-LSD выигрываем у всех конкурентов на большинстве кейсов (waveform-точность), **NMR проигрываем всем в среднем** — Opus +4.8 дБ, AAC +5.2, Vorbis +6.3, MP3 +8.1 (средний ΔNMR по сетке; меньше — лучше). Худшие разрывы — тонально-транзиентный контент (кастаньеты, глокеншпиль, клавесин) и вся сетка @24k; лучшие точки — EDM, свипы, шумы, мультитон @96k+. Вывод: аллокация всё ещё ближе к MSE, чем к перцептивной; приоритет v0.8 — шумовое формование/тональность, а не waveform-метрики.
- v0: SNR (время) и фактический kbps — `frc-a roundtrip`; band-LSD и pre-echo — интеграционные тесты `frc-a-core`.
- v0.x: объективное сравнение с Opus/AAC на корпусе — **сделано** (арена полигона, v0.7.x); остаются ViSQOL (объективное перцептивное качество) + слепые ABX (речь: чистая/шумная; музыка: разные жанры; edge: аплодисменты, клавесин, кастаньеты).
- Тест-векторы FRC-A добавляются в `Documents/test-vectors/` **только генерацией** из эталонной реализации (правило репозитория).

## Module boundaries

- Кодек — только `Products/FRC` (`frc-a-core`). Модули/приложения используют его как библиотеку; обратных зависимостей нет.
- Транскод-пайплайны остаются в своих владельцах (`Flora.Music`, `Apps/Web`) — FRC-A не двигает границы `CODECS.md`.
- E2E-инвариант сохраняется: голосовые кодируются на клиенте до шифрования.

- Компактная финализация RC: усечение хвостовых байтов конфликтует с детекцией усечённых пакетов флагом `overrun` (нулевой хвост неотличим от обрезанного); кандидат — CELT-схема с сырыми битами от конца буфера (v0.8) либо перенос детекции целостности на транспорт.
- Эвристика трима (v0.8): выбор по спектральному балансу без оценки тональности вредит многотоновому контенту (замер v0.7: −3.8 дБ SNR на multitone @24k) — нужен детектор тональности полос (spectral flatness / отношение пиковой к средней энергии бина).
