# Проверка монитора под палитру Flora

Локальная страница для приведения монитора к условиям, зафиксированным в
[`documents/design/color-reference.md`](../../documents/design/color-reference.md), и проверки того, что токены
видны так, как задумано: SDR, sRGB, γ 2.2, 6500 K, Full range, масштаб 100 %.

Страница **не измеряет** панель. Она показывает канонические sRGB-заливки и тесты «видно / не видно», по которым
настраивают монитор. Абсолютная точность (ΔE, белая точка, гамма-кривая) — только аппаратный калориметр + ICC-профиль.

## Состав

| Файл | Роль |
|------|------|
| `build.mjs` | Читает канонические источники, сверяет их и генерирует `index.html` |
| `index.html` | Готовая автономная страница; открывается двойным кликом, без сервера и зависимостей |
| `README.md` | Протокол настройки, критерии приёмки, журнал значений |

Источники правды, которые читает генератор (руками в `build.mjs` ничего не переносится):

- `packages/flora-client-core/src/display/floraThemeTokens.ts` — цвета токенов;
- `apps/Web/app/globals.css` (`:root`) — CSS-переменные, включая `color-mix`-производные;
- `documents/design/color-reference.md` — признанные бренд-цвета.

## Быстрый старт

```sh
node tools/monitor-calibration/build.mjs
```

Затем открыть `tools/monitor-calibration/index.html` в Chrome или Edge, развернуть на весь экран (`F11`),
убедиться, что масштаб Windows 100 % и разрешение 1920 × 1080.

Генератор падает, если бренд-цвета в токенах расходятся с `color-reference.md`, и предупреждает в консоли,
если какой-то токен расходится с одноимённой переменной в `:root`.

## Протокол

Порядок важен: динамические режимы искажают все последующие тесты.

1. **Сброс.** OSD → Reset. Монитор прогреть 30 минут, освещение в комнате постоянное и нейтральное (~6500 K).
2. **Режим картинки.** SmartImage → Standard (или sRGB, если пункт есть). SmartContrast, Over Scan, LowBlue,
   EasyRead, Pixel Orbiting, SmartResponse — Off. Sharpness — заводское (50).
3. **Система.** HDR и «Ночной свет» выключены. Разрешение 1920 × 1080, масштаб 100 %, 60 Гц.
   `colorcpl.exe` → профиль sRGB IEC61966-2.1 (или профиль производителя) по умолчанию.
4. **NVIDIA.** Формат цвета RGB, 8 bpc, динамический диапазон **Full**, Digital Vibrance 0,
   «Other applications control color settings».
5. **Яркость** — по тесту чёрного: 16 едва отличается от 0, 0 остаётся чёрным.
6. **Контраст** — по тесту белого: 250–255 различимы, 255 не «выгорает».
7. **Гамма** — по шахматке: с 50 %-полем сливается плашка γ 2.2 (код 186). В OSD выставить Gamma 2.2.
8. **Белая точка** — по серому клину: нейтральный от теней до светов. Color Temperature 6500 K.
   RGB-усиление вручную не крутить: без измерений это даёт оттенок и потерянные ступени.
9. **Контроль.** Тёмная лестница токенов, градиенты, 1 px сетка и текст 15 px.
10. **Запись.** Внести итоговые значения в журнал ниже.

## Критерии приёмки

| Тест | Норма | Если не так |
|------|-------|-------------|
| Чёрный 0–16 | 0 — чёрный, 1–2 не видны, 3–4 едва угадываются, 8+ видны | Схлопнулись 0–6 — поднять Brightness / включить Full range. 0 серый — Brightness завышена |
| Белый 239–255 | 250–255 различимы, 255 чистый белый | Всё от 239 белое — снизить Contrast / выключить SmartContrast. 255 серый — поднять Contrast |
| Гамма | С шахматкой сливается γ 2.2 (186) | 2.4 — монитор темнит середину, поднять Gamma; 2.0 — пересвет, опустить |
| Нейтраль | Клин без зелени/мадженты, белый белый | Сменить пресет 6500 K / sRGB; проверить Night Light и LowBlue |
| Тёмная лестница | Ступени различимы согласно ΔE, без провалов и лишних границ | Слипание — поднят чёрный/динамический контраст. Светлые линии между полосами — Over Scan/резкость/локальное затемнение |
| Градиенты | Плавно, без ступеней и цветных полос, особенно 0–48 | Ступени — выключить пост-обработку, проверить 8 bpc. Цветные полосы — сменить пресет цвета |
| 1 px сетка и текст | Линии резкие, без двойных контуров и радужной каймы | Проверить масштаб 100 %, Over Scan, ClearType, Sharpness |

## Ограничения

- Панель эталонного монитора — потребительская VA без заводской color-critical калибровки. Совпадение с hex
  достигается в пределах «пресет sRGB + γ 2.2 + 6500 K», а не в единицах ΔE.
- Браузер управляет цветом: если в ICC-профиле есть преобразование, страница и приложение увидят его одинаково.
  Расхождение между страницей и графическим редактором означает, что редактор применяет другой профиль.
- HDR, ночной свет, LowBlue, динамический контраст, масштабирование и пост-обработка делают тесты недействительными.

## Обновление

При изменении палитры: править `apps/Web/app/globals.css` → синхронизировать `FLORA_THEME_TOKENS` →
`node tools/monitor-calibration/build.mjs`. `index.html` не редактировать руками.
