# FRC-V — Flora Relativistic Codec — Video

**Status:** Draft (битстрим **v2** заморожен golden-векторами)  
**Version:** 1.1  
**Date:** 2026-07-16  
**Family:** FRC — Flora Relativistic Codec (см. [`CODECS.md`](./CODECS.md))  
**Reference implementation:** `Products/FRC/crates/frc-v` (Rust, pure std, `unsafe` запрещён)

---

## Overview

FRC-V — нативный видеокодек экосистемы FLORA. **v1** включает полный пайплайн
кадра: intra + **inter** (¼-pel MC, skip, spatial MV prediction), GOP,
отдельные хрома-режимы, rate control и SSIM-tuning в энкодере (не нормативны).

- Формат кадра: **YUV 4:2:0, 8 бит**, размеры кратны 8, до 16384×16384.
- Разбиение: суперблоки **64×64**, quadtree до листьев **8×8**.
- Предсказание: 7 интра-режимов (DC, TM, PLANAR, V, H, D45, D135);
  inter — ¼-pel luma (6-tap), bilinear chroma; skip-блоки.
- Преобразование: целочисленный DCT-II **4/8/16/32** с выбором размера на лист.
- Энтропия: адаптивный бинарный **range-coder** (15-битные вероятности).
- Пост-фильтр: деблокинг по сетке 8×8.

Измерения (30 кадров, PSNR overall, против x264 `-preset medium -tune psnr`):

| Режим | Клип | BD-Rate |
| --- | --- | --- |
| intra (`-g 1`) | foreman_cif | **−0.1%** |
| intra | testsrc2 640×360 | **−6.4%** |
| inter (`-g 30`) | foreman_cif | см. `Products/FRC/README.md` |

Документ нормативен для декодера: поток **версии 2** обязан давать
бит-в-бит одинаковую реконструкцию на всех платформах. Изменения битстрима
только вместе с регенерацией golden (`FRC_V_UPDATE_GOLDEN=1`).

### Design rationale

| Решение | Мотив |
| --- | --- |
| Бинарный range-coder + адаптация сдвигом | плотность арифметического кодера без таблиц переноса; модель = одно `u16` на контекст; тривиально зеркалится в декодере |
| Квантование в домене «8 × ортонормальный DCT» | одна таблица шагов на все размеры трансформа; энергия сохраняется между размерами |
| Единый код реконструкции у энкодера и декодера | паритет «recon энкодера == выход декодера» обеспечивается конструктивно, а не тестами постфактум |
| Кадры v1: intra + inter, одна ссылка (последний реконструированный) | простой GOP; P-кадры без второй ссылки; основа для B-кадров в v2 |
| Деблокинг вне цикла предсказания | intra-опоры берутся из нефильтрованной реконструкции — фильтр можно менять, не ломая паритет предсказания |
| Чистый std, без `unsafe`, целочисленные нормативные пути | аудируемость, WASM-декодер, детерминизм на всех платформах |

## 1. Терминология и соглашения

- Целые — **little-endian**; сдвиги `>>` над знаковыми — арифметические.
- `clamp(v, lo, hi)` — ограничение диапазона; `avg3(a,b,c) = (a + 2b + c + 2) >> 2`.
- `round_shift(v, s) = (v + 2^(s−1)) >> s` (v — i64).
- «Плоскость» — массив отсчётов row-major; Y — W×H, Cb/Cr — (W/2)×(H/2).
- Люма-координаты: блок `(x, y, n)` — квадрат n×n с левым-верхним углом (x, y).
  Хрома-блок листа: `(x/2, y/2, n/2)` в плоскостях Cb/Cr.
- `pt` — тип плоскости в контекстах энтропии: 0 — Y, 1 — Cb и Cr.

## 2. Контейнер

**Продуктовый (v1):** нативный `.frv`, magic **`8F 46 52 56`**, 32-байтовый
заголовок (width/height u16, fps_num/fps_den u32, frame_count u32), кадры:
`u32 size ‖ u64 pts ‖ payload`. Реализация — `crates/frc-v/src/container.rs`.

**Dev / совместимость:** **IVF** с FourCC **`FRV1`** (32-байтовый заголовок
`DKIF`, затем кадры `u32 size ‖ u64 pts ‖ payload`). CLI выбирает формат
по расширению (`.ivf` → IVF, иначе `.frv`).

Продуктовый A/V-mux с FRC-A — отдельный формат FRC (реестр — [`CODECS.md`](./CODECS.md)).

---

## 3. Заголовок кадра (байтовый, до арифметики)

| Смещение | Размер | Поле |
| --- | --- | --- |
| 0 | 1 | версия битстрима = **2** |
| 1 | 1 | флаги: bit0 — keyframe, bit1 — деблокинг включён |
| 2 | 1 | `qp` ∈ 0..=63 |
| 3 | 2 | `width − 1` (u16 LE) |
| 5 | 2 | `height − 1` (u16 LE) |

Ошибки разбора (короткий буфер, чужая версия, qp > 63, размеры не кратны 8
или > 16384) — отказ декодирования. P-кадр (`keyframe = 0`) требует
валидной ссылки (последний декодированный кадр того же размера). Остаток
пакета — арифметический поток.

---

## 4. Range-coder (нормативный)

Байтовый бинарный range-coder (низ `low`/диапазон `range`, перенос через
cache/FF-цепочку — схема LZMA rc).

**Вероятность** — `u16 p ∈ [1, 32767]`: оценка P(bit = 0)·2¹⁵.
Адаптация после каждого закодированного/декодированного бита (зеркально):

```
bit=1:  p -= p >> 5;              если p == 0 → p = 1
bit=0:  p += (32768 − p) >> 5
```

**Энкодер.** `low: u64 = 0`, `range: u32 = 0xFFFF_FFFF`, `cache = 0`,
`cache_size = 1`. Кодирование бита с вероятностью p:
`bound = (range >> 15) · p`; bit=1 → `low += bound; range −= bound`,
bit=0 → `range = bound`; адаптация; пока `range < 2²⁴`: `shift_low(); range <<= 8`.
«Сырой» бит (вероятность ½, без адаптации): `bound = range >> 1`.
Завершение: 5 × `shift_low()`. Первый байт потока всегда 0.

**Декодер.** Читает 1-й байт (пропускает), затем 4 байта в `code`;
`range = 0xFFFF_FFFF`. Бит: `bound = (range >> 15) · p`; `bit = code ≥ bound`;
bit=1 → `code −= bound; range −= bound`, иначе `range = bound`; адаптация;
пока `range < 2²⁴`: `code = (code << 8) | next_byte(); range <<= 8`.
**Исчерпание входа:** `next_byte()` возвращает 0 (декодер не завершается
досрочно и не падает; завершение гарантируют счётчики синтаксиса).

Все контексты (§6–§8) сбрасываются в начальные значения на каждом кадре.

## 5. Геометрия разбиения

Суперблоки 64×64 обходятся растром. Узел `(x, y, n)` классифицируется:

```
Outside:   x ≥ W или y ≥ H              — узла нет, синтаксис не кодируется
MustSplit: x+n > W или y+n > H          — принудительное разбиение (без флага)
Leaf:      n = 8                        — лист (без флага)
Choice:    иначе                        — кодируется флаг split
```

Дети узла — четверти в порядке **TL, TR, BL, BR**. Так как W, H кратны 8,
блок 8×8 не пересекает границу никогда.

Синтаксис листа (в порядке кодирования):

**Ключевой кадр** (`keyframe = 1`): `[split-флаги] → режим люмы → chroma_mode? → tx_split → тайлы Y → Cb → Cr`.

**P-кадр** (`keyframe = 0`): `[split-флаги] → is_inter →`  
если inter: `MVD → skip?` (skip=1: без остатка; иначе `tx_split → Y → Cb → Cr`);  
если intra: как ключевой (без `is_inter=0` на ключах).

`is_inter` контекст `inter_ctx` ∈ {0,1,2} — число inter-листьев среди
соседей слева/сверху в сетке 8×8 (аналог `dir_ctx`). MV предсказывается
медианой доступных соседей (`med3`); `MVD` кодируется экспоненциально-Голомба
в диапазоне ±`MVD_MAX`. MC: luma ¼-pel (6-tap), chroma bilinear ⅛-pel.

## 6. Синтаксические элементы и контексты

Начальные вероятности (P(0)·2¹⁵) нормативны.

| Элемент | Контекст | Инициализация |
| --- | --- | --- |
| `split` | глубина узла: n=64→0, 32→1, 16→2 | 20000, 18000, 16384 |
| `is_inter` | `inter_ctx` ∈ 0..=2 | 16384 ×3 |
| `skip` | — | 20000 |
| `mvd` | компоненты exp-Golomb | см. `syntax.rs` |
| `chroma_mode` | флаг «отдельный режим» + дерево режима | init 20000 |
| `directional` | `dir_ctx` ∈ 0..=2 | 22000, 16384, 10000 |
| `dc`, `tm`, `diag`, `h`, `d135` | — | 14000, 16384, 20000, 16384, 16384 |
| `tx_split` | размер листа: 8→0, 16→1, 32→2, 64→3 | 20000 ×4 |

**Дерево режима:** бит `directional`; если 0 → бит `dc` (1 = DC),
иначе бит `tm` (1 = TM, 0 = PLANAR); если 1 → бит `diag`; если 0 →
бит `h` (1 = H, 0 = V), иначе бит `d135` (1 = D135, 0 = D45).

**`chroma_mode`:** если флаг = 0 — хрома использует режим люмы; иначе
кодируется отдельное дерево режима (те же 7 режимов, §10.2).

**`dir_ctx`** — число доступных соседей (ячейка сверху и слева в сетке
режимов 8×8) с направленным режимом (V/H/D45/D135). Сетка заполняется
режимом листа для всех его ячеек 8×8 сразу после декодирования режима.

**`tx_split`:** базовый размер трансформа люмы `t = min(n, 32)`
(лист 64 кодируется 4 тайлами 32×32); `tx_split = 1` → размер `t/2`,
т.е. лист n даёт `(n/t)²` тайлов в растровом порядке. Хрома — всегда один
блок n/2 (флаг на хрому не действует).

## 7. Кодирование коэффициентов

Квантованные уровни блока t×t кодируются по **зигзаг-скану** (§7.1).

Схема: бит `cbf` («есть ненулевые», контекст `pt × size_idx(t)`,
init 16384). Если cbf=1 — по скану для каждой позиции:

1. бит `nz` (контекст `pt × band × pctx`, init 26000), 0 → `pctx=0`, дальше;
2. величина: `gt1` (`pt × band × pctx`, init 20000), `gt2` (`pt × band`,
   18000), `gt3` (`pt × band`, 16384); если |l| > 3: `r+1 = |l| − 3`,
   категория `c = bitlen(r+1) − 1` кодируется унарно битами `cat[pt][i]`
   (init 20000, i = 0..c−1 единицы, затем ноль, если c < 14), затем
   `c` сырых бит `r+1 − 2^c` (старший первым);
3. знак — сырой бит (1 = минус);
4. если позиция не последняя в скане — бит `eob` (`pt × band`, init 16384);
   eob=1 → остальные уровни нулевые, конец блока.

`pctx` ∈ {0, 1, 2} — величина предыдущего ненулевого уровня (0, 1, ≥2);
сбрасывается в 0 после нулевого уровня. Максимум декодируемой величины —
**32767** (избыток клампится). Энкодер v0.1 не превышает 16384.

### 7.1 Зигзаг-скан и полосы

Скан n×n обходит антидиагонали `d = r + c` от 0 до 2n−2; нечётные d —
сверху-вниз (r растёт), чётные — снизу-вверх (r убывает). Для n=8 первые
позиции совпадают с JPEG: (0,0),(0,1),(1,0),(2,0),(1,1),(0,2)…

Полоса позиции скана `pos` в блоке из n² отсчётов: `BAND64[pos·64/n²]`, где

```
BAND64: 0→0, 1→1, 2→2, 3..5→3, 6..9→4, 10..20→5, 21..41→6, 42..63→7
```

## 8. Дезквантование

Шаги (домен коэффициентов = 8 × ортонормальный, §9):

```
AC_STEP[q] = round(8 · 2^(q/8)),  q = 0..63        (8 … 1878)
DC_STEP[q] = max(6, round(0.8 · AC_STEP[q]))
```

Уровень `l` → коэффициент `clamp(l · step, −131071, +131071)`
(`COEFF_CLAMP = 2¹⁷−1`; защита обратного преобразования на битых потоках).
DC-шаг — для позиции 0 растра, AC — для остальных.

## 9. Преобразования (нормативные)

Матрица `T` размера n ∈ {4, 8, 16, 32}:

```
T[k][j] = round( 2^(13−log2 n) · √2 · c_k · cos(π(2j+1)k / 2n) ),   c_0 = 1/√2, иначе 1
```

(T = 2^(13−log₂n)·√N · O, O — ортонормальная DCT-II; N·max|T| ≈ 2¹³·√2 —
константа для всех размеров.) Матрицы зафиксированы в
`crates/frc-v/src/tables.rs`, генератор — `tools/gen_tables.mjs`; DCT4 для сверки:

```
[ 2048  2048  2048  2048 ]
[ 2676  1108 −1108 −2676 ]
[ 2048 −2048 −2048  2048 ]
[ 1108 −2676  2676 −1108 ]
```

Аккумуляция — **i64, без промежуточного округления**, единственный
`round_shift` на выходе каждой стадии-пары:

```
Прямое (энкодер):   C = round_shift(T · X · Tᵗ,  23 − log2 n)
Обратное (норматив): X = round_shift(Tᵗ · C · T,  29 − log2 n),
                     затем clamp(±2047)  (RESIDUAL_CLAMP)
```

Точнее: стадия 1 считает суммы без сдвига, стадия 2 применяет один
`round_shift` итога. Переполнение исключено: |acc| < 2⁴⁴.

Домен коэффициентов равен **8 × ортонормальному**: шаг квантования 8 ≈ 1
единица ортонормального домена; ошибка целочисленного roundtrip ≤ 2 LSB.

## 10. Интра-предсказание

### 10.1 Опоры

Для блока n×n в (x, y) собираются: `above[0..2n]` (строка y−1, столбцы
x..x+2n−1), `left[0..n]` (столбец x−1), `above_left` (x−1, y−1).
Недоступные из-за границы кадра → **128**; `has_above = y>0`, `has_left = x>0`.

Продолжение вверх-вправо `above[n..2n]`: отсчёт (x+k, y−1) берётся из
плоскости, если он **уже реконструирован** в порядке кодирования, иначе
реплицируется последний доступный. Нормативное правило доступности
(`preceded`) для пикселя (px, py) относительно блока (bx, by), py < by:

- `py/S < by/S` → доступен (предыдущий ряд суперблоков);
- иначе `px/S ≠ bx/S` → недоступен (правый сосед-суперблок не кодировался);
- иначе сравниваются Morton-индексы ячеек внутри суперблока:
  `morton(px%S/c, py%S/c) < morton(bx%S/c, by%S/c)`,
  где `morton` перемежает биты (y-бит старше x-бита, 3 уровня),
  что в точности повторяет порядок обхода quadtree TL,TR,BL,BR.

Параметры сетки: люма `S=64, c=8`; хрома `S=32, c=4`.

### 10.2 Режимы

```
DC:     среднее доступных опор above[0..n], left[0..n] (см. формулы ниже)
TM:     clamp(left[i] + above[j] − above_left, 0, 255)
PLANAR: ((n−1−j)·left[i] + (j+1)·above[n] + (n−1−i)·above[j] + (i+1)·left[n−1] + n) >> (log2 n + 1)
V:      above[j]
H:      left[i]
D45:    k = i+j;  k+2 < 2n ? avg3(above[k], above[k+1], above[k+2]) : above[2n−1]
D135:   pred[i][j] = border[n−1−i+j]   (сглаженная кромка, см. ниже)
```

DC: обе опоры → `(Σabove + Σleft + n) / 2n`; только верх → `(Σabove + n/2)/n`;
только лево — симметрично; ничего → 128.

Кромка D135 (`border[0..2n−1]`):

```
border[i]     = avg3(left[n−3−i], left[n−2−i], left[n−1−i]),  i = 0..n−3
border[n−2]   = avg3(above_left, left[0], left[1])
border[n−1]   = avg3(left[0], above_left, above[0])
border[n]     = avg3(above_left, above[0], above[1])
border[n+1+i] = avg3(above[i], above[i+1], above[i+2]),        i = 0..n−3
```

### 10.3 Реконструкция листа

Предсказание строится **на весь блок листа** по опорам из соседей
(тайлы трансформа не предсказываются друг от друга). Затем тайлы в растровом
порядке: дезквант → обратное преобразование → `rec = clamp(pred + res, 0, 255)`.
Хрома: режим из `chroma_mode` или люмы; блоки Cb и Cr по n/2.

Интра-опоры всегда берутся из **нефильтрованной** реконструкции.

## 11. Деблокинг

Если флаг включён — после реконструкции всего кадра, по каждой плоскости:
сначала **все вертикальные** границы сетки 8×8 (столбцы x = 8, 16, …),
затем **все горизонтальные** (строки y = 8, 16, …). Порог
`limit = clamp(AC_STEP[qp] / 4, 2, 120)`.

Пара (p1, p0 | q0, q1) поперёк границы; если
`2·|p0−q0| + |p1−q1|/2 > limit` — без изменений, иначе:

```
a  = clamp(clamp(p1 − q1, −128, 127) + 3(q0 − p0), −128, 127)
f1 = clamp(a + 4, −128, 127) >> 3
f2 = clamp(a + 3, −128, 127) >> 3
q0' = clamp(q0 − f1, 0, 255);  p0' = clamp(p0 + f2, 0, 255)
```

## 12. Требования к декодеру

- **Бит-точность:** только целочисленные операции; результат одинаков на всех
  платформах (включая wasm32) и равен реконструкции референсного энкодера.
- **Безопасность:** никаких паник на произвольном входе. Структурные ошибки
  заголовка → отказ; повреждённый арифметический поток → мусорное, но
  безопасное изображение (все пути клампированы, синтаксис конечен,
  исчерпание входа → нулевые байты).
- Лимиты: размеры ≤ 16384, аллокации — только из провалидированных размеров.

## 13. Референсный энкодер (не нормативно)

- **RDO-quadtree:** рекурсивное сравнение листа (intra / inter / skip) против
  суммы детей, метрика `D·λ_den + rate·λ_num`; при `--ssim-tune` дисторсия D —
  смесь SSE и целочисленного SSIM-прокси (~22% веса).
- **Inter:** integer motion search (¼-pel), skip при нулевом остатке,
  spatial MV prediction; стартовые кандидаты поиска — (0,0), spatial-предиктор,
  hint родительского блока и **temporal co-located MV** из финальной сетки
  предыдущего кадра.
- **GOP:** ключ каждые `keyint` кадров (qp − 4 на ключе). **Детектор смены
  сцены** (`--no-scene-cut` отключает): двухфакторное сравнение исходников —
  сдвиг гистограммы люмы (32 корзины, порог 40% массы) **и** MAD средних
  блоков 8×8 после компенсации глобального сдвига яркости (порог 12 уровней);
  оба фактора высоки → форс-ключ и перезапуск GOP. Движение (панорама, зум,
  дрожание) не двигает гистограмму, фейд гасится компенсацией яркости.
- **Rate control v2:** `--bitrate` — стартовый qp из целевых бит на пиксель
  (`qp ≈ 32 − 8·log₂(bpp/0.055)`), далее виртуальный буфер с утечкой 1/32
  и плавным ходом qp не быстрее ±2 за кадр (не влияет на декодер).
- **RDOQ:** жадный проход по ненулевым уровням от хвоста скана.
- **Пресеты скорости:** `--speed 0..2`, битстрим и декодер не зависят от пресета.
  0 — полный RDO; 1 — RD по топ-2 режимов, урезанный поиск движения, без RDOQ,
  ранний акцепт листа/skip на шумовом пороге квантования (`SSE·1024 ≤ n²·step²`);
  2 — режим люмы по SAD-преселекту, хрома `same`, один размер трансформа,
  суб-пиксельное уточнение до ½-pel.
- **Метрики:** `metrics::psnr/ssim` (+аккумуляторы последовательностей) —
  инструментальные PSNR и SSIM (окно 8×8, шаг 4, C₁/C₂ по BT.601-диапазону);
  CLI печатает обе в `encode` и `psnr`.
- **WASM-обёртка:** `crates/frc-v-wasm` — C-ABI декодера **и энкодера**
  (вход I420/RGBA, выход RGBA; конверсии BT.601 ненормативны; флаг bit2 —
  отключение детектора склеек) + JS-глу `www/frc-v-player.mjs` (плеер,
  `FrcVEncoder`, mux/demux `.frv`) — клиентское кодирование E2E-контура
  в Apps/Web.
- Энкодер детерминирован при фиксированных опциях.

Скорость (десктоп x86-64, 1 поток, 640×360): encode ~1.5–2 fps (speed 0),
decode ~120–150 fps; пресеты (синтетика 320×192): speed 1 ≈ ×11, speed 2 ≈ ×35
к скорости кодирования при −0.0…0.1 dB и +2…5% размера. Hot-path: развёрнутые
SSE/SAD-циклы для LLVM автовекторизации (без `unsafe`).

## 14. Golden-векторы, полигон и эволюция

Три уровня пиннинга (`crates/frc-v/tests/`):

1. **Golden** (`golden.rs`, `tests/data/golden.sums` + `*.frv`) — референсный
   энкодер байт-в-байт и чексаммы реконструкции декодера. Регенерация —
   осознанная, когда меняются *решения* энкодера при неизменном формате:
   `FRC_V_UPDATE_GOLDEN=1 cargo test -p frc-v --test golden`.
2. **Архив декодера** (`archive.rs`, `tests/data/archive/`) — исторические
   потоки прежних эр энкодера; **никогда не регенерируется**, только
   пополняется (`era1` — энкодер v0.7 до temporal-MV). Расхождение — это
   несовместимое изменение декодера: требуется bump `BITSTREAM_VERSION`,
   старые потоки обязаны остаться читаемыми.
3. **Полигон** (`polygon.rs` + генераторы `tests/common/`) — 13 классов
   синтетики (градиенты, шахматки, кольца-зум, terrain-пан/ротация,
   псевдотекст, шум, плазма, объекты поверх фона, хрома-паттерны, фейды,
   склейки сцен; движение — static/pan/zoom/rotate/jitter, суб-пиксельное).
   На каждом клипе: паритет encode↔decode по кадрам, пороги PSNR/SSIM/bpp,
   расписание ключей, отсутствие ложных срабатываний детектора склеек,
   сходимость rate control (±25%), монотонность по qp, детерминизм,
   паритет на всех пресетах. Ручной отчёт:
   `cargo test -p frc-v --release --test polygon -- --ignored --nocapture polygon_report`.

### 14.1 Кросс-кодек полигон (`frc-v-polygon`)

Арена против внешних кодеков — отдельный крейт `crates/frc-v-polygon`
(CLI `frc-v-polygon`): x264 / x265 / libvpx-VP9 / SVT-AV1 / libaom-AV1 через
ffmpeg в равных условиях (1 поток, общий keyint, elementary stream без
контейнера, FRC-V — процессом `frc-v` CLI). Корпус: детерминированная
синтетика (natural/organic/screen/objects/chroma/grain/montage/720p) +
эталонные клипы xiph/derf (`fetch`). Метрики: PSNR/SSIM единым кодом
`frc_v::metrics`, VMAF через libvmaf; сводка — **BD-rate** (PCHIP, схема
JVET/AOM) против каждого конкурента; отчёт — markdown + SVG RD-кривые +
JSON-снимок. Прогресс между версиями энкодера отслеживается
`frc-v-polygon compare old.json new.json` (self-BD-rate; ненулевой код выхода
при регрессиях). Типовой цикл:

```sh
cargo build --release -p frc-v-cli -p frc-v-polygon
frc-v-polygon fetch                # эталонные клипы (опционально)
frc-v-polygon run --label baseline # polygon-out/{snapshot.json,report.md,plots/}
frc-v-polygon run --label next --out polygon-out-next --baseline polygon-out/snapshot.json
```

Версия битстрима **1** (intra-only draft) устарела; декодер v1 принимает
только **версию 2**.

Планируемое (v2+): B-кадры, tile-параллелизм в битстриме, продуктовый
A/V-mux с FRC-A. WASM-энкодер реализован (см. §13, `frc-v-wasm`).
