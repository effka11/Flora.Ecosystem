## Overview

FSA-D — поиск по черновикам пользователя. Домен строго личный: «найти то, что я начал писать». Самый агрессивный recency-буст среди Boost-профилей (черновики живут короткими итерациями), typeahead с первого символа — и **принципиальный отказ от персонализации**.

---

## Architecture Position

**Владелец данных:** модуль-владелец черновиков (Social Content). Индекс per-user; может жить и на клиенте (ядро wasm32-совместимо) — для черновиков, не синхронизированных с сервером.

---

## Профиль (нормативный)

| Поле | Вес | positions | exact_boost |
|------|-----|-----------|-------------|
| `title` | 1.8 | ✓ | — |
| `text` | 1.0 | ✓ | — |
| `tags` | 1.2 | — | — |

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| recency | Boost, half-life **14 дней**, вес 0.5 | недавно редактированное — почти всегда искомое |
| static_rank | — | глобального приора у личных данных нет |
| proximity | 0.2 | поиск по фразе из собственного текста |
| λ (персонализация) | **0.0 — нормативно** | см. ниже |
| expansion | prefix ≥ 1, fuzzy ≥ 3 | typeahead по своим коротким заголовкам |

**Персонализация запрещена конструкцией.** `λ_d = 0` ⇒ множитель `1 + α·λ·A` равен 1 при любом `α` и любом снимке. Обоснование двойное: (1) индивидуальность бессмысленна — все документы и так принадлежат пользователю; (2) сигналы FIRA не должны касаться приватного контента даже в виде переупорядочивания. `DraftsQuery` намеренно не имеет поля `personalization`, `DraftsSearch::search` не принимает контекст.

## Документ

`DraftDoc`: `id`, `title?`, `text`, `tags[]`, `kind?` (post/article — словарь за владельцем), `community_id?` (черновик для сообщества), `updated_at` (последнее редактирование).

Атрибуты: `kind`, `community_id`. Ключей аффинити нет.

---

## API

`DraftsQuery`: `query`, `limit/offset`, `now`, `kind?`, `community_id?`.
