## Overview

FSA-M — поиск по сообщениям. Ключевое отличие от всех остальных поверхностей: сообщения E2E-зашифрованы (FSCP), сервер не видит plaintext — **индекс живёт на клиенте** поверх локального стора расшифрованных сообщений. Это возможно потому, что ядро FSA — чистая in-memory структура без I/O и часов, компилируемая в `wasm32`.

---

## Architecture Position

**Владелец данных:** локальный стор Messaging на устройстве (Apps/Web worker, Apps/Mobile). Сервер (`flora-messaging`) не участвует ни в индексации, ни в исполнении запросов.

```
Apps/Web (web worker, wasm)
  ├─ локальный стор расшифрованных сообщений → MessagesSearch.upsert
  ├─ запрос пользователя → MessagesSearch.search
  └─ PersonalizationContext — строится на клиенте (частота переписки)
```

**Нормативные границы приватности:**
- plaintext, индекс и ключи аффинити не покидают устройство;
- серверные FIRA-сигналы в FSA-M не участвуют (FIRA.md §12: любые данные Messaging запрещены для FIRA — симметрично, FIRA не участвует в поиске по сообщениям);
- контекст аффинити строится только из локальных данных: частота переписки с отправителем (`sender:{id}`), активность диалога (`conversation:{id}`).

## Профиль (нормативный)

| Поле | Вес | positions | exact_boost |
|------|-----|-----------|-------------|
| `text` | 1.0 | ✓ | — |
| `attachment_name` | 0.8 | — | — |
| `sender_name` | 0.5 | — | — |

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| recency | Boost, half-life **30 дней**, вес 0.3 | недавняя переписка вероятнее искомой |
| static_rank | — | у сообщений нет глобального приора |
| proximity | 0.3 | пользователь помнит фразу — совпадение фрагмента важно |
| λ (персонализация) | **0.3** | лёгкое предпочтение активных диалогов; релевантность текста первична |
| expansion | prefix ≥ 3, fuzzy ≥ **5** | консервативный fuzzy: короткие слова чатов («привет», «ок») дают шумные исправления |

## Документ

`MessageDoc`: `id`, `text` (расшифрованный), `attachment_name?`, `sender_id` + `sender_name`, `conversation_id`, `kind?` (text/image/file/voice/video — словарь за Messaging), `sent_at`.

Атрибуты: `conversation_id`, `sender_id`, `kind`.  
Ключи аффинити: `sender:{sender_id}`, `conversation:{conversation_id}`.

---

## API

`MessagesQuery`: `query`, `limit/offset`, `now`, `personalization (α)`, `conversation_ids[]` (пусто — все диалоги; иначе `any_of`-скоуп), `sender_id?`, `kind?`.

Поиск внутри одного диалога = `conversation_ids = [id]`. Глобальный поиск + группировка выдачи по диалогам — зона UI.
