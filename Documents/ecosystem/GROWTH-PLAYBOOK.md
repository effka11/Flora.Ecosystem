**Status:** Living document
**Version:** 0.3
**Date:** 2026-08-02

Стратегия и обоснования — [`GROWTH.md`](./GROWTH.md) (нормативный документ, v0.4). Здесь — только **исполнение**: пошаговые схемы, готовые тексты, чек-листы, **реестр точек outreach**. Формат каждой схемы: предусловия → шаги → готовый текст → критерий «сделано» → что мерить. Ничего не выдумывать на ходу: если ситуация не покрыта схемой — сначала дописать схему.

> 0.2 → 0.3: добавлен [Реестр точек outreach](#реестр-точек-outreach) (именованные организации/сообщества); Схема 0/1 ссылаются на него; первая точка — Партия «Яблоко».

Все тексты — черновики: перед отправкой перечитать и очеловечить под конкретного адресата. Отправка шаблона «как есть» заметна и работает хуже.

## Схема 0. Запуск кампании — первая неделя, по дням

Предусловие: ничего. Это точка старта.

| День | Действия (≈2 ч/день) | Результат |
| --- | --- | --- |
| **Пн** | Создать Telegram-канал проекта. Написать пост №1 — «что такое Flora и зачем» (текст ниже). Закрепить. | Канал жив |
| **Вт** | GitHub-витрина за один заход: repo description + topics (`social-network`, `e2e-encryption`, `privacy`, `rust`, `agpl`, `nextjs`, `image-codec`), включить Discussions, 3–5 скриншотов продукта в README; заодно убрать из README устаревший .NET-блок (GROWTH §7.1) | Репозиторий продаёт |
| **Ср** | Зарегистрировать аккаунт проекта в Mastodon (инстанс: mastodon.social или fosstodon.org). Профиль: формула позиционирования GROWTH §2.1 + ссылки. Первый пост — интро-тред | EN-присутствие |
| **Чт** | Заполнить [Реестр точек outreach](#реестр-точек-outreach): ≥20 именованных кандидатов (организации + чаты/клубы), отсортировать по близости (знакомые → знакомые знакомых → холодные). Критерии — GROWTH §4.6 | Реестр жив |
| **Пт** | Отправить первые 3 сообщения по точкам со статусом `кандидат` / тёплым лидерам (текст — Схема 1). Пост в TG-канал: «итоги недели» | Воронка деревень открыта |
| **Сб–Вс** | Начать статью №2 (миграция на Rust — завершена, история готова) или №8 (экономика без рекламы) из GROWTH §5.2 — 2–3 часа черновика | Черновик существует |

>

>

Критерий «сделано»: все 6 строк таблицы закрыты к воскресенью. Мерить: ничего, это фундамент.

## Схема 1. Вербовка «деревни» (микро-сообщества)

Предусловия: продукт принимает регистрации; у тебя есть инвайты; сообщества во Flora создаются; точка есть в [Реестре](#реестр-точек-outreach) со статусом `кандидат` или `контакт`.

Шаги:

1. Выбрать точку из реестра. Начинать с самых тёплых и с заполненным «углом».
2. Написать координатору **лично** (не в общий чат / не в пресс-форму без имени). Текст ниже, адаптировать под «угол» из реестра.
3. Если «да» → созвон/переписка 15 мин: что за сообщество, что им нужно. Создать им сообщество во Flora, выдать пачку инвайтов (лидеру — 20, не по 5). Статус точки → `пилот`.
4. Первые 2 недели — «консьерж»: отвечать на вопросы лично, баги от них — в приоритет.
5. Через 2 недели спросить лидера: «что мешает сильнее всего?» → в бэклог. При живой активности → `живая`; при отказе/тишине → обновить статус в реестре.

**Сообщение лидеру (тёплому знакомому):**

> Привет! Я делаю Flora — свою соцсеть с E2E-шифрованием, без рекламы и алгоритмического мусора (код открыт: github.com/effka11/Flora.Ecosystem). Сейчас альфа, и я собираю первые живые сообщества.
>
> Подумал про [название сообщества]: хотите попробовать переехать? Я всё настрою сам: создам сообщество, дам инвайты на всех, любые баги от вас чиню в первую очередь, фичи под ваши нужды обсуждаем напрямую со мной. Бесплатно навсегда — проект некоммерческий по уставу.
>
> Честно скажу: это альфа, что-то может отвалиться. Зато вы влияете на продукт, пока он мягкий.

**Сообщение холодному лидеру / координатору организации** — то же, плюс: (a) откуда ты их знаешь / почему именно они; (b) **зачем это им** (одна конкретная польза из колонки «Что даём» реестра); (c) явное «Flora — инфраструктура, не аффилиат» для политических и гражданских точек. Без (a)+(b) это спам.

**Угол для гражданской/политической точки (шаблон, подставить из реестра):**

> Здравствуйте, [имя/роль]!
>
> Я соло-разработчик открытой некоммерческой соцсети Flora (E2E на своём протоколе FSCP — сервер физически хранит только шифртекст; без рекламы и слежки; код AGPL: github.com/effka11/Flora.Ecosystem).
>
> Пишу, потому что [конкретное совпадение ценностей / их публичная позиция по цифр. правам или приватности]. Для [организация] это может быть полезно как [что даём: орг. чаты E2E + сообщество без чужой платформы], без зависимости от Telegram/Meta и без сдачи переписки хосту.
>
> Не предлагаю аффилиацию и не прошу публичной поддержки проекта — только пилот инфраструктуры для тех, кому это нужно. Альфа, честные ограничения есть. Если есть 15 минут у координатора по цифровой коммуникации — расскажу и выдам инвайты.

Критерий «сделано» для одной деревни: сообщество создано, ≥60% участников зарегистрировались, в первую неделю ≥10 постов/сообщений. Мерить: WASU деревни через агрегаты (GROWTH §6.6), субъективный ответ лидера через 2 недели.

Норма: 3 новых контакта в неделю. Конверсия ожидаемая ~1 из 3–4 у тёплых, ~1 из 10 у холодных — это нормально, не бросать после отказов.

## Схема 2. Статья на Habr — от черновика до публикации

Предусловия: выбрана тема из бэклога GROWTH §5.2.

Шаги:

1. **Структура (30 мин):** заголовок-обещание → лид (боль читателя, 2 абзаца) → 3–5 разделов с кодом/диаграммами из репозитория → честный раздел «что не получилось/ограничения» → финал со ссылками (GitHub + альфа + канал).
2. **Черновик (4–6 ч, можно за 2–3 захода).** Диаграммы уже есть в `ARCHITECTURE.md`/спеках — переиспользовать.
3. **Вычитка на следующий день** (не в день написания). Проверить: каждое утверждение о продукте подкреплено ссылкой на код/спеку.
4. **Публикация: вторник–четверг, 10:00–12:00 МСК** (максимум трафика Habr).
5. **Первые 3 часа после публикации — дежурство**: отвечать на каждый комментарий быстро и по делу. Первые часы решают, попадёт ли статья в топ.
6. **Переупаковка (правило актива):** в тот же день — пост в TG с выжимкой; на следующий — тред в Mastodon/X (EN-выжимка); через неделю — EN-версия на dev.to с каноникалом.

Заголовки: «Как мы сделали X» работает лучше «X: обзор». В заголовок — конкретику: «свой E2E-протокол», «свой аудиокодек на Rust», «7 модулей, одна БД».

Ответ на неизбежный комментарий «зачем свой протокол/кодек, есть же Signal/Opus/AVIF»: не защищаться, а объяснить требование, которого не покрывает готовое, признать trade-off и сослаться на спеку. Готовый абзац держать в статье заранее — снимает 80% негатива. Для FSCP: привязка ключей к учётным данным и миграция устройств без потери истории. Для FRC-I (готовый абзац): «условия задачи — декодер на чистом Rust без unsafe и C-зависимостей, который компилируется в WASM для браузера и в native для сервера/мобильных **из одного исходника**, безопасен на недоверенном вводе и достаточно прост, чтобы его мог прочитать один человек; encode ≥ 10 Мп/с на сервере без GPU. AVIF при равном PSNR плотнее нас на ~26% — это опубликовано в нашей же таблице; зато encode у нас ~×19 быстрее aom, и весь полигон воспроизводится одной командой (`Tools/frc-i-compete/run_compete.py`). PSNR занижает перцептивную разницу — butteraugli-класс метрика в планах, это тоже написано в спеке (§11.2)».

Критерий «сделано»: опубликована + 6 переупаковок разосланы. Мерить: просмотры, переходы на GitHub (реферер), регистрации в окно 72 ч, ответ «статья» в опросе «откуда узнали».

## Схема 3. Пост в тематический сабреддит / чужое сообщество

Предусловия: аккаунт с ненулевой историей (см. шаг 1), материал (статья/фича) уже существует.

Шаги:

1. **Прогрев (за 1–2 недели до):** 5–10 полезных комментариев в целевом сабреддите без единого упоминания Flora. Аккаунт с нулевой кармой и одной ссылкой = бан.
2. Прочитать правила сабреддита (у r/privacy и r/opensource жёсткие правила самопиара — обычно нужен флейр или день self-promo).
3. Формат поста — **текст со ссылкой внутри**, не голая ссылка. Первый абзац — ценность для читателя, не для тебя.
4. Дежурство в комментариях 2–3 часа.
5. Один сабреддит — не чаще 1 поста в 3–4 недели.

**Шаблон поста (r/opensource, EN):**

> **I'm building an ad-free, e2e-encrypted social network (AGPL) — here's the architecture**
>
> For the past N months I've been building Flora: a non-commercial social ecosystem — feed, communities, music, and DMs encrypted with a custom protocol (server stores ciphertext only). The recommendation algorithm is a public spec, not a black box.
>
> What I think might interest this sub: [2–3 инженерных пункта со ссылками на код/спеки]
>
> It's alpha, and here's an honest list of current limitations: [ссылка на SECURITY.md]. Happy to answer anything.

Критерий «сделано»: пост жив (не удалён модераторами), есть ответы на все комментарии. Мерить: переходы (Plausible, реферер), звёзды GitHub в окно 48 ч.

## Схема 4. Ньюсджек — реакция на инфоповод (правило 24 часов)

Предусловия: банк заготовок (ниже); инфоповод из классов GROWTH §5.7.

Триггеры (проверять утром за кофе, 10 мин: HN front page, TG-каналы новостей ИБ):

| Класс инфоповода | Заготовка |
| --- | --- |
| Законопроект о сканировании переписки / бэкдорах | «Почему E2E технически несовместим со сканированием — и что именно ломает бэкдор» + franking как модерация без сканирования (GROWTH Приложение A, сентябрь — Схема 11) |
| Утечка данных мессенджера/соцсети | «Какие данные *может* утечь платформа, если она хранит только шифртекст: разбор на нашей схеме БД» |
| Скандал с продажей данных / таргетингом | «Соцсеть без рекламы: какая архитектура делает продажу данных бессмысленной» |
| Очередное «алгоритм что-то скрывает» | «Вот полная спека нашего алгоритма рекомендаций. Целиком. Это возможно» |
| Блокировка/деплатформинг сообществ | «Право на выход: экспорт, открытый код и почему это должно быть нормой» |
| Отчёт о доле ботов / волна «мёртвого интернета» | «Соцсеть, в которой человек доказуем: как FPP делает ботоферму дорогой — без биометрии» (цифры отчёта → `C_identity` и экономика атак FPP §8) |
| Бан/скандал биометрического PoP (World ID и класс) | «Personhood без сдачи глаз: церемонии, web-of-trust и таблица „что мы не храним“ (FPP §9.1)» — разбор, почему централизованная биометрия и была риском by design |

Шаги: (1) убедиться, что понимаешь инцидент технически — 30–60 мин чтения первоисточников; (2) взять заготовку, вписать конкретику инцидента — 1–2 ч; (3) опубликовать в блог/TG + Mastodon-тред; (4) если инцидент крупный — сократить до комментария и разместить в обсуждениях (HN-тред инцидента, профильные чаты) как экспертную реплику, не как рекламу.

Тон (нормативно, GROWTH §10): разбор механики, ноль злорадства, обязательное честное «а вот это мы сами пока не решили». CTA — в конце и один.

Критерий «сделано»: опубликовано в первые 24 ч от волны, иначе — не публиковать (протухло). Мерить: переходы в окно 72 ч.

## Схема 5. Show HN (разовая, фаза 3)

Предусловия (жёсткие, GROWTH §9.1): SEC-1 закрыт; EN-лендинг жив; регистрация выдерживает всплеск; в день запуска ты свободен 6+ часов.

Шаги:

1. За неделю: перечитать свежие Show HN privacy-проектов, их топ-комментарии — собрать список из ~15 вероятных вопросов, написать ответы заранее.
2. За день: проверить прод (регистрация, инвайт-флоу, лендинг с мобильного); подготовить «тумблер паузы регистраций» (GROWTH §11).
3. Публикация: **вторник–четверг, 15:00–17:00 МСК** (утро восточного побережья США). Заголовок и первый комментарий — из GROWTH, Приложение A.
4. Первый комментарий от себя сразу после сабмита: стек, почему делаю, известные ограничения, что хочу от HN (feedback по протоколу).
5. Дежурство 6 часов: отвечать на всё, быстро, без защитной позиции. Технические придирки = подарок: «спасибо, завёл issue #N» + реально завести.
6. Не просить никого голосовать (бан-риск, и это анти-паттерн §10).
7. День после: разбор — что спрашивали чаще всего → FAQ на лендинг; выжимка «HN нас разобрал, вот что мы вынесли» → пост в TG/блог (сам разбор — тоже контент).

Критерий «сделано»: пост опубликован, на 100% комментариев отвечено в день запуска. Мерить: пик регистраций, D7 этой когорты отдельно, звёзды, issues от новых людей.

Если не взлетело (норма, GROWTH §11): повторный заход через 2–3 месяца с новым материалом — «Show HN: FRC-I, a pure-Rust image codec…» (демо `/playground/frc-i` — идеальный Show HN сам по себе), позже FRC-A и т.п.

## Схема 6. Питч микро-блогеру / подкасту

Предусловия: список из 10–15 адресатов (privacy/FOSS/dev, 1–20 тыс. аудитории; искать: гости других подкастов ниши, авторы каналов, куда репостят твои статьи).

Шаги: (1) неделю быть подписанным, понять формат и последние выпуски; (2) короткий питч — 5 предложений максимум, персонализация в первой строке обязательна; (3) нет ответа за неделю → один follow-up → стоп.

**Питч (EN/RU по адресату):**

> Привет! Слушаю/читаю [конкретный выпуск/пост — одно предложение, почему зашло].
>
> Я соло строю Flora — некоммерческую соцсеть с открытым кодом: свой E2E-протокол (сервер не может читать переписку), рекомендательный алгоритм как публичная спека, бэкенд целиком на Rust и своё семейство медиакодеков (фото-кодек уже в проде). Живая альфа, всё в открытую — включая известные дыры.
>
> Кажется, для [аудитории X] может быть интересная история: [один конкретный угол — например, «как соло-разработчик проектирует E2E-протокол» или «экономика соцсети без рекламы»]. Если любопытно — расскажу подробнее или дам ранний доступ.

Критерий «сделано»: 2 питча в неделю в фазах 2–3. Мерить: ответы, выходы материалов, реферальный трафик.

## Схема 7. Еженедельный операционный цикл (постоянный фон)

Понедельник, 45 мин:

1. Прогнать скрипт агрегатов (GROWTH §6.6) → строка в таблицу метрик (регистрации, WASU, k-фактор, D7, discovery-микс).
2. Ответить на вопрос «какая петля буксует?» одной фразой.
3. Выбрать 1–2 гипотезы из бэклога ICE (GROWTH §8.3) на неделю.

Ежедневно, 20–30 мин: триггеры ньюсджека (Схема 4, утро); ответы — комментарии, issues, личка деревень (вечер).

Пятница, 30 мин: build-in-public пост в TG (+зеркала): что сделано, одна цифра, один фейл или урок. Шаблон:

> **Неделя N во Flora.**
> Сделано: [1–3 пункта с одним скриншотом].
> Цифра недели: [метрика — честная, даже если маленькая].
> Грабли: [один фейл/урок — самая читаемая часть].
> Дальше: [один пункт].

Ежемесячно, +1 ч: GEO-замер (Приложение B GROWTH: 5–10 запросов к ассистентам, зафиксировать упоминания); ревизия ICE-бэклога; строка в `/open`-историю.

## Схема 8. Публикация каталога/листинга (IzzyOnDroid, AlternativeTo, awesome-списки)

Одна итерация = один каталог, ≤2 ч:

1. Прочитать требования каталога (у IzzyOnDroid — критерии к APK: размер, отсутствие проприетарных блобов; проверить FCM-зависимость release-сборки заранее).
2. Заполнить заявку/PR: описание — **дословно** формула позиционирования GROWTH §2.1 (консистентность = GEO, §5.6).
3. Скриншоты — те же 3–5, что в README (единый визуальный ряд).
4. Записать в таблицу «где мы уже есть» (завести в этом документе при первом листинге): каталог, дата, ссылка, статус.

Порядок: IzzyOnDroid → AlternativeTo → awesome-privacy → awesome-rust (FRC-I) → Wikidata. Один каталог в неделю в фазах 1–2 — достаточно.

## Схема 9. Онбординг внешнего контрибьютора (реактивная)

Триггер: первый issue/PR/вопрос от незнакомого человека.

1. Ответить ≤48 ч (жёсткая норма, GROWTH §7.3). Первый ответ: поблагодарить конкретно, дать контекст, показать следующий шаг.
2. PR приемлем, но с замечаниями → замечания как предложения с объяснением «почему» (ссылка на ARCHITECTURE/AGENTS-правила), не как приказы.
3. PR смержен → упомянуть в release notes; после 2–3 PR — позвать в обсуждение roadmap своего домена.
4. Конфликт вокруг CLA → один развёрнутый ответ по FAQ (GROWTH §7.4), ссылка, не спорить дальше.

## Реестр точек outreach

Норматив и критерии — [`GROWTH.md` §4.6](./GROWTH.md). Сюда — **только имена**. Новая строка = конкретная точка, прошедшая три критерия (ценности + взаимная польза + именованность).

**Статусы:** `кандидат` → `контакт` (написали) → `пилот` (сообщество/инвайты выданы) → `живая` (≥ критерий Схемы 1) | `отказ` | `пауза` (повтор только с новым поводом).

| Точка | Тип | Почему ценности | Что даём им | Угол / кому писать | Близость | Статус | Заметка |
| --- | --- | --- | --- | --- | --- | --- | --- |
| Партия «Яблоко» | политическая партия | защита прав и свобод, критика слежки и произвольного контроля; цифровая автономия совпадает с манифестом Flora | E2E-орг. коммуникация (сервер не читает); сообщество + лента без рекламы и чужого алгоритма; независимость от закрытых мессенджеров | Координатор IT / цифровой коммуникации / молодёжного крыла: инфраструктура для внутренних групп и сторонников, **без** аффилиации Flora с партией | холодная | кандидат | Первая институциональная точка реестра (2026-08-02) |
| Молодёжное «Яблоко» | молодёжное крыло партии | то же ценностное ядро, что у партии; ближе к цифровой повестке и низовым группам | пилот сообщества + E2E для координации ячеек/мероприятий; без зависимости от Telegram | Координатор / IT-волонтёр молодёжки: «инфраструктура для вас, не аффилиация» | холодная | кандидат | Отдельная точка от партии — проще зайти через цифру, чем в федеральный аппарат |
| | | | | | | | |
| | | | | | | | |
| | | | | | | | |

Дописать до ≥20 строк (Схема 0, Чт): микс типов — партии/НКО (гражданские, если критерий ценностей ок), privacy/FOSS-чаты, музыкальные микро-сцены, курсы/клубы, знакомые офлайн-группы. Пустые строки выше — место под следующие имена; не оставлять классы без имени.

Правило ведения: после каждого касания обновить статус и «Заметку» (дата + одна фраза). Раз в месяц вычищать вечные `кандидат` без движения → `пауза` или удалить, если критерии больше не держатся.

## Диспетчер: «у меня есть N часов, что делать?»

| Ситуация | Действие |
| --- | --- |
| 30 минут | Ответы: комментарии, issues, личка деревень. Либо 1 листинг из Схемы 8 |
| 2 часа | Кусок текущей статьи (Схема 2) или 3 касания по [Реестру точек](#реестр-точек-outreach) (Схема 1) или 2 питча (Схема 6) |
| Полдня | Инженерная задача фазы из ICE-бэклога (GROWTH §8.3, сверху вниз) |
| Горит инфоповод | Бросить всё → Схема 4 (правило 24 ч) |
| Август, окно свободно | Подготовка сентября → Схема 11 (franking-статья, заготовка, подписки на триггеры) |
| Ничего не горит и всё сделано | Следующая строка ICE-бэклога |
| Нет сил | Пятничный пост всё равно выпустить (ритм дороже объёма, GROWTH §11) — 15 мин по шаблону Схемы 7 |

Правило недели: **1 контент-единица + 3 касания деревень + 1 инженерная growth-задача.** Всё сверх — бонус. Меньше двух недель подряд — сократить scope фазы, не ритм.
