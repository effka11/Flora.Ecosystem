## Overview

FSA-C — поиск сообществ. Ищутся **карточки** (имя, описание, теги), не контент: посты приватных сообществ в индекс FSA-C не попадают по построению. Домен исследовательско-навигационный: «найти сообщество про X» и «найти то сообщество». Сильный глобальный приор размера/здоровья и заметная персонализация по темам FIRA.

---

## Architecture Position

**Владелец данных:** Social Content (`flora-content`). Индексируются карточки всех видимых сообществ; приватные сообщества присутствуют карточкой (найтись должны), но их контент — никогда. Фильтр `exclude_private` — продуктовое решение поверхности.

## Профиль (нормативный)

| Поле | Вес | positions | exact_boost |
|------|-----|-----------|-------------|
| `name` | 2.2 | ✓ | 0.8 |
| `description` | 0.8 | — | — |
| `tags` | 1.4 | — | — |

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| recency | Boost, half-life **60 дней**, вес 0.15 | живые сообщества выше заброшенных (по `last_activity_at`) |
| static_rank | 0.6 × size_rank | размер/здоровье — сильный глобальный приор качества |
| proximity | 0.1 | многословные названия |
| λ (персонализация) | **0.8** | темы UIP сильно улучшают попадание («фото» для фотографа — фото-сообщества) |
| expansion | prefix ≥ 2, fuzzy ≥ 4 | typeahead по названию |

## Документ

`CommunityDoc`: `id`, `name`, `description?`, `tags[]`, `topic_id?` (таксономия FIRA), `lang?`, `is_private`, `last_activity_at`, `size_rank ∈ [0,1]`.

Атрибуты: `topic`, `lang`, `private ∈ {true,false}`.  
Ключи аффинити: `community:{id}` (членство/интерес к конкретному сообществу), `topic:{topic_id}` (тема сообщества в UIP пользователя).

---

## API

`CommunitiesQuery`: `query`, `limit/offset`, `now`, `personalization (α)`, скоупы `topic_id?` / `lang?`, `exclude_private`.

`AffinitySnapshot` для FSA-C: UIP-темы → `topic:{id}`, членства и FIRA-C-сигналы → `community:{id}`.
