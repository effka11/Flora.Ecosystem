# Векторы ABI FGCE

Языконезависимые замороженные байты для C ABI v3. Каждый клиент — эталонный
TypeScript и любой будущий клиент — обязан воспроизводить эти байты и
декодировать ответы в те же значения.

| Файл | Направление | Содержание |
|------|-------------|------------|
| `encoding.json` | хост → wasm | логический вызов (`op` + `args`) и точные байты запроса |
| `decoding.json` | wasm → хост | байты ответа и декодированное значение |

`abi` в обоих файлах — значение, которое должен вернуть `fgce_abi_version()`.
Клиент проверяет его до первого запроса; несовпадение — ошибка, а не
предупреждение.

## Формат

```jsonc
// encoding.json
{
  "name": "begin 4x4",
  "op": "begin",                       // имя энкодера в клиенте
  "args": { "width": 4, "height": 4 }, // логические аргументы, типы протокола
  "requestHex": "070400000004000000"   // little-endian байты для fgce_submit
}
```

```jsonc
// decoding.json
{
  "name": "frame 2x2 with stride",
  "responseHex": "07...",              // байты из fgce_response_*
  "expect": {                          // семантическое значение; пиксели кадра — hex
    "kind": "frame",
    "width": 2, "height": 2, "stride": 8,
    "pixelsHex": "ff0000ff..."
  }
}
```

Типы протокола в `args` (`Verb`, `Edge`, `EntityKind`, …) используют ту же
JSON-форму, что и `bindings/ts/src/protocol.ts`. Буферы пикселей передаются
hex-строками, чтобы любой язык мог сравнить их без бинарного JSON.

## Правила

1. Вектор — **эталон**, а не пример: клиент, кодирующий тот же логический вызов,
   обязан получить ровно `requestHex`.
2. Векторы меняются только вместе с wire-форматом: `crates/fgce-wasm/src/wire.rs`,
   `docs/wasm-abi.md` и эталонный энкодер — в одном изменении. Нельзя подгонять
   ни энкодер под вектор, ни вектор под зелёный тест энкодера.
3. Новый opcode получает векторы до того, как его начнёт использовать первый
   неэталонный клиент.
4. Векторы создаются эталонной реализацией и регенерируются, а не правятся руками:

   ```sh
   FGCE_ABI_VECTORS_REGEN=1 npm test
   ```

   Запускайте это только при осознанном изменении wire-формата; дифф ревьюится
   как часть изменения протокола.
