# FRC-I — Flora Relativistic Codec — Image

**Status:** Frozen (битстрим v10; decoder compatibility v1..v10)
**Version:** 10.0 (reference encoder; wire v10 — §7.18, §11.6)
**Date:** 2026-07-21
**Family:** FRC — Flora Relativistic Codec (см. [`CODECS.md`](./CODECS.md))  
**Reference implementation:** `Products/FRC/crates/frc-i` (Rust, pure std)

---

## Overview

FRC-I — нативный фото-кодек экосистемы FLORA: один контейнер, два режима.

- **Lossless** — побайтно точное восстановление: обратимое цветовое преобразование
  YCoCg-R (либо identity-RGB, либо палитра до 256 цветов — выбор кодера),
  MED-предиктор, контексты по градиентам.
- **Lossy** — перцептивное сжатие: YCbCr (v1–v7) либо целочисленный YCoCg
  (v8+, §6.4), опциональный сабсэмплинг 4:2:0,
  направленная **intra-предикция блоков** (v3: моды DC/V/H/TM/D45/D135;
  v7.3a: +SMOOTH от реконструированных соседей; v7.3b: chroma-from-luma),
  DCT/ADST остатка (v7.4), перцептивное квантование с dead-zone и bounded
  trellis, run/level-кодирование, tile-local CDEF-класс post-filter (v7.5),
  согласованный center-sited 4:2:0 reconstruction (v7.6), скалярные матрицы
  квантования (v7.7), encoder-only RDOQ/dead-zone/chroma calibration (v7.8),
  bit-exact transform/trellis acceleration (v7.9a), целочисленный YCoCg
  с пошаговым квантованием плоскостей (v8, §6.4, §7.16) и per-root
  адаптивная квантизация delta-Q (v9, §7.17); v10 замораживает
  асимметричный reference AQ поверх неизменного v9 wire (§7.18).

Lossless и lossy v1–v6 используют **rANS** (12-битные вероятности,
статические таблицы per-tile/per-context); lossy v7+ использует адаптивный
**range coder** с фиксированными детерминированными prior. Оба слоя используют
**hybrid-uint токены** (алфавит 32, старшие биты больших значений уходят
сырыми). Изображение делится на **независимые тайлы 256×256** — единица
параллелизма (референсная реализация кодирует и декодирует тайлы в потоках
`std::thread::scope`; результат от числа потоков не зависит) и локализации
повреждений.

Этот документ **нормативен** и описывает замороженные битстримы FRC-I: v3
(бывш. FIC v3), v4 (v3 + деблокинг-фильтр §7.6), v5 (адаптивные
суперблоки 16×16 §7.7), v6 (блок метаданных §2.5: ICC-профиль), v7
(адаптивная lossy-линия §3.5, §7.8–§7.15), v8 (целочисленный YCoCg §6.4,
дерево/энтропия как у v7 — §7.16), v9 (per-root delta-Q §7.17) и v10
(тот же wire с замороженным асимметричным reference AQ §7.18).
Исторические отличия FIC v1/v2 сведены в §7.5 и §10. Все версии v1..v10
заморожены golden-векторами (`Products/FRC/crates/frc-i/tests/data/`):
декодер обязан читать любой корректный поток любой выпущенной версии всегда.

### Competitive snapshot

Основной полигон с линии v9 — **перцептивный**: SSIMULACRA2 и butteraugli
(нативные бинарники libjxl) плюс PSNR(RGB/Y), BD-rate Bjøntegaard по кадрам;
харнессы `Tools/frc-i-compete/run_honest_jxl.py` (vs нативный cjxl/djxl)
и `run_ab_frc.py` (A/B версий FRC-I). Историческая PSNR-таблица v8
(`run_compete.py`, Kodak 24) сохранена для преемственности:

| Кодек | PSNR BD-rate FRC-I v8 vs X | Encode mid-q |
| --- | ---: | ---: |
| **FRC-I v8** | — | **11.8 Мп/с** |
| FRC-I v7.9a (frozen) | **−2.1%** | 11.8 Мп/с |
| JPEG | **≈−29%** | ~9.2 Мп/с |
| JPEG XL | **≈−12%** | ~5.2 Мп/с |

| FRC-I v5 (legacy) | **≈−35%** | ~23 Мп/с |

**v9 vs v8** (per-root delta-Q §7.17, полигон §11.5; отрицательное =
v9 лучше):

| Корпус | SSIMULACRA2 | butteraugli | PSNR(RGB) | Encode |
| --- | ---: | ---: | ---: | ---: |
| Kodak 24 (768×512) | **−5.2%** | **−4.0%** | +1.8% | без изменения |
| picsum 12 (~1.7 Мп) | **−4.4%** | **−3.1%** | +1.5% | без изменения |

Кратко: v9 = сигналируемая per-root адаптивная квантизация поверх
неизменного дерева/энтропии v8: биты уходят из маскирующих текстур в
гладкие зоны и края. Перцептивные метрики (родная целевая функция
JXL/AVIF) выигрывают ~4–5% BD-rate за счёт контролируемой PSNR-цены;
скорость кодера сохранена (AQ-эвристика — один MAD-проход по источнику).

**v10 vs v9** (асимметричный reference AQ §7.18/§11.6; отрицательное =
v10 лучше):

| Корпус | SSIMULACRA2 | butteraugli | PSNR(RGB) | Размер лестницы |
| --- | ---: | ---: | ---: | ---: |
| Kodak 24 (768×512) | **−0.64%** | **−0.34%** | +0.60% | +0.54% |
| picsum 12 (~1.7 Мп) | **−0.44%** | **−0.23%** | +0.47% | +0.24% |

v10 сохраняет декодер v9 и меняет только замороженные решения кодера:
уточнение слабомаскирующих корней немного сильнее огрубления текстур.
Скорость сохранена (парный чередующийся q70-прогон — без измеримого
изменения, §11.6).

PSNR-цель «коридор 0…+10% от AVIF» остаётся исторической для v8;
перцептивный зазор к AVIF/JXL — §11.5.

### Design rationale (кратко)

| Решение | Мотив |
| --- | --- |
| rANS (v1–v6) и adaptive range coder (lossy v7) вместо Huffman | Дробные биты на символ; v7 не несёт таблицы частот DCT-секций и адаптируется внутри независимого тайла |
| Малый алфавит токенов + сырые биты | компактные таблицы частот, дешёвая адаптация per-tile; старшие биты шумов несжимаемы — не тратим на них моделирование |
| Статические таблицы v1–v6; фиксированные prior v7 | Тайлы декодируются независимо; v7 получает локальную адаптацию без сериализации CDF |
| Независимые тайлы 256×256 | параллельный encode/decode без изменения формата; локализация повреждений |
| Intra-предикция от реконструкции (модель VP8) | межблочная корреляция уходит в предсказание до DCT: −4…−16% на фотоклассах при равном/лучшем PSNR; декодеру — один предсказатель на блок |
| Диагональные моды D45/D135 (v3) | направленные текстуры: ещё −3.3% на фото при том же наборе контекстов; кодеру +2 кандидата RD, декодеру — две таблицы копий по диагонали |
| Dead-zone квантование AC (свобода кодера) | −7..12% размера за ≤0.1 dB: слабые изолированные коэффициенты не окупают своих run/level-токенов |
| Выбор инструментов на кодере (палитра/identity/raw/моды) | Wire допускает любой корректный выбор; решения frozen reference v7.9a дополнительно защищены encode-golden |
| Чистый std, без `unsafe`, без C-зависимостей | аудируемость, WASM-декодер для Apps/Web из того же исходника, детерминизм |
| Захардкоженные константы DCT/цвета (без libm) | бит-в-бит одинаковый результат на любой платформе — golden-вектора законны |
| Lossless-схема неизменна с v1 | bias-коррекция LOCO-I и run-режим были реализованы и измерены: статические rANS-таблицы уже поглощают смещение остатков и почти бесплатно кодируют нули — обе добавки ухудшали корпус, отклонены по цифрам |
| AC-контексты по nnz соседей — отклонены | реализованы и измерены при разработке v3 (3 бакета × 4 контекста, модель JXL/AV1): +5..8% на корпусе — цена дополнительных частотных таблиц тайла выше выигрыша от условности; приёмы кодеков с адаптивными вероятностями не переносятся на статические таблицы |

## Goals & Non-Goals

**Goals:**

- Заменить PNG (lossless) и JPEG (lossy) во внутренних пайплайнах Flora с
  измеримым выигрышем размера при равном качестве.
- Гарантированный худший случай: несжимаемые данные ≤ исходника + ~0.4%.
- Декодер, безопасный для недоверенного ввода (см. §9): без паник, с лимитами.
- База для FRC-V (видео): плоскостные кодеры переиспользуются в intra-кадрах.
- **Линии v7 (§11.3) и v8 (§11.4):** приблизить плотность к AVIF на реальных
  фото, сохранив encode ≥ 11 Мп/с (v8; у v7 было ≥ 10) и кратно более
  простой декодер.
- **Линия v9 (§11.5):** перейти на перцептивную целевую функцию
  (SSIMULACRA2 / butteraugli) без потери скорости: encode-бюджет жёсткий —
  не ниже v8 (скоростной потолок достигнут, §11.4).
- **Линия v10 (§11.6):** улучшить обе перцептивные метрики поверх frozen v9
  без нового decoder tool и без измеримого падения encode speed.

Итог v7 freeze-gate: vs AVIF **+25.6%**, encode **12.4 Мп/с**. Линия v8
взяла integer YCoCg (~−2.1% vs v7) без rect, с бюджетом encode **≥ 11 Мп/с**.
Линия v9 добавила per-root delta-Q: S2 **−5.2%** / butteraugli **−4.0%**
BD-rate vs v8 (Kodak) при неизменной скорости.
Линия v10 перекалибровала reference AQ: ещё **−0.64% / −0.34%** vs v9
на Kodak и **−0.44% / −0.23%** на picsum, wire/decoder не изменены.


**Non-Goals (текущая линия):**

- HDR / битовая глубина >8, EXIF (для EXIF зарезервирован тип чанка
  метаданных §2.5; ICC поддержан с v6). Битность 10/12 — после v7.
- Анимация (мультикадровость — контейнер FRC-V).
- Прогрессивная развёртка (после v7).
- Победа над AVIF/JXL «любой ценой» по одной таблице BD-rate: скорость
  encode и простота декодера — часть целевой функции, их не сдаём
  (бюджеты в §11.3).

## 1. Терминология и соглашения

- Целые числа — **little-endian**.
- Битовые потоки («сырые биты», упаковка таблиц) — **MSB-first** внутри байта,
  последний байт дополняется нулями.
- «Плоскость» — прямоугольный массив отсчётов одной компоненты, row-major.
- `bitlen(v)` — позиция старшего единичного бита (`bitlen(1)=1`, `bitlen(255)=8`).
- Диапазон плоскости `[lo, hi]` и «виртуальный сосед» `mid`:

| Плоскость | lo | hi | mid |
| --- | --- | --- | --- |
| Y (lossless), R/G/B (identity), альфа, Y/Cb/Cr (lossy) | 0 | 255 | 128 |
| Co, Cg (YCoCg-R) | −255 | 255 | 0 |
| Индексы палитры из `n` записей | 0 | n−1 | n/2 (целочисленно) |

## 2. Контейнер

```text
[Header 20 B] [Metadata block?] [Palette block?] [TileTable: n_tiles x u32] [TilePayload x n_tiles]
```

Поток обязан заканчиваться ровно на последнем тайле: лишние байты — ошибка.

### 2.1. Header (20 байт)

| Смещение | Размер | Поле | Значение |
| --- | --- | --- | --- |
| 0 | 4 | magic | `8F 46 52 49` (`\x8F` + `"FRI"`) |
| 4 | 1 | version | `1..=10`; иное → `UnsupportedVersion` |
| 5 | 1 | flags | см. ниже; неизвестные биты → отказ |
| 6 | 4 | width | u32, 1..=32768 |
| 10 | 4 | height | u32, 1..=32768 |
| 14 | 1 | bit_depth | `8` |
| 15 | 1 | quality | lossy: 1..=100; lossless: 0 |
| 16 | 1 | tile_shift | `8` (тайл 256) |
| 17 | 3 | reserved | нули; иное → отказ |

Флаги (бит 0 — младший):

| Бит | Имя | Семантика |
| --- | --- | --- |
| 0 | `LOSSLESS` | режим без потерь |
| 1 | `ALPHA` | выход декодера RGBA; есть альфа-плоскость (или альфа в палитре) |
| 2 | `CHROMA420` | сабсэмплинг цветоразностей (только lossy) |
| 3 | `IDENTITY` | lossless без цветового преобразования (плоскости R, G, B) |
| 4 | `PALETTE` | палитровый lossless: блок палитры + одна плоскость индексов |
| 5 | `DEBLOCK` | деблокинг-фильтр на выходе декодера (§7.6); только v4+, только lossy |
| 6 | `METADATA` | блок метаданных после заголовка (§2.5); только v6+, любой режим |
| 7 | reserved | обязан быть 0 |

Комбинаторика (декодер обязан проверить): `IDENTITY`/`PALETTE` только при
`LOSSLESS`; `IDENTITY` и `PALETTE` взаимоисключающи; `CHROMA420` несовместим с
`LOSSLESS`; `DEBLOCK` несовместим с `LOSSLESS` и требует `version >= 4`
(в v1–v3 бит 5 — неизвестный флаг → отказ); `METADATA` требует `version >= 6`
(в v1–v5 бит 6 — неизвестный флаг → отказ); `quality` согласован с режимом.

### 2.2. Palette block (только при `PALETTE`)

```text
u8 count_minus_1;  // записей = count_minus_1 + 1 (1..=256)
entries[count]     // RGB (3 B) или RGBA (4 B при флаге ALPHA), порядок кодера
```

Референсный кодер сортирует записи по яркости BT.601 (перцептивно близкие
цвета получают соседние индексы — MED-предсказание индексов начинает работать),
но порядок — свобода кодера, декодер трактует список как данность.

### 2.3. Тайлы

Сетка тайлов 256×256 обходится **row-major**; краевые тайлы усечены до границ
изображения. `TileTable` — длины payload'ов тайлов (u32 каждая); сумма длин
обязана совпасть с остатком потока байт-в-байт.

### 2.4. Состав payload тайла

Секции строго в порядке:

| Режим | Секции |
| --- | --- |
| `PALETTE` | 1 предиктивная (плоскость индексов) |
| `LOSSLESS` планарный | 3 предиктивные (Y, Co, Cg — либо R, G, B при `IDENTITY`) [+ альфа предиктивная] |
| lossy | 3 DCT (Y, Cb, Cr; в v8 — Y, Co, Cg §6.4) [+ альфа предиктивная] |

Альфа-плоскость кодируется **без потерь всегда**, в полном разрешении.
После последней секции в payload тайла не должно оставаться байт.

### 2.5. Metadata block (v6+, только при `METADATA`)

Расположен **сразу после заголовка**, до блока палитры. Метаданные не влияют
на декодирование пикселей.

```text
u32 total_len;             // длина остатка блока; 1..=8 МиБ, иное → отказ
chunks[..]                 // TLV-чанки до исчерпания total_len (ровно)
  u8  type;                // тип чанка
  u32 len;                 // длина данных
  data[len]
```

Типы чанков:

| type | Содержимое |
| --- | --- |
| 1 | ICC-профиль (байты профиля как есть); повторный чанк → отказ, пустой → отказ |
| прочие | зарезервированы (EXIF и др.); декодер обязан **пропустить** незнакомый чанк |

Пропуск незнакомых типов — единственное расширяемое место формата: новые
виды метаданных добавляются без смены версии, потому что не влияют на
пиксели. Обрыв чанка за границей `total_len` и `total_len` вне лимита —
порча потока. Потолок 8 МиБ — DoS-защита декодера (аллокация до проверки
тела недопустима).

## 3. Энтропийный слой

### 3.1. Hybrid-uint токены

Беззнаковое `v < 2^20` → пара (символ алфавита 32, сырые биты):

```text
v < 16:  sym = v, сырых бит нет
v >= 16: n = bitlen(v) (5..=20); sym = 16 + (n - 5); raw = v - 2^(n-1), n-1 бит
```

Знаковые значения предварительно отображаются зигзагом:
`m(v) = (v << 1) XOR (v >> 31)` (арифметический сдвиг): 0,−1,1,−2,2 → 0,1,2,3,4.

### 3.2. rANS

32-битное состояние, нижняя граница `L = 2^23`, побайтовая ренормализация,
точность вероятностей 12 бит (сумма частот таблицы = 4096).

Провод: `[u32 LE: начальное состояние для чтения][байты потока]`.

Декодирование символа по таблице (freq[s], cum[s]):

```text
slot = x & 4095
s: cum[s] <= slot < cum[s+1]
x = freq[s] * (x >> 12) + slot - cum[s]
while x < L: x = (x << 8) | next_byte   // нет байта -> Corrupt
```

Кодер (справочно): символы кодируются в обратном порядке от состояния `L`,
`x_max = ((L >> 12) << 8) * freq`; итоговый буфер разворачивается.

**Строгость:** после последнего символа секции состояние обязано равняться
ровно `L`, все байты потока — потреблены. Иное — повреждение.

### 3.3. Таблицы частот (разреженная сериализация)

Для каждого контекста секции:

```text
u8 first_sym; u8 n_syms (1..=32, first+n <= 32);
ceil(n_syms * 12 / 8) байт: n_syms значений (freq-1) по 12 бит, MSB-first
```

Сумма частот обязана равняться 4096 (все частоты диапазона >= 1). Контекст,
не встречающийся в данных, сериализуется вырожденно: `first=0, n=1, freq=4096`.

### 3.4. Поток сырых бит

Все сырые биты секции (биты токенов, знаки уровней) пишутся подряд MSB-first
в отдельный поток. Декодер обязан потребить все его байты (частичный последний
байт дочитывается нулями-паддингом).

### 3.5. Адаптивный range-кодер (v7)

Вместо статических rANS-таблиц (§3.2–3.3) lossy-секции v7 используют
**FIFO range-кодер** (32-бит, перенос через cache/pending-FF, схема LZMA)
и **адаптивные частотные модели**. Порядок декодирования = порядку
кодирования → модель обновляется после каждого символа одинаково на
обеих сторонах. Всё целочисленно (контракт §9).

Интервал: `range_init = 0xFF000000`, ренормализация при `range < 2^24`.
Первый байт потока всегда 0 (лаг-байт); финализация — 5 сдвигов. Число
байт на выходе кодера равно числу байт, потребляемых декодером той же
последовательности; обрыв — `Corrupt`.

Модель алфавита `n ∈ {2, 4, 15, 22, 32}` (SPLIT/EOB / TX/CDEF / MODE /
RUN / прочие токены): счётчики `u16`,
инкремент затухает `256 → 128 → 64 → 32` по числу обновлений; при
`total ≥ 2^13` — полуделение с полом 1. Prior зависит от вида контекста
(run: высокие 0..2; level: высокие 0..1; split: уклон к WHOLE; CDEF:
уклон к OFF; EOB: равновесный). В v7 EOB — отдельный бинарный флаг,
а не символ RUN.

Банк моделей: 82 контекста (§7.8) с иерархическим прогревом
(родитель группы → тёплый старт детальной модели) и order-1 бакетами
(4 шт., только для алфавитов ≥ 16). Таблицы в поток **не пишутся**.

## 4. Секции

### 4.1. Предиктивная секция (lossless-плоскости)

```text
u8 mode;                        // 0 coded, 1 raw; иное -> Corrupt
mode 0: [FreqTable x 8][u32 token_len][u32 raw_len][token bytes][raw bytes]
mode 1: [w*h отсчётов по raw_bits(range) бит, row-major, MSB-first]
```

`raw_bits(range) = max(1, bitlen(hi - lo))`: 8 для 0..=255, 9 для ±255,
`bitlen(n-1)` для палитры. Значение отсчёта = прочитанное + `lo`, кламп в
`[lo, hi]`. Режим 1 — потолок худшего случая; кодер выбирает меньшую форму.

### 4.2. DCT-секция (lossy-плоскости)

v1–v6 (статический rANS):

```text
[FreqTable x n_ctx][u32 token_len][u32 raw_len][token bytes][raw bytes]
```

`n_ctx`: **5** в v1 (§7.5), **6** в v2/v3/v4, **7** в v5/v6 (§7.7, CTX_SPLIT).

v7+ (адаптивная энтропия, §3.5) — таблиц нет:

```text
[u32 token_len][u32 raw_len][arith bytes][raw bytes]
```

Банк моделей общий для всех DCT-плоскостей тайла (Y→Cb→Cr): хрома
стартует тёплой. Байта режима нет. Контейнер секции одинаков в v7..v10;
v9/v10 добавляют в символьный поток по одному delta-Q-символу перед каждым
корнем 32×32 (§7.17–§7.18).

## 5. Lossless-кодирование плоскости

Схема идентична во всех версиях формата (см. rationale: добавки JPEG-LS
отклонены по измерениям). Растровый обход. Соседи текущего отсчёта
(`W` слева, `N` сверху, `NW` по диагонали):

```text
(x=0, y=0): W = N = NW = mid
(x=0, y>0): W = N = NW = P[0, y-1]
(x>0, y=0): W = N = NW = P[x-1, 0]
иначе:      W = P[x-1,y], N = P[x,y-1], NW = P[x-1,y-1]
```

Предсказание MED (LOCO-I):

```text
если NW >= max(W,N): pred = min(W,N)
иначе если NW <= min(W,N): pred = max(W,N)
иначе: pred = W + N - NW
```

Контекст — активность градиентов `g = |N-NW| + |NW-W|`, бакеты
`{0},{1},{2},{3..4},{5..8},{9..16},{17..32},{>32}` → контексты 0..7.

Кодируется `zigzag(value - pred)` hybrid-uint токеном в контексте, сырые биты —
в raw-поток. Реконструкция: `value = clamp(pred + residual, lo, hi)` — кламп
обязателен (детерминированное поведение на повреждённых потоках).

## 6. Цвет

### 6.1. YCoCg-R (lossless, обратимое)

```text
прямое:  Co = R - B;  t = B + (Co >> 1);  Cg = G - t;  Y = t + (Cg >> 1)
обратное: t = Y - (Cg >> 1);  G = Cg + t;  B = t - (Co >> 1);  R = B + Co
```

Сдвиги арифметические. Y ∈ 0..=255, Co/Cg ∈ −255..=255. После обратного
преобразования каналы клампятся в 0..=255 (значимо только для повреждённых
потоков — валидные обратимы точно).

### 6.2. YCbCr BT.601 full-range (lossy, фиксированная точка 16.16)

`HALF = 32768`, сдвиг 16. Константы (целые, ×65536):

```text
Y  = ( 19595 R + 38470 G +  7471 B + HALF) >> 16
Cb = ((-11059 R - 21709 G + 32768 B + HALF) >> 16) + 128
Cr = (( 32768 R - 27439 G -  5329 B + HALF) >> 16) + 128
R = Y + (( 91881 (Cr-128)                 + HALF) >> 16)
G = Y + ((-22553 (Cb-128) - 46802 (Cr-128) + HALF) >> 16)
B = Y + ((116130 (Cb-128)                 + HALF) >> 16)
```

Все компоненты клампятся в 0..=255. Плавающая точка запрещена — детерминизм.

### 6.3. Сабсэмплинг 4:2:0

Плоскости Cb/Cr тайла имеют размер `ceil(tw/2) × ceil(th/2)` и вычисляются
**в границах тайла** (тайлы полностью независимы).

Даунсэмплинг: среднее 2×2 с репликацией края при нечётных размерах,
округление `(sum + 2) >> 2`.

Апсэмплинг v1–v6 (билинейный, co-sited с левым верхним отсчётом):

```text
fx = x/2; nx = (x нечётный) ? min(fx+1, cw-1) : fx   (аналогично fy/ny)
out[x,y] = (c[fy,fx] + c[fy,nx] + c[ny,fx] + c[ny,nx] + 2) >> 2
```

В v7 downsample остаётся тем же средним 2×2, но отсчёт считается
**center-sited** в координате `(2cx+1/2, 2cy+1/2)`. Для каждой оси полного
разрешения (`p`, длина chroma `n`, `k=floor(p/2)`) decoder выбирает:

```text
p чётный: i0=max(k-1,0), i1=k,          w0=1, w1=3
p нечётный: i0=k,        i1=min(k+1,n-1), w0=3, w1=1
```

Затем separable bilinear:

```text
top    = wx0*c[y0,x0] + wx1*c[y0,x1]
bottom = wx0*c[y1,x0] + wx1*c[y1,x1]
out[x,y] = (wy0*top + wy1*bottom + 8) >> 4
```

Индексы клампятся внутри плоскости **тайла**, поэтому независимость тайлов
сохраняется. Эта формула устраняет полупиксельный фазовый сдвиг между
средним 2×2 encoder и историческим co-sited decoder.

### 6.4. Целочисленный YCoCg (lossy, v8)

Битстрим v8 заменяет BT.601 (§6.2) масштабированным целочисленным YCoCg
(сдвиги арифметические, floor; все компоненты в 0..=255 по построению):

```text
Y  = (R + 2G + B + 2) >> 2
Co = ((R − B) >> 1) + 128
Cg = ((2G − R − B) >> 2) + 128

co = Co − 128; cg = Cg − 128
R = Y + co − cg
G = Y + cg
B = Y − co − cg
```

Обратный ход клампится в 0..=255 (ошибки квантования могут выводить за
диапазон). Преобразование не полностью обратимо (масштабирование хромы
и floor теряют младшие биты): максимальная ошибка восстановления RGB без
квантования равна 1, проверено sampled/exhaustive-перебором. Сабсэмплинг
4:2:0 применяется к Co/Cg по правилам §6.3 (center-sited реконструкция
v7). Мотив и измерения — §11.3 (п. v7.9b) и §11.4.

## 7. Lossy-кодирование плоскости (intra-предикция + transform остатка)

### 7.1. Блочная структура и intra-предикция

Плоскость обходится блоками 8×8 row-major; краевые блоки добираются
**репликацией края**. Каждая плоскость (Y, Cb, Cr — в 4:2:0 хрома на своём
разрешении) предсказывается **от собственной реконструкции** внутри тайла.

Граница блока `(bx, by)` из реконструированной плоскости (`px = 8bx`,
`py = 8by`; недоступные соседи замещаются 128; координаты клампятся в
валидную область плоскости `w × h`). Верхняя строка расширена вправо на
8 отсчётов (для D45; над правым краем реплицируется последний столбец):

```text
above[i]  = py > 0 ? R[py-1, min(px+i, w-1)] : 128     (i = 0..15)
left[j]   = px > 0 ? R[min(py+j, h-1), px-1] : 128     (j = 0..7)
corner    = px > 0 && py > 0 ? R[py-1, px-1] : 128
```

Моды предсказания (значения фиксированы форматом; кодируются символом
0..=5, см. §7.3):

| Сим | Мода | pred[j][i] |
| --- | --- | --- |
| 0 | DC | `(sum(above[0..8]) + sum(left) + 8) >> 4` для всех отсчётов |
| 1 | V | `above[i]` |
| 2 | H | `left[j]` |
| 3 | TM | `clamp(left[j] + above[i] - corner, 0, 255)` |
| 4 | D45 | вниз-влево: `s = i + j`; `(above[s] + 2·above[s+1] + above[min(s+2, 15)] + 2) >> 2` |
| 5 | D135 | вниз-вправо: см. опорный ряд ниже |

D135 использует опорный ряд из 17 отсчётов вдоль границы
(левый столбец снизу вверх, угол, верхняя строка):

```text
line[j] = left[7-j]      (j = 0..7)
line[8] = corner
line[8+1+i] = above[i]   (i = 0..7)
pred[j][i] = (line[d-1] + 2·line[d] + line[d+1] + 2) >> 2,  d = 8 + i - j
```

Обе диагонали сглажены 3-отводным фильтром `(1,2,1)/4` — подавляет
ступенчатость предсказания от шумной границы.

В v5 те же шесть мод применяются и к суперблокам 16×16 (§7.7) — все
формулы масштабируются заменой 8→16 (граница `above[0..32]`, `left[0..16]`,
DC-нормировка `(sum + 16) >> 5`, D135-ряд из 33 отсчётов, `d = 16 + i - j`).

Остаток `orig - pred` преобразуется ортонормированным DCT-II (базис идентичен
ITU-T T.81); центрирования (−128) начиная с v2 нет — его роль выполняет
предсказание.

Базисные константы зафиксированы литералами f32 (арифметика f32, без FMA):

```text
A0 = 0.353_553_39         C1 = 0.490_392_64      C2 = 0.461_939_77
C3 = 0.415_734_8          C5 = 0.277_785_1       C6 = 0.191_341_72
C7 = 0.097_545_16
BASIS[u][n] = c(u) * cos((2n+1) u pi / 16), c(0)=A0, c(u>0)=C(u)
```

### 7.2. Квантование и реконструкция

Для v1–v6 базовые матрицы — ITU-T T.81 Annex K.1 (люма) / K.2 (хрома).
Для v7 нормативны скалярные матрицы §7.15. Масштаб качества во всех версиях —
классическое отображение IJG:

```text
scale = q < 50 ? 5000/q : 200 - 2q
Q[i] = clamp((base[i] * scale + 50) / 100, 1, 255)
```

**Деквантование (нормативно):** `coef = c * Q[i]` (f32). Квантование —
свобода кодера: формат фиксирует только смысл `c` как множителя шага `Q[i]`.
Референсный кодер (информативно) использует dead-zone: DC округляется
классически (`+0.5`, half-away-from-zero), AC — со смещением `+0.40` к нулю
(`c = sign(t) · floor(|t| + 0.40)`, `t = coef / Q[i]`): слабые изолированные
коэффициенты обнуляются, экономя run/level-токены при потере ≤ 0.1 dB.

Реконструкция отсчёта: `clamp(round(idct + pred), 0, 255)` — она же источник
границ для следующих блоков, поэтому кодер обязан вести реконструкцию тем же
путём, что декодер.

### 7.3. Кодирование блока

Контексты DCT-секции v2/v3: `0` — DC; `1`/`2` — run в низкой/высокой зоне;
`3`/`4` — level в низкой/высокой зоне; `5` — мода предсказания.
Низкая зона — позиции зигзага ≤ 15. Зигзаг — стандартный порядок JPEG.

Порядок токенов блока: **мода → DC → AC**.

- **Мода:** символ 0..=5 в контексте 5 (сырых бит нет); символ ≥ 6 → `Corrupt`.
- **DC:** `zigzag(dc)` hybrid-uint в контексте 0 — кодируется **напрямую**,
  без цепочки: межблочную корреляцию DC уже поглотило предсказание.
- **AC:** по зигзагу с позиции 1: пары «run нулей → level»:
  - run-токен в контексте зоны позиции **начала** пробега; символ `31` = EOB
    (пробеги ≤ 62 занимают символы ≤ 17 — коллизий нет);
  - level: hybrid-uint от `|c| - 1` в контексте зоны позиции коэффициента;
    знак — 1 сырой бит (1 = отрицательный);
  - если последний ненулевой коэффициент стоит на позиции 63, EOB **не пишется**.

Декодер обязан считать позицию: выход за 63 → `Corrupt`.

### 7.4. Выбор моды кодером (информативно)

Референсный кодер считает для каждой из шести мод DCT+квантование остатка и
минимизирует полную RD-стоимость `D + λ·R`: `D` — SSE ошибки квантования в
DCT-домене (базис ортонормирован — равно SSE в пикселях), `R` — оценка
битовой стоимости токенов (константа за ненулевой коэффициент + длина
мантиссы), `λ = 0.85 · qstep²` от среднего шага матрицы (модель H.264;
плато решений широкое — калибровка 0.05..10 даёт одинаковый выбор).
При равенстве — младший символ. Формат выбор не ограничивает: любой
сигнализированный набор мод валиден.

### 7.5. Отличия битстримов v2 и v1 (декодируются всегда)

**v2:**

- Моды предсказания — только 0..=3 (DC/V/H/TM); символ ≥ 4 → `Corrupt`.
  Расширение верхней строки не используется (`above[8..16]` не читается).

**v1:**

- Intra-предикции нет: блок центрируется константой 128
  (эквивалент `pred[j][i] = 128`), моды не сигналятся.
- Контекстов 5 (без контекста моды), порядок токенов блока: DC → AC.
- **DC — цепочкой:** `zigzag(dc - prev_dc)`, где `prev_dc` — DC предыдущего
  блока плоскости тайла (init 0).

### 7.6. Деблокинг-фильтр (v4, флаг `DEBLOCK`)

Пост-фильтр **вне петли предсказания**: intra-предикция (§7.1) работает с
нефильтрованной реконструкцией — байты тайлов v4 идентичны v3, меняется
только заголовок. Фильтр применяется декодером к готовой плоскости тайла
(Y, Cb, Cr; хрома — в собственном разрешении, до апсэмплинга §6.3);
тайлы остаются независимыми.

На каждой границе блоков 8×8 (вертикальной и горизонтальной) пары
`p1 p0 | q0 q1` поперёк ребра (за краем плоскости сосед реплицируется):

```text
T = clamp(Q[0] / 2, 2, 24)          // Q[0] — DC-шаг матрицы плоскости
фильтровать, если |p0-q0| < T  и  |p1-p0| <= T/2  и  |q1-q0| <= T/2
d   = clamp((3(q0-p0) + (p1-q1) + 4) >> 3, -T, T)
p0' = clamp(p0 + d, 0, 255);  q0' = clamp(q0 - d, 0, 255)
```

Порядок нормативен: сначала все вертикальные рёбра плоскости, затем все
горизонтальные (вторые читают результат первых). Целочисленная арифметика.
Условие на соседей (`T/2`) отличает ступень квантования от настоящей детали:
контрастные рёбра не размываются. Кодер выставляет флаг при `quality < 45`
(свобода кодера); декодер обязан фильтровать всегда, когда флаг стоит.
На корпусе q=30: +0.40 dB (photo) / +0.44 dB (portrait) при нулевой цене
в байтах; шум не трогается (рёбра выше порога). В v5 фильтр действует на
той же фиксированной сетке 8×8 независимо от разбиения на суперблоки.

### 7.7. Адаптивные суперблоки 16×16 (v5)

Плоскость обходится **суперблоками 16×16** row-major. На каждый суперблок
сигналится split-решение — символ в новом контексте `6` (итого контекстов
DCT-секции v5 — семь):

- **`0` (целиком):** одна мода (§7.1, масштаб 16) + DCT 16×16 остатка.
- **`1` (расщепление):** четыре блока 8×8 row-major, каждый кодируется
  ровно как в v3 (§7.1–7.3). Подблоки, полностью лежащие вне плоскости
  (правый/нижний край), **не кодируются**.
- символ ≥ 2 → `Corrupt`.

Кодирование суперблока целиком:

- **DCT 16×16** — ортонормированный DCT-II; базис из литералов
  `cos(k·π/32)` (k = 0..=16, f32) через симметрии косинуса,
  `c(0) = 1/4`, `c(u>0) = √(2/16)`.
- **Матрица квантования** (нормативно): коэффициент `(u, v)` наследует шаг
  своей пространственной частоты — `Q16[u][v] = Q[u/2][v/2]`. Базис
  ортонормирован, поэтому одинаковый шаг даёт одинаковую пиксельную ошибку
  независимо от размера блока: качество зон 16×16 и 8×8 согласовано.
  (Удвоение шага измерено: −50% размера, но −1.9 dB на фото — отклонено.)
- **Зигзаг 16×16** — то же серпантинное правило, что и 8×8
  (начало: 0, 1, 16, 32, …). Низкая зона — позиции скана ≤ 63 (та же
  четверть скана). Run-токены до 254 не коллидируют с EOB (символ 31:
  пробеги кодируются битовой длиной, максимум — символ 19).
- Порядок токенов: **split → мода → DC → AC**; правила DC/AC — §7.3
  с заменой 63 → 255 в проверке позиции.

Реконструкция и репликация краёв — как у 8×8 (масштаб 16). Выбор
целиком/расщепление — свобода кодера (референсный: RD-сравнение обоих
вариантов с общим λ плоскости; проба расщепления идёт по реконструкции
с откатом — байты детерминированы). Гладкие зоны (небо, кожа, фон)
получают одну моду и один DC вместо четырёх — главный резерв плотности v5:
на корпусе q=75 портрет −18.5% при −0.37 dB, фото −1.2% при −0.07 dB;
графика/шум не регрессируют (RD выбирает расщепление).

### 7.8. Контексты и кодирование блоков v7

Энтропия — адаптивный range-кодер (§3.5); дерево блоков — §7.9.
Число контекстов DCT-секции: **82** (не сериализуется):

| Диапазон | Назначение |
| --- | --- |
| 0 | SPLIT узла 16×16 (алфавит 2) |
| 1 | MODE (алфавит 15; §7.10–7.11) |
| 2..5 | DC (4 бакета; референс использует только базу — условность по prev_dc отклонена A/B) |
| 6..29 | RUN (алфавит 22): 6 бакетов позиции зигзага × 4 nnz-бакета предыдущего блока |
| 30..53 | LEVEL: 6 бакетов позиции × 4 бакета магнитуды предыдущего уровня |
| 54..77 | EOB (алфавит 2): 6 бакетов позиции × 4 nnz-бакета предыдущего блока |
| 78 | SPLIT корня 32×32 |
| 79 | SPLIT узла 8×8 |
| 80 | TX (алфавит 4; §7.12) |
| 81 | CDEF strength плоскости тайла (алфавит 4; §7.13) |

Позиционные бакеты 8×8: `1 / 2–3 / 4–7 / 8–15 / 16–31 / 32+`.
Перед бакетизацией позиция приводится к спектральной доле 8×8:
`pos4 << 2`, `pos8`, `pos16 >> 2`, `pos32 >> 4` (минимум 1).
nnz аналогично нормируется: `nnz4 × 4`, `nnz8`, `nnz16 / 4`,
`nnz32 / 16`, затем бакеты `0 / 1–3 / 4–9 / 10+`.

AC v7: перед каждой парой `run → level` пишется EOB-флаг в контексте
позиции начала пробега (`0` = пара следует, `1` = конец блока). RUN больше
не содержит символ 31; возможные пробеги 0..1022 дают hybrid-uint символы
0..21. Если ненулевой коэффициент занял последнюю позицию скана, отдельный
завершающий EOB не пишется. Остальной порядок токенов блока — как в v5.

### 7.9. Рекурсивное дерево блоков v7.2

Плоскость сканируется корнями 32×32 row-major. Дерево фиксированной глубины
пишется pre-order; `0 = WHOLE`, `1 = QUAD`:

```text
32×32 (CTX 78) -> whole TX32 | четыре узла 16×16
16×16 (CTX  0) -> whole TX16 | четыре узла 8×8
 8×8  (CTX 79) -> whole TX8  | четыре листа 4×4
 4×4           -> лист (split-флага нет)
```

Каждый whole/лист содержит `MODE → TX → DC → AC`. Дочерние узлы обходятся
row-major; полностью лежащие вне правого/нижнего края не пишутся.
Глубина не приходит из потока, поэтому декодирование ограничено константой
и не допускает рекурсивного DoS. Референсный кодер раскрывает неполный
корень 32×32, но декодер обязан принимать whole на краю и клиповать запись.

Для `N ∈ {4,8,16,32}` в базовом TX=0 используется ортонормированный DCT-II:
`B[u,n] = sqrt(1/N)` при `u=0`, иначе
`sqrt(2/N)·cos((2n+1)uπ/(2N))`. Зигзаг — то же диагональное серпантинное
правило для матрицы N×N. Квантование наследует относительную частоту:
`Q_N[u,v] = Q_8[floor(8u/N), floor(8v/N)]`. Предикторы §7.1 масштабируются
до N без изменения формул.

Выбор split — свобода кодера. Референс сравнивает `D + λR`, реконструирует
кандидатные дочерние узлы в порядке декодера и откатывает область при победе
whole; гладкие/контрастные узлы имеют MAD-предвыбор, а частичная сумма
стоимости даёт ранний выход. Это не часть декодерного контракта.

Публичный lossy `encode()` пишет текущую версию (v10 с §7.18). Явный
`encode_with_version(..., N)` / CLI `--bitstream N` сохраняется только для
compatibility-тестов и воспроизведения старых потоков; lossless без метаданных
остаётся на минимальном достаточном v3.

### 7.10. SMOOTH-предиктор v7.3a

В каждом whole/листе v7 значения MODE `0..5` — DC/V/H/TM/D45/D135
(§7.1, масштаб N из §7.9); `6` — SMOOTH. Для luma это полный допустимый
диапазон `0..6`; chroma дополнительно принимает CfL `7..14` (§7.11).
v1–v6 сохраняют прежние диапазоны мод.

Для `N ∈ {4,8,16,32}`, координат `x,y ∈ [0,N)`, верхней границы `A[x]`,
левой `L[y]`, `BL = L[N−1]` и `TR = A[N−1]`:

```text
V = ((N−1−y) * A[x] + (y+1) * BL + floor(N/2)) / N
H = ((N−1−x) * L[y] + (x+1) * TR + floor(N/2)) / N
P[x,y] = (V + H + 1) >> 1
```

Деление целочисленное с округлением вниз; входы неотрицательны. Отсутствующие
границы и расширение края формируются по правилам §7.1/§7.9 до вычисления
формулы. Один и тот же предиктор обязан использоваться encoder-реконструкцией
и decoder для всех четырёх размеров.

### 7.11. Chroma-from-luma v7.3b

CfL разрешён только в Cb/Cr whole/листьях v7. Плоскость Y кодируется и
декодируется первой; источником CfL служит её **реконструкция до деблокинга**.
При `CHROMA420=1` она приводится к размеру chroma тем же усреднением 2×2,
что §6.3: `(a+b+c+d+2)>>2`, с репликацией правого/нижнего края. При
`CHROMA420=0` используется Y 1:1. Частичный блок N×N дополняется репликацией
края по §7.9.

MODE `7..14` кодирует α в Q4 без дополнительных битов:

| MODE | 7 | 8 | 9 | 10 | 11 | 12 | 13 | 14 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| α Q4 | −8 | −4 | −2 | −1 | +1 | +2 | +4 | +8 |
| α | −1/2 | −1/4 | −1/8 | −1/16 | +1/16 | +1/8 | +1/4 | +1/2 |

Для N∈{4,8,16,32}, реконструированного luma-блока `Y[i]` и обычного
DC-предиктора chroma `DC` от уже реконструированных chroma-границ:

```text
meanY = (sum(Y[i]) + N*N/2) / (N*N)
t     = alphaQ4 * (Y[i] - meanY)
delta = t >= 0 ? (t + 8) >> 4 : -((-t + 8) >> 4)
P[i]  = clamp(DC + delta, 0, 255)
```

Все деления целочисленные; половины округляются от нуля. Encoder обязан
строить residual и собственную реконструкцию от той же уже
реконструированной Y, а не от исходной luma. CfL в Y либо MODE ≥15 —
`Corrupt`. Decoder принимает CfL и для 4:4:4; reference encoder после A/B
эмитит его только для 4:2:0.

Выбор α — свобода кодера. Reference encoder оценивает
`round(16*cov(C-DC,Y-meanY)/var(Y))`, ограничивает `[-8,+8]`, округляет к
ближайшему множеству `{±1,±2,±4,±8}` (при равенстве — меньшая магнитуда)
и добавляет ровно один CfL-кандидат к SAD/RD-перебору базовых мод. Это
encoder-only оптимизация; на wire всегда допустимы все восемь значений.

### 7.12. Направленные transform и bounded trellis v7.4

После MODE каждый whole/лист v7 содержит символ TX в контексте 80:

| TX | Вертикальный базис | Горизонтальный базис |
| --- | --- | --- |
| 0 | DCT-II | DCT-II |
| 1 | ADST (DST-VII) | DCT-II |
| 2 | DCT-II | ADST (DST-VII) |
| 3 | ADST (DST-VII) | ADST (DST-VII) |

TX ≥4 — `Corrupt`. Для `N ∈ {4,8,16,32}`, пространственного residual
`R[y,x]`, вертикального базиса `V` и горизонтального `H`:

```text
DCT[k,n]  = sqrt(1/N), k=0
            sqrt(2/N) * cos((2n+1)k*pi/(2N)), k>0
ADST[k,n] = 2/sqrt(2N+1) * sin((2n+1)(k+1)*pi/(2N+1))
F[u,v]    = sum_y sum_x V[u,y] * H[v,x] * R[y,x]
R[y,x]    = sum_u sum_v V[u,y] * H[v,x] * F[u,v]
```

Оба базиса ортонормированы. Reference implementation строит ADST из
зафиксированных литералов `sin(k*pi/(2N+1))`; runtime-тригонометрия запрещена.
Координата коэффициента `(u,v)`, зигзаг и шаг `Q_N[u,v]` остаются §7.9
независимо от TX. Decoder сначала деквантует `F = c*Q_N`, затем применяет
обратный separable transform и складывает результат с predictor.

Выбор TX и trellis — свобода кодера. Reference encoder после RD-выбора MODE
сравнивает четыре TX по SSE квантования и требует от альтернативы меньшей
ошибки, не позволяя приблизительной rate-модели покупать разреженность ценой
качества. Затем encoder-only bounded trellis:

1. уточняет ненулевую магнитуду среди соседних уровней;
2. проходит AC в обратном зигзаге и может обнулить узел;
3. при удалении объединяет соседние run-рёбра, поэтому решение учитывает
   `EOB → run → level`, а не только независимый коэффициент.

Trellis использует transform-domain SSE; его решения не сигналятся отдельно.
Reference encoder v7.8 применяет `λ_trellis = 0.055 * λ_plane` вместо
исторических `0.02` в v7.4–v7.7: после scalar qmatrix прежнее значение
недооценивало rate. Identity/transform-skip остатка был измерен, дал регрессию
и **не входит** в wire-набор.

### 7.13. Directional constrained post-filter v7.5

Каждая DCT-секция плоскости v7 начинается с символа CDEF в контексте 81,
до первого split дерева. Значение 0 отключает фильтр; 1..3 выбирает строку
параметров:

| CDEF | Primary strength P | Secondary strength S | Damping D |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 0 |
| 1 | 2 | 1 | 3 |
| 2 | 6 | 2 | 3 |
| 3 | 12 | 4 | 4 |

Значение ≥4 — `Corrupt`. После реконструкции всей плоскости тайла decoder
сначала применяет деблокинг §7.6, если его header-флаг установлен, затем
CDEF. Для chroma оба фильтра работают в собственном разрешении до
апсэмплинга. CfL §7.11 всегда получает luma **до обоих фильтров**. Alpha
остаётся lossless и CDEF-символа не имеет. Фильтр не читает соседние тайлы.

Плоскость делится на блоки 8×8; неполные правый/нижний блоки допустимы.
Все направления и выходы вычисляются из неизменной копии входа фильтра.
Для направления `d` заданы два смещения:

| d | offset 1 | offset 2 |
| --- | --- | --- |
| 0 | (1,−1) | (2,−2) |
| 1 | (1,0) | (2,−1) |
| 2 | (1,0) | (2,0) |
| 3 | (1,0) | (2,1) |
| 4 | (1,1) | (2,2) |
| 5 | (0,1) | (1,2) |
| 6 | (0,1) | (0,2) |
| 7 | (0,1) | (−1,2) |

Для каждого направления считается взвешенный SAD только по парам внутри
текущего 8×8-блока: вес первого смещения 2, второго 1. Cost нормируется
как `(sum << 10) / sum_weights`; выбирается минимум, при равенстве —
меньший `d`.

Для отсчёта `x` primary taps используют `d` и веса `[4,2]`, secondary —
направления `(d+2) mod 8`, `(d+6) mod 8` и веса `[2,1]`. Каждый tap берётся
в обоих знаках смещения; координата за краем тайла реплицирует его край.
Ограниченная разность:

```text
shift = max(0, D - floor(log2(strength)))
constrain(delta, strength, D) =
  sign(delta) * min(abs(delta), max(0, strength - (abs(delta) >> shift)))
```

При strength=0 результат `constrain` равен 0. Сумма tap-вкладов `sum`
округляется как `(sum + 8 - (sum < 0)) >> 4`. Выход равен
`clamp(x + adjustment, min_tap, max_tap, 0, 255)`, где `min_tap/max_tap`
включают центр и все прочитанные primary/secondary отсчёты.

Выбор strength — свобода кодера. Reference encoder выводит единственного
ненулевого кандидата из `Q[0]` (`≤6 → 1`, `7..16 → 2`, иначе `3`) и
сравнивает его с OFF по SSE после возможного деблокинга. Для скорости
решение оценивается на одной позиции регулярной решётки 2×2 блоков
(в малой плоскости — на всех блоках); decoder всегда фильтрует всю плоскость.

### 7.14. Chroma reconstruction v7.6

При `CHROMA420=1` decoder v7 после deblock/CDEF chroma и до цветового
преобразования обязан использовать center-sited формулу §6.3. Новых
символов или header-флагов нет: формула является частью замороженной
семантики версии 7. CfL по-прежнему использует downsample 2×2 реконструкции
luma до post-filter (§7.11), поэтому prediction loop не меняется.

Reference encoder v7.8 включает 4:2:0 при `quality <= 85`, а при
`quality > 85` пишет 4:4:4. Это решение кодера, не ограничение decoder: тот
обязан принимать оба значения `CHROMA420` при любом lossy quality. В v7.6–v7.7
reference-порог был 75; после scalar qmatrix и RDOQ-перекалибровки возврат 85
дал лучший совместный PSNR/SSIM результат (§11.3). v1–v6 сохраняют
исторический порог 85 и co-sited upsample §6.3.

### 7.15. Scalar quantization matrices v7.7

Для каждой из 64 позиций базовых матриц v7 нормативно:

```text
BASE_LUMA_V7[i]   = 48
BASE_CHROMA_V7[i] = 48
```

К ним применяется неизменное IJG-масштабирование §7.2. Матрицы 4×4, 16×16
и 32×32 наследуются по правилу §7.9; поскольку база скалярна, шаг одинаков
для всех AC-направлений и для DCT/ADST. Новых символов и header-флагов нет:
выбор матрицы выводится из `version >= 7` и является нормативным изменением
декодера. v1–v6 всегда используют Annex K и побитово совместимы.

JPEG-матрицы оптимизировали видимость ошибок исходного 8×8 DCT, но в v7
искажали баланс Y/Cb/Cr после intra/CfL, recursive DCT/ADST и trellis.
Reference-значение 48 выбрано A/B по Kodak: оно сохраняет широкий диапазон
quality и скорость q70 выше 10 Мп/с; глобальный масштаб не заменяет
перцептивную проверку, поэтому принятие подтверждено также SSIM (§11.3).

### 7.16. Битстрим v8: целочисленный YCoCg

v8 наследует всю lossy-семантику v7 (§3.5, §7.8–§7.15) с **одним**
нормативным отличием: цветовое пространство и матрицы квантования.
Дерево блоков, split-алфавит, transform, контексты коэффициентов и
реконструкция c·Q[i] идентичны v7. Контейнер DCT-секции не меняется
(§4.2 v7). Измерения и история решений — §11.4.

**Цвет и матрицы квантования.** Плоскости lossy — Y/Co/Cg целочисленного
YCoCg (§6.4). Базовые матрицы скалярны и различаются по плоскостям:

`	ext
BASE_Y_V8[i]  = 51
BASE_CO_V8[i] = 45
BASE_CG_V8[i] = 38
`

IJG-масштабирование §7.2 и наследование производных размеров §7.9
неизменны. Header-флагов нет: выбор пространства и матриц выводится из
ersion >= 8.

**Отклонённые кандидаты до freeze v8** (не входят в wire):

- прямоугольные партиции 2:1 (прототип v7.10 / early v8): +0.5% BD-rate
  при гейте, но encode падал к ~10.2 Мп/с — ниже бюджета v8 **≥ 11 Мп/с**;
- TX-conditioned контексты и AC-смещение реконструкции — ухудшали плотность
  на полигоне (§11.4).

### 7.17. Битстрим v9: per-root delta-Q (адаптивная квантизация)

v9 наследует всю lossy-семантику v8 (цвет §6.4, матрицы §7.16, дерево,
энтропию §3.5, CDEF, деблокинг) с **одним** нормативным добавлением:
перед деревом каждого корня 32×32 каждой DCT-плоскости в символьный
поток кодируется **индекс delta-Q** `dq ∈ 0..=7`, масштабирующий матрицы
квантования этого корня. Контейнер секции не меняется (§4.2 v7+).

**Синтаксис.** Порядок обхода корней прежний (row-major по 32×32).
На корень — ровно один символ в новом контексте `CTX9_DQ = 82`
(общее число контекстов v9 — 83; раскладка v7/v8 без изменений).
Модель: алфавит 8, собственная родительская группа прогрева (23),
prior `[1, 2, 3, 6, 16, 6, 3, 2]` — нейтраль доминирует. Никаких
header-флагов: наличие delta-Q выводится из `version >= 9`.

**Масштабирование (нормативно).** Числители Q6 по индексу:

```text
DQ_NUM[8] = { 40, 45, 51, 57, 64, 72, 81, 91 }   // ~ 64·2^((dq-4)/6)
q'[i] = clamp((q[i] * DQ_NUM[dq] + 32) >> 6, 1, 255)
```

`dq = 4` — нейтраль (числитель 64, матрица без изменения); шаг
лестницы — 1/6 октавы (~12%), диапазон множителя ~0.63…1.42.
Масштабируется базовая 8×8-матрица плоскости (после IJG §7.2);
производные 4×4/16×16/32×32 строятся из масштабированной 8×8
правилами §7.9. Реконструкция коэффициента остаётся `c · Q'[i]`.
Деквантование всего дерева корня (все размеры блоков, DC и AC,
DCT и ADST) использует матрицы своей ступени.

**Семантика.** Delta-Q — сигналируемое решение кодера (как моды и
split): декодер обязан принять любой индекс. Референсная эвристика —
свобода кодера (§8, §11.5): перцептивное маскирование по локальной
активности источника — текстуры огрубляются, гладкие зоны и края
уточняются. Alpha-плоскость lossless и delta-Q не несёт.

### 7.18. Битстрим v10: асимметричный reference AQ

v10 имеет **ту же нормативную lossy-семантику и синтаксис, что v9**:
цвет, матрицы, дерево, контексты, `CTX9_DQ`, `DQ_NUM`, реконструкция и
порядок символов не меняются. Единственное decoder-visible отличие —
`header.version = 10`; декодер обрабатывает тело v10 по правилам §7.17.
Любая последовательность допустимых v9 delta-Q-индексов допустима в v10.

Новая версия нужна для заморозки другого **reference encoder**, не нового
decoder tool: v9 обязан навсегда воспроизводить свои golden bytes, а
публичный v10 фиксирует перекалиброванные решения AQ (§8, §11.6). Поэтому
потоки v9 и v10 нельзя нормализовать заменой байта версии: версия определяет
контракт reference encode, хотя decode результата использует одну семантику.

Reference v10 сохраняет активность v9 и применяет разные силы к знаку
отклонения лог-активности:

```text
a       = max(MAD32 - 0.9 * MAD16_of_2x2_downsample, 0)
l       = log2(1 + a)
center  = mean(l по корням плоскости тайла)
d       = l - center
strength = d > 0 ? 2.25 : 2.75
delta   = round_away_from_zero(strength * d)
dq      = clamp(4 + delta, 0, 7)
```

Для `delta > 0` сохраняется абсолютный up-floor v9: если `a < 4`,
огрубление запрещено (`delta = 0`). Нормативные пределы остаются
`−4..+3`; chroma AQ выключен (`dq = 4`). Формула — encoder-only свобода,
но frozen reference v10 защищён encode-golden (§10).

## 8. Референсные решения кодера (информативно)

Решения кодера (не влияют на способность декодера читать поток):

- **Палитра**: если уникальных RGBA ≤ 256 и палитровый поток меньше —
  выбирается палитра. Это верно и в lossy-запросе: малоцветная графика
  получает *точный* поток меньшего размера, чем DCT.
- **Identity vs YCoCg-R**: по субвыборке (~64k пикселей) оценивается энтропия
  MED-остатков в обоих пространствах (с потолком raw-fallback); identity
  выбирается при выигрыше > 2%.
- **Raw-fallback** на секцию: coded-форма больше сырой → пишется сырая.
- **4:2:0**: автоматически при `quality <= 85`; v7/v8 используют center-sited
  reconstruction, v1–v6 — исторический co-sited (§7.14).
- **Версия потока**: публичный lossy encoder пишет v10 (§7.18),
  lossless — минимальный v3. При ICC lossy остаётся v10,
  lossless использует v6 (§2.5). Явный выбор v1..v9 оставлен только для
  compatibility/golden-тестов.
- **Delta-Q (v9, §7.17)** — референсная эвристика (свобода кодера,
  калибровка §11.5): активность корня = MAD источника 32×32 минус
  0.9·MAD его 2×2-даунскейла (дисконт структуры: градиенты и края,
  переживающие даунскейл, маскируют хуже мелкозернистой текстуры);
  ступень = 2.0 ступени на октаву лог-активности относительно средней
  по плоскости тайла, кламп −4…+3 ступени; огрубление дополнительно
  требует абсолютной активности ≥ 4 (в малоактивных bokeh-кадрах
  «выше среднего» — это объект в фокусе, его не трогаем). Хрома
  delta-Q не использует (нейтраль): измеренные силы 0.5–1.0 ухудшали
  и S2, и butteraugli — остаточные плоскости после CfL низкоэнергетичны.
- **Асимметричный AQ (v10, §7.18)** — активность и ограничения v9
  сохранены; сила уточнения `2.75`, огрубления `2.25`. Это reference-only
  перекалибровка: decoder принимает любые `dq`, а frozen v9 продолжает
  использовать симметричную силу `2.0`.
- **Деблокинг** (§7.6): флаг ставится автоматически при `quality < 45` —
  там, где блочность заметна.
- **Split-решение** на суперблок 16×16 (v5): RD-сравнение «целиком» против
  «четыре 8×8» (§7.7) с тремя ускорителями (свобода кодера, суммарно
  encode ×1.3 при −0.7% размера корпуса q=75):
  - предвыбор по активности квадрантов (MAD 8×8): все ≤ 4 → WHOLE без
    пробы; контраст квадрантов ≥ 12 → QUAD без пробы 16×16; все ≥ 16
    (равномерный шум/текстура) → WHOLE (AC умирают, один DC дешевле
    четырёх — на шуме это ещё и −2.6% размера);
  - ранний выход из пробы расщепления: частичная сумма стоимостей 8×8
    превысила стоимость 16×16 → победитель ясен;
  - отклонено (измерено): QUAD при одном насыщенном квадранте — +2%.
- **Дерево v7.2** (§7.9): те же RD/предвыбор/ранний выход применяются
  на глубинах 32/16/8; для split 8→4 добавлена компенсация четырёх
  DC/mode-токенов в rate-оценке. Неполный корень 32×32 форсированно
  раскрывается, чтобы репликация края не смещала сравнение.
- **SAD-предотбор мод** (§7.4): полный RD только для 4 лучших из 6 мод
  в v3/v5 и из 7 базовых + одного CfL-кандидата в reference v7 chroma
  (для 16×16 — топ-3, для 32×32 — топ-2: DCT дороже, разброс мод меньше);
  нейтрален по размеру на q=75.
- **Линейность DCT** для DC/V/H: спектр остатка = F(orig)−F(pred) без
  полного DCT предсказания; аналитические F(DC), F(строки), F(столбца).
- **Мода intra-предикции** на блок: RD-перебор шести мод в v3/v5 (§7.4);
  в v7 — семи базовых (§7.10) и, для chroma, CfL (§7.11).
- **Dead-zone** при квантовании AC (§7.2). Reference encoder v1–v6 использует
  adaptive quantization по активности блока: bias линейно интерполируется
  от `0.40` при активности ≤ 4 до `0.18` при активности ≥ 16. На историческом
  корпусе q=75 это дало −8.4% размера при неизменном PSNR фотоклассов.
  Reference encoder v7.8 использует постоянный bias `0.40`: после scalar
  qmatrix старая маска переобнуляла AC текстур и проигрывала PSNR/SSIM.
  Wire фиксирует только деквантование `c * Q[i]`; frozen reference v7.9a
  дополнительно фиксирует свои решения encode-golden.

## 9. Требования к декодеру (нормативные)

1. **Никаких паник / UB** на произвольных байтах: только `Ok` или типизированная
   ошибка. Арифметика на недоверенных значениях — checked/wrapping (включая
   usize-переполнения на 32-битных платформах).
2. **Аллокации только после** валидации заголовка и проверки лимитов
   (`max_pixels`, по умолчанию 2^26; стороны ≤ 32768).
3. **Строгость структуры**: длины секций/тайлов сходятся байт-в-байт; финальное
   состояние rANS = `L` для v1–v6, range/raw-потоки v7 потреблены полностью;
   резервные поля нулевые; неизвестные флаги/версии — отказ
   (`UnsupportedFeature`/`UnsupportedVersion`).
4. **Клампы реконструкции** (предиктивная плоскость, выход IDCT, обратный цвет)
   обязательны и детерминированы.
5. Повреждённый поток не должен стоить более O(размер заявленного изображения)
   памяти и времени.

Реализация подтверждает контракт тестами: случайный мусор, обрезка валидного
потока на каждом байте, побитовые мутации, злонамеренные заголовки/таблицы.

## 10. Версионирование и заморозка

- Форматы v1–v10 **заморожены**. Любое изменение битстрима или decoder semantics
  — новая версия (byte 4); исключение — новые **типы чанков метаданных**
  (§2.5). Кодер пишет v3 для lossless, v10 для lossy; с ICC — соответственно
  v6 и v10. Явный выбор старой версии не является публичным production API.
- Golden-вектора: `Products/FRC/crates/frc-i/tests/data/*.fri` +
  FNV-1a-хеш пиксельного выхода.
  - `golden-v1-*.fri`, `golden-v2-*.fri`, `golden-v6-*.fri` —
    **decode-заморозка**: файлы
    закоммичены навсегда и не регенерируются; тесты проверяют только
    декодирование.
  - `golden-v3-*.fri` … `golden-v5-*.fri` — legacy reference-encode vectors
    через явную `encode_with_version`; служебная регенерация:
    `FRC_I_UPDATE_GOLDEN=1 cargo test -p frc-i --test golden`.
  - `golden-v7-*.fri` и `golden-v8-*.fri` —
    **неизменяемая encode/decode-заморозка** (тесты кодируют через явные
    `encode_with_version(..., 7|8)`). Расхождение требует новой версии,
    а не регенерации файлов.
  - `golden-v9-lossy-q75.fri` и `golden-v9-lossy-icc-q75.fri` —
    **неизменяемая encode/decode-заморозка v9** через явный
    `encode_with_version(..., 9)`.
  - `golden-v10-lossy-q75.fri` и `golden-v10-lossy-icc-q75.fri` —
    **encode/decode-заморозка текущего публичного кодера**: публичный
    `encode()` обязан побайтово совпадать с явным v10, декодер — давать
    зафиксированный FNV-1a пиксельного выхода.
- Реализацию кодера v7/v8/v9/v10 можно ускорять только bit-exact: golden bytes,
  reconstructed pixels и decoder semantics не меняются.

## 11. Результаты, честный baseline и путь к AVIF

### 11.1. Синтетический корпус (исторические замеры v3–v5)

Синтетический корпус (512×512: фото с текстурами, портрет, графика, белый шум),
release-сборка; сравнение с `image` crate (PNG CompressionType::Best/Adaptive,
JPEG q=75). Измерено 2026-07-15 (кодер v5: суперблоки + AQ), x86-64:

| Изображение | PNG | FRC-I-lossless | JPEG q75 (PSNR) | FRC-I v5 q75 (PSNR) |
| --- | --- | --- | --- | --- |
| photo-512 | 221 536 | 170 705 (**−22.9%**) | 19 215 (44.42) | 12 193 (**−36.5%**, 43.97) |
| portrait-512 | 104 923 | 94 797 (**−9.7%**) | 12 100 (48.94) | 4 542 (**−62.5%**, 47.66) |
| graphics-512 | 4 192 | 1 951 (**−53.5%**, палитра) | 21 658 (41.62) | 1 951 (**точный**, в 11 раз меньше) |
| noise-512 | 787 132 | 786 480 (−0.1%, raw-потолок) | 328 987 (22.28) | 121 353 (12.16)* |

Итого lossy по корпусу: **−63.3%** против JPEG при сопоставимом PSNR
(q=30 с деблокингом: −71.3%, q=90: −24.1%).

> **Предупреждение о репрезентативности.** Этот корпус полезен для
> регрессионного контроля инструментов, но среднее по нему завышено
> классами portrait (огромные гладкие зоны) и graphics (палитра, выигрыш
> 11×). На реальных фотографиях картина другая — см. §11.2. Конкурентные
> заявления по §11.1 не делаются.

Вклад инструментов по версиям (q=75, photo/portrait):

- dead-zone AC (`+0.40`, v3-кодер): −12.7% / −7.6% размера за −0.08 / −0.01 dB;
- диагональные моды D45/D135 + RD-выбор (v3): ещё −3.2% / +1.2% при +0.05 dB;
- adaptive quantization по активности блока (§8, v3-кодер):
  −8.4% суммарного размера корпуса q=75 при неизменном PSNR фотоклассов;
- деблокинг-фильтр (§7.6, v4): +0.40 / +0.44 dB на q=30 бесплатно по байтам;
- суперблоки 16×16 (§7.7, v5): photo −1.2% (−0.07 dB),
  **portrait −18.5% (−0.37 dB)** — гладкие зоны схлопываются в один блок;
  graphics/noise без регрессии (RD выбирает расщепление);
- nnz-контексты AC (JXL/AV1): **+5..8% — отклонены** (см. rationale).

Скорость lossy (без SIMD, тайловый параллелизм, здесь 4 тайла): ~34 Мп/с
encode на q=75 (~37 на q=30, ~21 на q=90 — больше выживших AC),
~105 Мп/с decode; на изображениях с большим числом тайлов масштабируется
до числа ядер.

\* Белый шум вне перцептивной модели: FRC-I агрессивно квантует
высокочастотный шум (PSNR ниже), JPEG тратит на его сохранение в 2.4 раза
больше байт. Для реальных фото важен первый столбец пары.

Закрытые пункты старого roadmap: суперблоки 16×16 (v5, §7.7), деблокинг
(v4, §7.6), adaptive quantization (v3-кодер, §8), ICC (v6, §2.5),
скорость encode ≥ 30 Мп/с (эвристики §8). Открытые пункты слиты
в план §11.3.

### 11.2. Честный baseline: Kodak 24 против AVIF/JXL/JPEG

Первый прогон против реальных конкурентов на реальных фотографиях.
Полигон: `Tools/frc-i-compete/run_compete.py` (корпус Kodak 24 768×512,
лестницы качества всех кодеков, PSNR(RGB), BD-rate Bjøntegaard;
отчёт — JSON). Кодеки: FRC-I v5 (release), JPEG/AVIF/JXL — ffmpeg
(libaom-av1 `still-picture`, libjxl). Измерено 2026-07-15, x86-64.

**BD-rate** (меньше = лучше; медиана по 24 кадрам близка к среднему):

| Пара | BD-rate | Комментарий |
| --- | --- | --- |
| FRC-I vs JPEG | **+11.9%** | на реальных фото мы пока *хуже* JPEG |
| FRC-I vs JXL | **+37.1%** | |
| FRC-I vs AVIF | **+90.5%** | ~2× битрейт при равном PSNR; разброс +54…+144%, выигрышей нет |
| AVIF vs JPEG | −41.8% | контроль: полигон воспроизводит известное соотношение |
| JXL vs JPEG | −14.0% | контроль (PSNR занижает JXL — он оптимизируется под butteraugli) |

Сумма размеров при ~38 dB PSNR (24 кадра): AVIF 1.58 МБ, JXL 2.09 МБ,
JPEG 2.20 МБ, **FRC-I 2.76 МБ**. Скорость encode mid-quality:
**FRC-I ~23 Мп/с**, JXL ~5.2, JPEG ~9.2 (ffmpeg), AVIF ~0.6 —
**FRC-I в ~35–40 раз быстрее AVIF**. Контроль на `cpu-used=1`
(медленный/лучший aom, 6 кадров): разрыв тот же (+94.5%) — дело не в
режиме кодера AVIF.

Выводы, зафиксированные как факты для планирования:

1. Заявление «−63% vs JPEG» из §11.1 на реальные фото **не переносится**:
   на Kodak мы отстаём и от JPEG (+11.9%). Kodak-BD-rate — единственная
   метрика плотности для конкурентных решений с этого момента.
2. Разрыв с AVIF (~2×) — это класс инструментов (энтропийное
   моделирование, разбиение, предикция), а не тюнинг эвристик §8.
3. Уже достигнутое преимущество — скорость (35–40× encode) и простота
   декодера (§9, чистый std, wasm в десятки КБ). Его не сдавать: бюджет
   замедления encode на весь путь §11.3 — не более ~3× от текущего.
4. PSNR — основная метрика полигона, но перцептивный зазор AVIF/JXL она
   занижает. Начиная с v7.7 крупные изменения дополнительно проверяются
   windowed SSIM (`Tools/frc-i-compete/compare_ssim.py`). Butteraugli-класс
   метрика остаётся обязательной перед product rollout, но не меняет
   замороженный wire.

### 11.3. Путь к AVIF: история разработки и freeze-gate v7

Целью линии было: **BD-rate vs AVIF (libaom, still) на Kodak в коридоре
0…+10%** при encode ≥ 10 Мп/с. Арифметика от §11.2 (+90.5% vs AVIF):
нужно **−42%** нашего битрейта. «Убить AVIF» — выиграть одновременно
по (плотность × скорость × простота).

Ядро (`frc-i`) не переписывалось. Lossy-моделирование развивалось в
битстриме **v7** за явным selector; после freeze-gate v7 стал версией
публичного lossy `encode()`.

Этапы и **фактические** цифры (полигон Kodak, PSNR BD-rate):

1. **v7.1/v7.1b — адаптивная энтропия (§3.5, §7.8).** Сделано
   (принято в frozen v7). Range-кодер + адаптивные модели, 78 контекстов
   (nnz × позиция), бинарный EOB, RUN-алфавит 20,
   иерархический прогрев, order-1 на токенах, prior по виду контекста.
   **Факт v7.1b (Kodak 24, 2026-07-16):** **−3.6% BD-rate vs v5**;
   vs AVIF **+75.6%**. Бинарный EOB дал ещё **−0.20% среднего размера**
   поверх v7.1: лучше во всех 216 точках лестницы, диапазон −0.55…−0.01%.
   Скорость encode ~22.2 Мп/с (v5 ~23.1 Мп/с в том же прогоне).
   Order-1 для малых алфавитов SPLIT/EOB/MODE дал +0.12% и отклонён.
   **Вывод:** ожидание −15…−25% было завышено — двухпроходный
   статический rANS уже близок к оптимуму по токенам тайла; адаптив
   снимает цену таблиц и открывает богатые контексты, но сам по себе
   не даёт главного скачка. v7.1b оставлен из-за стабильного выигрыша
   при малой сложности; дальнейший основной рычаг — v7.2.
   Порог отсечения (§11.3 правила) не сработал: этап принят как
   инфраструктура при малом замедлении.
2. **v7.2 — рекурсивное разбиение 32×32 → 4×4 (§7.9).** Сделано
   (принято в frozen v7). Фиксированное quadtree 32→16→8→4, DCT4/DCT32,
   отдельные split-контексты глубины и RD-выбор с откатом реконструкции.
   **Факт (Kodak 24, 2026-07-16):** **−2.26% BD-rate vs v7.1b**,
   накопительно **−5.73% vs v5** и **+71.8% vs AVIF**. При одинаковом
   quality размер +1.82%, PSNR +0.22 dB — BD-rate учитывает обмен честно.
   Encode ~13.7 Мп/с (v5 ~18.4 в том же прогоне), цель ≥10 сохранена.
   Первоначальное ожидание −8…−15% не подтвердилось: квадратное дерево
   улучшает локальную адаптацию, но без более сильных предикторов часто
   покупает качество дополнительными DC/mode-токенами. Этап принят:
   вклад >2%, фиксированная глубина и бюджет скорости соблюдены.
3. **v7.3 — предикция.**
   - **v7.3a — SMOOTH (§7.10): сделано (принято в frozen v7).** Один линейный
     двумерный предиктор, wire ID 6, одинаковая целочисленная формула для
     4/8/16/32. **Факт (Kodak 24, 2026-07-16): −0.80% BD-rate vs v7.2**,
     улучшение на всех кадрах (−1.95…−0.14%); накопительно **−6.49% vs v5**
     и **+70.3% vs AVIF**. При одинаковом quality размер −0.89%, PSNR
     +0.006 dB. Encode ~14.8 Мп/с (v5 ~20.5 в том же прогоне).
   - A/B-отсечение: D63/D117/D153 по отдельности дали +0.34/+0.14/+0.32%
     на smoke-8 и удалены; SMOOTH_V/H нейтральны (+0.02/+0.00%), а
     квадратические веса дали +0.03% против линейных. В bitstream оставлен
     только стабильный победитель. Вклад меньше 2%, но этап принят как
     бесплатное по скорости улучшение всех 24 кадров.
   - **v7.3b — chroma-from-luma (§7.11): сделано (принято в frozen v7).**
     Восемь signed Q4 slopes кодируются MODE 7..14; predictor использует
     реконструированную Y до деблокинга и работает для 4/8/16/32. Reference
     encoder эмитит CfL только в 4:2:0 и по covariance выбирает один α для
     SAD/RD. **Факт (Kodak 24, 2026-07-16): −1.57% BD-rate vs v7.3a**,
     улучшение на всех кадрах (−3.73…−0.26%); накопительно **−7.93% vs v5**
     и **+67.4% vs AVIF**. При одинаковом quality размер −0.41%, PSNR
     +0.072 dB. Encode ~13.4 Мп/с (v5 ~18.3 в том же прогоне), бюджет ≥10
     сохранён. Exhaustive-перебор восьми α был на 0.28% хуже: близкие CfL
     варианты вытесняли базовые моды из короткого RD shortlist.
   - A/B-отсечение v7.3b: CfL в 4:4:4 терял ~0.05 dB на q90/95 и отключён
     в reference encoder; исходная широкая сетка `±1/4,±1/2,±1,±2` давала
     смешанные регрессии. Степенная сетка `±1/16..±1/2` улучшила все 24
     кадра. Тонкие углы не возвращать без исправления RD/rate-модели.
4. **v7.4 — направленные transform + bounded trellis (§7.12): сделано
   (принято в frozen v7).** Wire-набор: DCT_DCT, ADST_DCT, DCT_ADST,
   ADST_ADST для 4/8/16/32; TX — отдельная адаптивная модель. Encoder выбирает
   TX по минимальной ошибке квантования, затем уточняет уровни и обнуляет
   run-связанные AC обратным проходом. **Факт (Kodak 24, 2026-07-16):
   −8.90% BD-rate vs v7.3b**, улучшение на всех кадрах
   (−11.25…−6.46%); накопительно **−15.73% vs v5** и **+60.36% vs AVIF**
   (медиана +56.10%). При одинаковом quality размер −15.76%, PSNR −0.417 dB:
   trellis существенно перенастроил шкалу качества, а BD-rate сравнивает
   кривые при равном PSNR. Encode ~11.1 Мп/с (v5 ~23.4 в том же прогоне) —
   бюджет ≥10 сохранён с небольшим запасом.
   - A/B-отсечение v7.4: полный ADST-набор без trellis дал −3.90% на smoke-3;
     только одноосевые transform — −3.71%, только ADST_ADST — −2.70%.
     Identity/transform-skip дал **+8.41%** и удалён из encoder и wire.
     Trellis `λ` 0.01 дал −6.92%, 0.02 — −8.86% на smoke-3; слишком сильный
     0.35 разрушал качество. Повторный transform победителя устранён, чтобы
     удержать скорость.
5. **v7.5 — directional constrained post-filter (§7.13): сделано
   (принято в frozen v7).** Один strength 0..3 на плоскость тайла; направление
   выводится на каждом 8×8, primary/secondary taps ограничиваются по
   контрасту. Фильтр работает после деблокинга, вне prediction/CfL loop.
   **Факт (Kodak 24, 2026-07-16): −1.35% PSNR BD-rate vs v7.4**, улучшение
   на всех кадрах (−2.90…−0.04%; медиана −1.14%); накопительно
   **−16.82% vs v5** и **+57.96% vs AVIF** (медиана +53.96%). При одинаковом
   quality размер +0.017%, PSNR +0.075 dB. Encode ~10.94 Мп/с против
   ~11.10 у v7.4 в полном прогоне: бюджет ≥10 сохранён.
   - A/B-отсечение: luma-only дал лишь −0.57% на smoke-3; включение Cb/Cr —
     −1.84%. Exhaustive-поиск трёх strength для одной luma улучшил
     −0.57% → −0.63%, но снизил скорость 10.75 → 8.3 Мп/с; оставлен один
     qstep-кандидат и SSE-решение на 1/4 блоков.
   - Сетка primary strength `2/6/12` дала −1.94% на smoke-3; `2/4/8` —
     −1.84%, более сильная `2/8/16` — −1.83%. Перенос границы weak→medium
     с Q=6 на Q=3 ухудшил результат на 0.15%, отклонён.
   - Первоначальные **−2…−5% перцептивно** не подтверждены PSNR-полигоном;
     отдельная перцептивная метрика ещё обязательна. Этап принят несмотря
     на вклад <2%: улучшены все 24 кадра, а замедление относительно v7.4
     около 1.4%, значительно ниже 20%-порога отсечения.
6. **v7.6 — center-sited chroma reconstruction (§6.3/§7.14): сделано
   (принято в frozen v7).** Исторический decoder интерпретировал среднее 2×2
   как co-sited top-left и тем самым сдвигал chroma на полпикселя. v7
   использует согласованные separable веса 1:3/3:1; reference encoder
   переключается с 4:2:0 на 4:4:4 после quality 75 вместо 85.
   **Факт (Kodak 24, 2026-07-16): −2.56% BD-rate vs v7.5**
   (медиана −1.83%, диапазон −8.77…+0.49%; улучшены 23/24 кадра);
   накопительно **−19.16% vs v5** и **+53.16% vs AVIF**
   (медиана +49.65%). При одинаковом quality размер +2.17%, PSNR +0.239 dB.
   Encode ~10.96 Мп/с против ~10.94 у v7.5: q70 остаётся 4:2:0, бюджет
   скорости не изменился.
   - Исправление фазы само по себе дало **−1.47%** на полном Kodak и улучшило
     все 24 кадра (−4.83…−0.19%). Более ранний 4:4:4 добавил в среднем
     −1.11%; пять кадров локально регрессировали, но в сумме с phase fix
     осталась одна ограниченная регрессия +0.49%.
   - A/B-отсечение: 4-tap Catmull-Rom оказался на +0.10% хуже bilinear
     на smoke-3 при четырёхкратном числе taps; downsample `[1,3,3,1]`
     дал +0.83% и −0.040 dB. Оба удалены. Перенос только q85 в 4:4:4 дал
     −0.84% на smoke-3; добавление q80 — ещё −0.65%, поэтому оставлен
     порог 75.
7. **v7.7 — scalar quantization matrices (§7.15): сделано
   (принято в frozen v7).** Annex K заменён только для v7 на одинаковый шаг 48
   во всех 64 позициях Y/Cb/Cr. **Факт (Kodak 24, 2026-07-16):
   −16.97% PSNR BD-rate vs v7.6**, медиана −16.89%, диапазон
   −18.92…−14.84%; улучшены все 24 кадра. Накопительно **−32.92% vs v5**
   и **+27.39% vs AVIF** (медиана +24.25%; один кадр уже +9.72%).
   Windowed RGB SSIM подтверждает не только PSNR-перераспределение:
   **−10.64% SSIM BD-rate vs v7.6**, улучшены 24/24
   (−13.33…−5.56%). Encode q70 ~10.7 Мп/с против ~10.96 у v7.6;
   порог ≥10 сохранён.
   - A/B: flat только для Y дал +1.71%, только для chroma +6.85% на smoke-3;
     выигрыш требует совместного баланса компонент. Общий масштаб
     32/48/64 дал −16.31/−16.66/−16.59% против v7.6 на smoke-3; выбран 48.
     Chroma 51 и 44 уступили равному Y/C шагу на 0.15/0.21 п.п.
   - Энтропийный аудит перед qmatrix не дал победителя: глобальная
     wire-rate модель, TX-specific scans, Markov-sign, раздельные Y/C банки
     и явная EOB-position дали от нейтрали до регрессии и удалены.
8. **v7.8 — encoder RDOQ/dead-zone/chroma recalibration: сделано
   (принято в frozen v7).** Wire и decoder не изменены. Для scalar qmatrix
   reference encoder поднял `λ_trellis` с 0.02 до 0.055, отключил старую
   activity-зависимую dead-zone только в v7 (`AC bias = 0.40`) и вернул
   порог 4:2:0 с 75 на 85. **Факт (Kodak 24, 2026-07-16):
   −1.58% PSNR BD-rate vs v7.7**, медиана −1.57%, диапазон
   −3.19…+0.55%; улучшены 21/24 кадра. Windowed RGB SSIM:
   **−0.66%**, медиана −0.29%, диапазон −2.96…+1.36%; улучшены 19/24.
   Накопительно **−33.98% vs v5**; разрыв до AVIF уменьшен до
   **+25.57%** (медиана +23.71%, диапазон +6.86…+45.02%).
   - A/B trellis на smoke-3: λ 0.03/0.04/0.055/0.06/0.08 дали
     −0.28/−0.72/−0.87/−0.87/−0.18% PSNR; у 0.08 появилась регрессия,
     выбран более устойчивый 0.055.
   - Удаление legacy AQ поверх λ 0.055 дало ещё −1.35% PSNR; bias
     0.45/0.50 были нейтральны и смешанны. С исходным порогом 75 итог
     smoke-8 улучшал PSNR на −2.14%, но ухудшал SSIM на +0.95%.
     Порог 85 сбалансировал обе метрики (−1.35/−0.19%); постоянный 4:2:0
     улучшал SSIM, но регрессировал PSNR на +2.68%, поэтому отклонён.
   - Нового поиска нет; decoder speed неизменна. Парный q70-замер находится
     на границе 10 Мп/с, а нормализация по одновременному v5-прогону даёт
     ~10.4 Мп/с в условиях v7.7 baseline.
9. **v7.9a — bit-exact encoder speed: сделано.** Wire, решения кодера,
   reconstructed pixels и decoder semantics не изменены. Separable
   DCT/ADST считает четыре независимых dot-product параллельно, сохраняя
   порядок сумм внутри каждого коэффициента. Bounded trellis не повторяет
   одинаковые level-кандидаты и хранит связный список AC в компактном
   stack-массиве `u16` вместо `Vec`.
   **Парный Kodak 24 q70 A/B:** 12.03 → **12.42 Мп/с** (**+3.26%**);
   все 24/24 q70 stream побайтово совпадают с v7.8. PSNR/SSIM BD-rate
   неизменны по определению.
   - Профиль-отсечение показало: полный transform-search занимает ~20%
     encode-времени, bounded trellis — до ~9%.
   - Переиспользование вертикального ADST с тремя spectrum-буферами
     регрессировало cache; streaming-вариант дал лишь +0.33% и удалён.
     Группировка восьми dot-product также дала только +0.34%; оставлена
     более устойчивая группа из четырёх.
10. **v7.9b — lossy color transform: отклонено.** Wire и decoder v7 оставлены
    без изменений: нормативны BT.601 (§6.2) и общий scalar step 48 (§7.15).
    На smoke-8 BT.709 ухудшил PSNR/SSIM BD-rate на **+1.17%/+0.57%**;
    отдельные шаги 48/45/51 ухудшили PSNR до +1.34%. Перекалибровка BT.601
    48/46/53 также проиграла: +0.37%/+0.08%.
    - Единственный положительный кандидат — integer scaled YCoCg:
      `Y=(R+2G+B+2)>>2`, `Co=((R-B)>>1)+128`,
      `Cg=((2G-R-B)>>2)+128`; обратное
      `R=Y+Co-Cg`, `G=Y+Cg`, `B=Y-Co-Cg` после вычитания 128 из chroma.
      Результат до квантования лежит в 0..255, sampled/exhaustive проверка
      RGB дала максимальную ошибку 1.
    - Лучший Pareto-набор scalar steps **Y/Co/Cg = 51/45/38** на Kodak 24:
      **−2.08% PSNR BD-rate** (медиана −2.26%, диапазон −3.81…+2.21%;
      улучшены 23/24) и **−0.73% windowed RGB SSIM** (медиана −0.61%,
      диапазон −3.10…+3.53%; улучшены 18/24). Encode q70 ~12.0 Мп/с.
      Гипотетический разрыв до AVIF был бы +22.56%.
    - Заранее установленный порог был ≥3% PSNR при SSIM не хуже. Кандидат
      недобрал 0.92 п.п. и дал крупные покадровые SSIM-регрессии, поэтому
      менять decoder semantics ради него нельзя. Код кандидата удалён; это
      отрицательный результат, а не новый нормативный v7-инструмент.
11. **v7.10 — rectangular partition/transform: отклонено.** Были реализованы
    2:1 leaf-узлы 8×16/16×8 и 16×32/32×16, ternary QUAD/HORZ/VERT syntax,
    separable DCT/ADST, rectangular quant/scan и gradient-guided shortlist.
    Лучший вариант использовал RD-gated anisotropic shortlist и DCT-only
    bounded trellis.
    - Smoke-8 дал **−3.50% PSNR BD-rate** и **−3.41% windowed RGB SSIM**
      при ~10.2 Мп/с, без покадровых регрессий.
    - Полный Kodak 24 против принятого v7.9a (его stream bit-exact совпадает
      с v7.8) дал **−3.26% PSNR BD-rate** и **−3.42% SSIM**, но только
      **9.5 Мп/с**. Заранее установленный порог ≥5% при encode ≥10 Мп/с
      не выполнен по обеим координатам.
    - Aspect-normalized rectangular scan ухудшил smoke PSNR-результат до
      −1.99%; расширение shortlist на любую анизотропию также ухудшило
      плотность и скорость. Оба направления отсечены.
    - Экспериментальные transform, partition syntax, decoder и тесты удалены:
      v7 wire/decoder остаются на принятой v7.9a-семантике. Результаты
      сохранены только как benchmark evidence.
12. **v7.11 — measured bottleneck + recursive binary tree: отклонено.**
    Диагностика принятого v7.9a выполнена на Kodak 24 при
    `q={30,50,70,85,95}` без изменения codec wire/API.
    - Luma занимает **79.17–94.27%** файла. Внутри оценённого luma syntax
      `RUN + LEVEL + EOB` растут с **64.96%** при q30 до **90.15%** при q95:
      крупный резерв требует уменьшить число/разброс ненулевых коэффициентов,
      а не оптимизировать chroma.
    - Дополнительное conditioning коэффициентов по block size даёт только
      **+0.97…−0.34%** оценённых бит; по TX — **−2.36…−2.68%**, совместное —
      **−0.13…−2.40%**. Дробление adaptive-моделей не окупает прогрев.
    - Offline `LAST + significance-map` oracle вместо текущего RUN/EOB даёт
      лишь **+2.08%** оценённых полных бит при q30 и **+1.17%** при q95.
      `LAST + RUN` хуже на **0.17–4.59%**. Самостоятельный entropy-wire этап
      не достигает порога 5%.
    - Tile-local двухкоэффициентный Wiener-like luma restoration upper bound:
      **−0.40% BD-rate** (24/24 улучшены, диапазон −0.65…−0.10%). Этого
      недостаточно для decoder-инструмента.
    - Smoke-8 falsification: глобальный FLIPADST **+1.27% BD-rate**, PAETH
      **+0.50%**, adaptive signed-level вместо magnitude+raw-sign **+1.08%**;
      все три ухудшили каждый из восьми кадров и удалены полностью.

    Единственный измеренный structural-класс, близкий к порогу, — v7.10
    rectangles (−3.26%). Для проверки более сильной гипотезы был реализован
    **recursive binary tree**: каждый square-узел 16/32 разрешал
    `LEAF/QUAD/HORZ/VERT`, а каждый полученный 2:1 узел независимо остаётся
    leaf либо делится по длинной стороне на два square-узла. Поэтому одна
    половина региона может остаться rectangular, а другая рекурсивно дойти до
    8/4; максимальная глубина фиксирована `32 → 32×16 → 16 → 16×8 → 8 → 4`.
    Search был luma-only, decoder — bounded, tile-local и без
    stream-зависимого heap.
    - Полный recursive-BT на smoke-8 дал **−3.47% PSNR BD-rate** при
      **5.5 Мп/с**.
    - Компактная split+shape syntax дала **−3.50%** при **5.4 Мп/с**.
    - RD-gating поднял скорость до **6.4 Мп/с**, но ослабил выигрыш до
      **−3.23%**.
    - Заранее установленный gate **≥5% и ≥10 Мп/с** не выполнен ни одним
      вариантом. Полный Kodak и SSIM не запускались после провала первичного
      gate. Rectangular transform/scan, recursive syntax, decoder и тесты
      удалены; v7 wire остался на v7.9a.

13. **Freeze v7 — принято v7.9a.**
    - Финальный reference encoder побайтово совпадает с v7.8; v7.9a меняет
      только bit-exact скорость transform/trellis. Kodak q70: **12.42 Мп/с**.
    - Финальный разрыв к AVIF — **+25.57% PSNR BD-rate**. Для верхней границы
      исходной цели +10% требовалось бы ещё около **−12.4%** текущего
      битрейта. Цель v7 не достигнута и явно не объявляется достигнутой.
    - Дальнейшие правдоподобные выигрыши требуют новой partition/coefficient
      syntax. Их нельзя добавлять в замороженный v7; это работа новой версии.
    - Публичный lossy `encode()` и lossy `encode_with_icc()` пишут v7
      (до выпуска v8 — §11.4). Lossless сохраняет минимальные v3 без ICC
      и v6 с ICC.
    - Encode/decode freeze зафиксирован
      `golden-v7-lossy-q75.fri` и `golden-v7-lossy-icc-q75.fri`; декодер
      продолжает принимать v1..v7.

Правила после заморозки:

- Wire и decoder semantics v7 неизменны; decoder-visible инструменты требуют
  новой версии битстрима.
- Изменения реализации v7 допустимы только при побайтовом совпадении golden,
  одинаковых reconstructed pixels и прохождении Kodak speed regression gate.
- **Контракт §9:** целочисленные детерминированные CDF, лимиты памяти,
  независимые тайлы.
- Битность 10/12, progressive и дальнейший density roadmap — новая версия,
  не расширение v7.

### 11.4. Линия v8: принятые инструменты и полигон

Кандидаты v8 выбраны из измеренной базы §11.3. Бюджет encode линии v8 —
**≥ 11 Мп/с** (строже, чем ≥ 10 у v7).

1. **Целочисленный YCoCg + пошаговые матрицы 51/45/38 — принято**
   (§6.4, §7.16). Носитель выигрыша: на изолированном v7.9b-замере
   **−2.08%** PSNR BD-rate (медиана −2.26%, лучше на 23/24) при encode
   ~12.0 Мп/с — укладывается в бюджет ≥ 11.
2. **Прямоугольные партиции 2:1 — отклонены до freeze.** Early v8 с
   гейтом анизотропии дал суммарно **−2.55%** vs v7.9a при **10.2 Мп/с**
   (ниже бюджета). Изолированный вклад rect ~**−0.51%** не окупал потерю
   ~1.6 Мп/с. Дерево/энтропия v8 оставлены идентичными v7.
3. **TX-conditioned контексты — отклонено** (+2.17% BD-rate на полном
   Kodak; 2-класса — +1.21%).
4. **AC-смещение реконструкции — отклонено** (δ=10: +1.18%; δ=4: +0.40%).

**Итог wire v8** (Kodak 24, out-v8-ycocg-speed): только YCoCg +
матрицы 51/45/38; **−2.1%** PSNR BD-rate vs v7.9a при encode q70
**11.8 Мп/с** (бюджет ≥ 11 соблюдён). Правила заморозки v7 распространяются
на v8; encode/decode freeze — golden-v8-lossy-q75.fri,
golden-v8-lossy-icc-q75.fri.

Направления следующей версии (не v8): прямоугольные/рекурсивные партиции
под gate ≥5% и ≥11 Мп/с, LAST-кодирование коэффициентов, butteraugli-класс
метрика в полигоне (§11.2), битность 10/12, progressive.

### 11.5. Линия v9: перцептивный полигон и per-root delta-Q

**Смена полигона.** PSNR исчерпан как целевая функция: скоростной потолок
достигнут (§11.4), а PSNR-BD занижает перцептивный зазор к AVIF/JXL.
Основной полигон v9 — перцептивный: **SSIMULACRA2** и **butteraugli**
(нативные бинарники libjxl) + PSNR(RGB/Y) как guard-метрика; BD-rate
Bjøntegaard по кадрам, лестница q = 30…90. Харнессы:
`run_honest_jxl.py` (vs нативный cjxl/djxl, корпуса Kodak/picsum/webphotos)
и `run_ab_frc.py` (A/B двух конфигураций FRC-I: версия битстрима +
env-переопределения кодера). Бюджет скорости жёсткий: **не ниже v8**.

**Кандидат линии — per-root delta-Q (§7.17), принят.** Сигналируемая
AQ выбрана как единственный инструмент v9: перераспределение битов —
главный источник перцептивного выигрыша при нулевой цене скорости
(эвристика — один MAD-проход по источнику, ~1 оп/пиксель; сигнал —
1 символ на корень, ~0.1% потока). Дерево/энтропия/цвет v8 не тронуты —
изменение изолировано и дёшево для декодера.

**Калибровка референсной эвристики** (Kodak 24, полная сетка A/B vs v8;
S2/BA/PSNR — mean BD-rate, отрицательное = лучше):

| Конфигурация | S2 | BA | PSNR(RGB) |
| --- | ---: | ---: | ---: |
| сила 1.0 (первый проход) | −4.3% | −2.0% | +1.1% |
| сила 1.5 | −5.7% | −2.0% | +1.8% |
| сила 2.0 | −6.3% | −1.9% | +2.5% |
| сила 2.0 + дисконт структуры 0.9 | −5.4% | −4.1% | +1.8% |
| **сила 2.0 + дисконт 0.9 + up-floor 4 (принято)** | **−5.2%** | **−4.0%** | +1.8% |

Ключевые решения (все измерены полной сеткой):

1. **Дисконт структуры 0.9 — принято.** Активность = MAD −
   0.9·MAD(2×2-даунскейл): шум усредняется даунскейлом (маскирует —
   активность остаётся), градиенты/края переживают его (бандинг виден —
   активность падает). Butteraugli −2.0% → −4.1% почти бесплатно по S2;
   дисконт 1.0 уже съедает сам текстурный сигнал (S2 −5.4% → −2.0%).
   Это устранило главный per-image провал MAD-эвристики (kodim21,
   облачное небо: BA +4.3% → −1.1%).
2. **Абсолютный up-floor 4 — принято.** Относительное правило «выше
   средней активности тайла» в малоактивных bokeh-кадрах огрубляло
   объект в фокусе (picsum pic48). Порог маскирования абсолютен:
   ниже MAD 4 (после дисконта) up-ступени запрещены. Kodak: ноль
   per-image регрессий по S2 и BA.
3. **Хрома-AQ выключена — измерено.** Силы 0.5–1.0 ухудшали и S2,
   и butteraugli при любом luma-профиле: остаточные Co/Cg после CfL
   низкоэнергетичны, перекос квантования цвета заметнее экономии.
4. **Отклонено по измерениям:** глобальный min-квадрант вместо MAD
   (S2-выигрыш падает вдвое: −5.7% → −2.9%); мёртвая зона 0.5/1.0
   (монотонно режет выигрыш — сигнал дёшев, экономить нейтралью нечего);
   порог тёмных зон (не устранял оставшийся выброс, резал средние);
   асимметрия «только вверх»/«только вниз» (каждая половина даёт
   ~половину эффекта — нужны обе).

**Итог wire v9** (защита на втором корпусе picsum 12, ~1.7 Мп):

| Корпус | S2 | BA | PSNR(RGB) | Худший кадр BA |
| --- | ---: | ---: | ---: | ---: |
| Kodak 24 | −5.2% | −4.0% | +1.8% | −0.5% (регрессий нет) |
| picsum 12 | −4.4% | −3.1% | +1.5% | +3.7% (pic29, горы) |

Единственный документированный выброс — pic29 (тёмный горный лес,
максимально текстурный кадр): экономию битов butteraugli тарифицирует
на низких q; на продуктовых q=75/85 дельта ≤ 0.05. Скорость
encode не изменилась (в пределах шума, ≈1%: AQ-проход ~1 оп/пиксель);
лестница v9 в среднем на ~3% меньше байт при том же q. Заморозка:
`golden-v9-lossy-q75.fri`, `golden-v9-lossy-icc-q75.fri`, FNV-1a
декодера; правила §10.

Направления следующей версии (не v9): перекалибровка reference AQ (v10),
LAST-кодирование коэффициентов, прямоугольные партиции под перцептивный
gate, битность 10/12, progressive.

### 11.6. Линия v10: асимметричный reference AQ

**Ограничение линии.** v9 уже содержит нужный decoder tool — сигналируемый
per-root delta-Q. v10 не добавляет синтаксис и не усложняет decoder; задача
линии — получить дополнительный выигрыш обеих перцептивных метрик только
перекалибровкой reference encoder (§7.18). Freeze-condition: отрицательный
mean BD-rate одновременно по S2 и butteraugli на Kodak 24 и picsum 12,
худшая покадровая регрессия <1%, парная encode speed не ниже v9 вне шума.

**Интенсивностная гипотеза отклонена.** Защита теней по средней Y корня
(`dark push`, диапазоны 8…96) и отдельное огрубление бликов (`bright push`,
пороги 192…224) проверены на smoke-сетке. Тени тратили биты без устойчивого
butteraugli-выигрыша, а блики были нейтральны либо регрессировали; обе ветви
полностью удалены из production-кода. Средняя интенсивность корня не стала
частью frozen v10.

Рабочим рычагом оказалась **асимметрия уже измеренной активности v9**:
butteraugli ограничивает сильное огрубление, а S2 стабильно окупает более
точные слабомаскирующие корни. Полная калибровка (B vs frozen v9;
отрицательное = B лучше):

| Конфигурация (down / up, ступеней на октаву) | Корпус | S2 | BA | PSNR(RGB) | Размер |
| --- | --- | ---: | ---: | ---: | ---: |
| 3.0 / 3.0 | Kodak 24 | −1.16% | +0.10% | +1.17% | −0.33% |
| 3.5 / 2.0 | Kodak 24 | −0.73% | −0.24% | +0.80% | +2.13% |
| 3.5 / 2.0 | picsum 12 | −0.34% | +0.22% | +0.67% | +1.44% |
| 2.5 / 2.0 | Kodak 24 | −0.36% | −0.20% | +0.23% | +0.72% |
| 2.5 / 2.0 | picsum 12 | −0.16% | −0.01% | +0.22% | +0.48% |
| **2.75 / 2.25 (принято)** | **Kodak 24** | **−0.64%** | **−0.34%** | +0.60% | +0.54% |
| **2.75 / 2.25 (принято)** | **picsum 12** | **−0.44%** | **−0.23%** | +0.47% | +0.24% |

Финал улучшает S2 на 23/24 Kodak и 11/12 picsum; худшие S2-регрессии
ограничены +0.14% (kodim01) и +0.23% (pic48). Butteraugli mean выигрывает
на обоих корпусах; худшие покадровые BD-регрессии +0.79% (kodim13) и
+0.74% (pic48), то есть остаются внутри 1%-ограничителя.

**Product-quality guard.** На q75/q85 raw butteraugli улучшается и по mean,
и по median на обоих корпусах. Picsum не имеет регрессий больше 0.02.
На Kodak локально регрессируют 3/24 кадра при q75 и 2/24 при q85; худшие
дельты +0.055/+0.046, при средних −0.0126/−0.0106. То есть product-профили
не повторяют слабую положительную BA-медиану полной BD-лестницы.

**Скорость.** Вычислительный путь не изменился: тот же один MAD-проход и
то же число кодируемых корней. В восьми чередующихся полных q70-прогонах
Kodak медиана с учётом process spawn составила 10.63 Мп/с (v9) и
10.62 Мп/с (v10), отношение 0.999 — шум измерения. Decoder bit-exact
совпадает с v9 для одинакового тела.

**Freeze v10.** Публичный lossy `encode()`/`encode_with_icc()` пишет v10;
явный v9 сохраняет старые решения byte-for-byte. Заморозка:
`golden-v10-lossy-q75.fri`, `golden-v10-lossy-icc-q75.fri`, FNV-1a
декодера; правила §10.

Открытые направления после v10: LAST-кодирование коэффициентов,
перцептивно gated partition syntax, битность 10/12 и progressive. Повторно
возвращать intensity masking без нового межкорпусного evidence нельзя.

## 12. Интеграция в Flora (границы модулей)

- Кодек — **функциональный продукт** без бизнес-логики:
  `Products/FRC/crates/frc-i` (семейство FRC, см. §2.0
  `next-architecture.md`). Никаких зависимостей на модули; модули используют
  кодек через technical adapter `Products/FRC/crates/frc-i-integration`
  и свой Infrastructure-слой.
- Владелец пайплайна фото постов — `Flora.Content`; аватарки — `Flora.Users`;
  E2E-вложения шифруются **после** кодирования на клиенте (модель доверия
  [`CODECS.md`](./CODECS.md) не меняется). См. playbook
  [`CODECS-IMAGE.md`](./CODECS-IMAGE.md).
- **Публичный контур (посты / аватары / video posters):**
  - storage MIME `application/vnd.flora.frc-i-image-set` — versioned envelope
    с FRI primary (текущая версия кодера, §10) + готовым lossless WebP
    fallback (один UUID, без runtime transcode на GET);
  - GET выбирает вариант по `Accept` + `Media:FrcI:ServeEnabled`; ответ всегда
    получает `Vary: Accept`. Без явного `image/x-flora-frc-i` — WebP;
  - флаги: `Media:FrcI:WriteDual` (писать envelope), `ServeEnabled` (отдавать FRI),
    `BackfillEnabled` (resumable конверсия legacy rows).
- **E2E-контур (Messaging):** сервер хранит opaque ciphertext. Клиент кодирует
  WebP fallback и FRI, шифрует каждый вариант отдельно и кладёт optional
  `frcVariant` в `FscpImageBlock`. Старые readers игнорируют поле.
- Клиентские адаптеры: `@flora/frc-i` (WASM) + Expo `flora-frc-i` (native FFI).
- Расширение файлов `.fri`, MIME primary — `image/x-flora-frc-i`.

### Quality profiles (reference)

| Поверхность | FRI quality | WebP fallback |
| --- | --- | --- |
| Post images / video posters | 75 | lossless |
| User / community avatars | 85 | lossless |
| E2E message photos (client) | 75 | browser-native prepared JPEG/PNG/WebP |
